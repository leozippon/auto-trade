# 离线读数：先核对，再只用它能说明的部分

自己写的脚本、离线组合与筛选没有回测合同兜底：一处解析或索引错误会安静地给出一个看起来合理的数，之后的取舍全建在它上面。离线读数用来否决想法、给候选排序；量级与测试哪个候选只看宿主的正式验证。

## 先核对

- 写解析之前先跑一次原始命令、看几行真实输出，不凭印象假定格式。
- 据离线网格、排名或统计量提交批次之前，用一条独立实现的路径重算所选点及其相邻两点。子代理交回的数也一样：核过再写进 `hypothesis` 或 `reason`，还没交回的数不先写。
- 离线引擎先对上一个已验证节点再用：用候选自己的打分与下单函数，在该节点的前几个复核日重算名单与订单，逐笔对照它 `result_ref` 记录里的 `executions`。对不上先修引擎，不读它的收益。
- 事后离线重算某一天的分数，要用不晚于这一天的最近一次重训留下的快照。同一场回放里各次 `fit` 共用一个 `context.state_dir`，后一次重训覆盖同一份状态文件；读已被盖掉的共享文件，分数、相关和篮子收益会悄悄改变，而与模型无关的列不变，行数上看不出来。所以每次重训结束就把这次真正写进共享路径的权重按决策日另存；沿上一次模型续训的，要按同样的顺序重跑，重算的分数与验证值和当时记下的一致，这次重放才可信。
- 在研究期末视图上模拟 08:00 的决策时按下面截断。不要手拼时间字符串去和 `available_at` 比：格式差一个字符，字典序比较就会放进未来的行而不报错。

```python
import pandas as pd


def visible(frame, inference_at):
    """Rows an 08:00 decision at inference_at sees: daily by trade_date, macro by available_at."""
    at = pd.Timestamp(inference_at).tz_convert("Asia/Shanghai")
    if "available_at" in frame.columns:
        return frame[pd.to_datetime(frame["available_at"], utc=True) <= at]
    return frame[frame["trade_date"] < at.strftime("%Y%m%d")]
```

## 能说明什么

- 秩与符号能迁移到宿主；水平只有在离线组合跑的就是登记的构造（持仓数量、保留带、行业上限、按组合定的单股预算与整手、ST 过滤、换名上限）、又用宿主的量尺时才可比，而且仍只是一次有噪声的抽样。整组合重排的前 N 名只能作标明了的诊断。
- 宿主的量尺（系统提示的「读数」，定义在运行事实 `acceptance_rules`）与常见的离线读数不是一回事：
  - `/mnt/tools/screen.py` 的 `top_excess` 减的是当日被打分名字的等权均值，不是随机选股对照组合；组合带强规模倾斜时两者可以符号相反。
  - 宽池的 rank IC 是整池的排序，几十个持仓以内的集中组合只持有最前面一小截：先看 `top_excess` 的 t 与 hit，IC 显著不等于前几名有边际。
  - 换手、仓位不同的腿（例如每期重新打乱的 `c_shuf`，保留带留不住随机名次）在主动读数上可比，因为对照组合按各腿自己的成交骨架抽；在账户收益与 `book.excess_vs_benchmark` 上不可比。
- 离线门只能否决：命中就省下一次 `validate`（每步有限额）；没命中不是边际的证据。
- 离线视图不是回放视图（`/mnt/snapshot` 的 `universe` 只有视图日期那一版，早年的上市、改名、ST 与行业归属都按那一版读；`exchange`、`market` 与 `ts_code` 三列则连视图日期的也不是，而是数据商现在的标签，早年的视图里会出现北交所与 920xxx 代码，那是当时还在新三板精选层的名字，原中小板的名字也标作主板）：涉及早年、名称、ST、行业与板块的离线水平都带着这层误差。
