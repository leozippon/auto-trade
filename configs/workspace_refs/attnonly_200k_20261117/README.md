# 只用注意力的持续学习模型·20 万元账户（attnonly_200k，20261117）

本目录是参考包，会话里在 `refs/`：每次尝试开头从签入的版本重新复制，可写，改动不保留。包里没有起步策略。

## 方向

研究一个只由注意力层搭成、不带前馈块的选股模型，并让它在回放里持续学习。问的是：把「存什么」与「算什么」都放在注意力里的模型，能不能作为一个整体逐日更新，并胜过按季冷重训的同样的模型，也胜过把前馈块加回去的同样的模型。

方向之内的候选，是一个学到的函数只由注意力（以及注意力自身包含的线性映射）构成、并把学到的状态从一次决策带到下一次的模型；按日程从头重训的模型与加回前馈块的模型是对照，不是这个方向本身。所有者的原话和提案里每个词在本臂里指什么，在 `refs/references/proposal.md`；与本方向相邻、已经关闭的实现在 `refs/references/families.md`。

## 算力（所有者的要求）

所有者认为现有的策略太简单、没有充分用上 GPU，要求更多地使用 GPU 算力（原话在 `refs/references/proposal.md`）。在本臂里这条要求是：被测试的策略里，注意力模型既跨同一决策日的整个截面（当天全部可交易的股票）做注意力，也跨时间（每只股票一段日线序列）做注意力，在卡上用当时可见的全部历史训练，持续学习的版本此后逐日接着学；模型的大小按一条回放分到的卡装得下多少来定，先用冒烟量出显存峰值。下面的两个对照与候选规模相当、同样在卡上训练，所以它们也满足这条要求。

## 让结果读得出来的对照

本臂的结论只能从下面的对照读出；怎样实现由会话决定。

- 一个机制有没有帮助，只能对着同一架构、关掉这个机制、在同一批里验证的版本读。登记册的说法是「任何把持久化当卖点的实验，必须同批跑冷启动对照」。本方向里关掉机制的版本有两个：把前馈块加回去的同一架构，以及同一个只用注意力的模型按季冷重训。候选与这两个对照在同一批里、同样的种子基上验证。
- 关掉的只能是这个机制：对照与候选同样频率更新、用到同样新的已实现样本、优化量相当。按季冷重训在两次重训之间是冻结的，赢它的差距混着更新频率与新数据，不能归给带过来的状态。所以冷重训的对照在两次重训之间也要像候选一样逐日用新到期的样本更新，两者只差「每季是否从头开始」；加回前馈块的孪生与候选用同样的更新规则与节奏。
- 种子基的个数在第一次复制之前定下。同一配置换种子基时读数散布多大，见技能 `validation-readings`；比这更小的差，用预测层面的逐日配对比较（见建议）或更多种子基去分。
- 最后测试的是会话判断最好的候选。关掉机制的版本更好时测它是正当的（它同样满足「算力」一节），所以可能胜出的配置按候选验证，不标成对照；一个清楚的否定结果也是结果。

## 建议（可以不采纳）

- 要分辨机制开与关，预测层面的比较比组合读数的统计功效高得多：在研究年上逐日算打分与其后实现收益的截面秩相关、按日配对，它用上每天的整个截面，组合只持有几十只；筛选脚本（`source_refs.signal_screen_ref`）对任何逐日的截面打分给出这类秩相关。
- 加回前馈块的孪生，参数量要么与只用注意力的模型对齐，要么写明没有对齐：参数量不同时，差别分不清来自结构还是来自容量。
