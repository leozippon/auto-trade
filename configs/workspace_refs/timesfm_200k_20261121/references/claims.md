# TimesFM：论文的主张、2.5 检查点与本项目的差别

这是包作者对论文与代码的摘要，供会话快速定位；数字都标了出处，以 `refs/papers/timesfm/paper.pdf`（PMLR 版）为准。包作者无法核实的地方标为「未核实」。

## 问题

论文要做一个通用的零样本预测器：一个模型，读任意一条单变量序列过去的 L 个点，给出其后 H 个点（式 1），不对目标数据集做任何训练，准确度接近在该数据集上专门训练的监督模型。预训练时不能用任何数据集特有的协变量（第 3 节）。评价是点预测的 MAE。

## 方法与关键部件

模型叫 TimesFM，是一个只有解码器的 Transformer（图 1，第 4 节）：

- 分块（patching）：序列切成长 p=32 的不重叠块，每块连同填充掩码经一个残差 MLP 块映射成一个 token（式 2）。块长的消融见图 5（70M 模型上 p=16、32 最好，32 训练快一倍）。
- 只有解码器：因果自注意力，每个位置预测它之后的一段，整个上下文窗口内并行训练，所以同一个模型对各种上下文长度都训练过。
- 输出块比输入块长：输出块长 h=128（式 4）。预测超过 128 步时自回归地接着解；图 4 显示在 ETT 预测 512 步的任务上，输出块从 8 加到 128，平均 MAE 单调下降。
- 块掩码：训练时随机遮掉第一个块的前 r 个点（r 在 0 到 p−1 之间），使模型见过 1 到最大上下文的所有长度。
- 损失：点预测的 MSE（式 5）；论文说多分位输出头「容易加」，但 1.0 的论文版本只做点预测。
- 归一化：只用 RevIN 的标准化部分，每条序列按上下文第一个块的均值与标准差缩放（第 5 节末）。
- 预训练语料（表 1，第 5 节）：Google Trends（约 2.2 万个热门查询，小时粒度 2018-01 到 2019-12，其余粒度 2007-01 到 2021-12，约 5 亿点）、Wiki 页面浏览量（2012-01 到 2023-11，约 3,000 亿点）、300 万条合成序列（ARMA、正弦季节、趋势与阶跃的组合，每条 2,048 点，附录 A.7），以及 M4、Electricity、Traffic、Weather、Favorita、LibCity 等公开数据。采样时真实数据 80%、合成 20%；最大上下文 512（周粒度 256、月及以上 64）。正文说语料是 O(100B) 个点，与表 1 各行的量级（Wiki 一项即逾千亿）并不完全一致，以表 1 为准。
- 规模与训练（附录 A.5、表 6，第 6.2 节）：200M 模型 20 层、模型维 1280、16 头、dropout 0.2，余弦衰减学习率峰值 5e-4，全局批 4096 训练 150 万步，在 16 核 TPUv5e 上约 2 天。另有 17M、70M 两个规模（图 3：误差随 FLOPS 单调下降）。

本臂的关键部件是预训练得到的权重：上面的结构在本项目的数据上从头训练是可行的（20 层、1280 维、约 2.3 亿参数），论文的主张全部来自大规模预训练。

## 2.5 检查点与论文里的 1.0 有什么不同

会话用的是模型库里的 TimesFM 2.5（2025-09 发布，`transformers` 格式是 2026-02 的转换），论文写的是 1.0。没有找到 2.5 的论文或技术报告；下表右列来自仓库 README、仓库 2.5 代码（`src/timesfm/timesfm_2p5/`）、`transformers` 5.15 的实现与模型库目录里的 `config.json`。

| | 论文里的 1.0 | 2.5（模型库里的这份） |
|---|---|---|
| 参数 | 约 200M | 共 231,289,280 个（检查点张量逐个相加）：Transformer 栈约 1.97 亿，输入块 180 万，点输出头 490 万，连续分位头 2,790 万（README：「optional 30M quantile head」） |
| 层、维、头 | 20 层，1280 维，16 头 | 相同：20 层，1280 维，16 头 × 80 维 |
| 输入 / 输出块 | 32 / 128 | 32 / 128；连续分位头的输出长 1,024 |
| 最大上下文 | 512 | 16,384（README：「up to 16k」） |
| 位置编码与归一化层 | 正弦位置编码，LayerNorm | RoPE；每层注意力与前馈前后各一个 RMSNorm；query/key 各有 RMSNorm；query 有逐维缩放；栈内线性层无偏置；swish |
| 输入归一化 | 按第一个块的均值、标准差 | 逐块累积的均值、标准差（因果的 RevIN）；`transformers` 版在此之前还按整条输入的均值、标准差做一次全局标准化 |
| 输出 | 点预测（MSE） | 10 个通道：通道 0 是均值，1–9 是 10% 到 90% 分位；中位数（通道 5）作为点预测；2.5 的训练损失没有公开文档 |
| 频率指示 | 1.0 的公开检查点有可选的频率输入 | 去掉（README） |
| 其他推理开关 | 无 | 翻转不变（对 −x 再算一遍取平均，计算量加倍）、输入非负时把输出截在 0 以上、分位交叉修正 |
| 预训练语料 | 表 1 | 原始 PyTorch 检查点的模型卡列出：GiftEvalPretrain（Salesforce）、Wiki 页面浏览量（截至 2023-11）、Google Trends 热门查询（截至 2022 年底）、合成与增广数据；没有给出总的截止日期，也没有逐项清单 |

所以本臂实际是在用 2.5 复现一篇关于 1.0 的论文：论文的结构思想（分块、只有解码器、长输出块、零样本）都在，数字不会一样；仓库 README 说 2.0 比 1.0 在主要基准上最多好约 25%（`v1/README.md`），2.5 相对 1.0 的 ETT 数字没有公开。

## 官方代码里有什么

仓库 `google-research/timesfm`，提交 `918df02c9d36`（默认分支 master，2026-11-13），Apache-2.0。README 说 2.5 及以前的权重也是 Apache-2.0；3.0 的权重是非商用许可，与本臂无关，3.0 的代码已从包里剥掉。

| 位置 | 内容 |
|---|---|
| `src/timesfm/timesfm_2p5/` | 2.5 的 PyTorch（`timesfm_2p5_torch.py`）与 Flax 实现、共用的预处理与协变量入口（`timesfm_2p5_base.py`） |
| `src/timesfm/torch/`、`flax/` | 层的实现（残差块、带 RoPE 与逐维缩放的注意力、RMSNorm、累积归一化） |
| `src/timesfm/utils/xreg_lib.py` | 协变量（XReg）：对目标或 TimesFM 的残差拟合带岭罚的线性回归，再与 TimesFM 的预测相加；两种顺序 `"xreg + timesfm"` 与 `"timesfm + xreg"` |
| `timesfm-forecasting/examples/finetuning/` | 2026-04 加的 LoRA 微调示例：`transformers` 的 `TimesFm2_5ModelForPrediction` 加 `peft`，`target_modules="all-linear"`，r=4 时约 140 万可训练参数，随机抽 (上下文, 预测) 窗口，损失用模型自带的（见下节的注意事项） |
| `timesfm-forecasting/examples/covariates-forecasting/` | 协变量的演示脚本 |
| `v1/` | 1.0 与 2.0 的旧代码：JAX/PAX 与 PyTorch 两套、1.0 的长预测评测脚本（`v1/experiments/long_horizon_benchmarks/run_eval.py`，ETT 的切分边界在里面）、微调与 LoRA/DoRA 示例 |
| `tests/` | 2.5 的单元测试 |

最小用法（官方包，2.5）：`TimesFM_2p5_200M_torch.from_pretrained(...)`，`compile(ForecastConfig(max_context=..., max_horizon=..., use_continuous_quantile_head=True, ...))`，`forecast(horizon, inputs)` 返回点预测与分位；`forecast_with_covariates(...)` 走 XReg。官方 2.5 的 PyTorch 类只做推理（解码在 `torch.no_grad()` 里），微调走 `transformers`。

依赖与替换：

| 依赖 | 用在哪里 | 镜像里 | 怎样替换 |
|---|---|---|---|
| `huggingface_hub`、`safetensors`、`numpy`、`torch` | 官方 2.5 PyTorch 路径 | 有（`huggingface_hub` 随 `transformers` 安装） | 不需要；官方代码可以从 `PYTHONPATH=refs/papers/timesfm/repo/src` 导入阅读与对照，但它只认原始格式的权重（张量名不同、QKV 融合），模型库里没有，不能直接加载 |
| `jax` | XReg 协变量、Flax 路径 | 无 | XReg 只是岭回归加残差，用 numpy 或 `sklearn.linear_model.Ridge` 几十行重写 |
| `flax`、`optax`、`orbax`、`paxml`、`tensorflow`、`utilsforecast`、`wandb` | Flax 路径与 `v1/` 的 1.0 代码与评测 | 无 | 不需要：1.0 的权重不在模型库里；ETT 评测只用到它的切分与标准化，照着重写即可 |

## 怎样加载模型库里的检查点

模型库目录 `/mnt/pretrained/timesfm-2.5-200m-transformers` 只有 `config.json`、`model.safetensors`（925,187,448 字节，float32，272 个张量）、`README.md` 与一个空壳的 `configuration.json`。`config.json` 的 `architectures` 是 `TimesFm2_5ModelForPrediction`，`model_type` 是 `timesfm2_5`。包作者读了 `transformers` 5.15.0 的源码，并在镜像里加载过一次（没有 missing、unexpected 或 mismatched keys）：

- 5.15.0 有 `transformers.models.timesfm2_5`，导出 `TimesFm2_5Config`、`TimesFm2_5Model`、`TimesFm2_5ModelForPrediction`，`AutoModel` 也登记了 `timesfm2_5`。`config.json` 的每个键都是 `TimesFm2_5Config` 的字段。
- 检查点里前馈层的张量名是 `mlp.ff0`、`mlp.ff1`，模型里叫 `fc1`、`fc2`；5.15.0 的 `conversion_mapping.py` 对 `timesfm2_5` 登记了这两个改名，加载时自动处理。其余张量名与模型一致。
- 所以 `TimesFm2_5ModelForPrediction.from_pretrained(context.pretrained_dir + "/timesfm-2.5-200m-transformers")` 只用合同允许的 `torch` 与 `transformers` 即可，写法也在合同 README 的 Pretrained models 一节。会话里第一次加载时确认没有「missing / unexpected keys」的警告。

用法与要注意的地方（都来自 5.15.0 的 `modeling_timesfm2_5.py`）：

- 调用：`out = model(past_values=[每条序列一个一维张量], forecast_context_len=L)`；`out.full_predictions` 形状 (序列, 128, 10)，`out.mean_predictions` 是其中通道 5（中位数），`out.last_hidden_state` 形状 (序列, L/32, 1280)，最后一个位置就是产生预测的那个 token，可作嵌入。一次前向最多给 128 步，没有自回归续解；要更长的预测，把中位数接到上下文后面、`forecast_context_len` 相应加长再调用一次，官方 2.5 代码（`timesfm_2p5_torch.py` 的 `decode`）就是这样续解的。
- `forecast_context_len` 必须是 32 的倍数；不传时默认 16,384，每条序列都被补零到这个长度，又慢又改变归一化。
- 全局标准化的均值、标准差是在补零之后的整条输入上算的，补的零也算进去；所以尽量给满长度的窗口，历史不够的股票要么跳过，要么明确地知道它的归一化不同。
- 截零：只要一批里所有输入的最小值不小于 0，整批输出都被截在 0 以上（`truncate_negative`，按整批判断，不是逐条）。喂价格、成交量、波动率时无害，喂收益时最好显式传 `truncate_negative=False`。
- 翻转不变默认开（`force_flip_invariance=True`），每次前向实际算两遍；做嵌入或训练时可以关掉，复现时保持默认。
- 自带的损失：传 `future_values` 时返回「归一化空间里中位数的 MSE 加各分位的 pinball 损失」。按代码读，分位损失把 0.1–0.5 这五个分位水平配到了错一位的通道上（0.1 配到均值通道 0，0.2 配到 10% 分位通道 1，……，0.5 配到 40% 分位通道 4；0.6 起才对上），包作者认为这是实现缺陷（未在镜像里运行验证）。官方 LoRA 示例用的就是这个损失；要训练分位时自己写损失，按排序目标微调时反正要写自己的损失。
- 训练出的适配器或权重写在 `context.state_dir`，不写进模型库。

## 金融数据上的证据

两篇都是 arXiv 预印本，包作者没有找到它们发表在会议或期刊上；评价的是 TimesFM 1.0 与 2.0，不是 2.5。

Rahimikia、Ni、Wang，「Re(Visiting) Time Series Foundation Models in Finance」（arXiv 2511.18578v1）：

- 设定：日度超额收益，单变量；美国约 1 万只普通股（样本外 18,144,743 个日收益，表 3），另有 7 个非美国市场；每年用截至当年的数据扩展窗口重估，样本外 2001–2023；上下文 5、21、252、512 个交易日；指标是样本外 R²、方向准确率、按预测分十组的等权多空组合（逐日调仓，主结果不计交易成本，第 5.2.4 节另有成本情景）。
- 零样本：TimesFM 2.0（500M）上下文 512 时 R² 为 −2.80%，方向准确率略低于 50%，多空年化 −1.47%；CatBoost 同窗口 R² −0.03%、准确率 51.16%；最好的树（CatBoost，窗口 252）多空年化 46.50%、Sharpe 6.79（引言与第 5.1 节）。
- 微调（全部参数、原损失、同样逐年扩展，第 5.1.3 节，预测指标表 8、组合表 9）：R² 有些改善，准确率仍在 50% 左右；组合普遍变差，各微调模型的 Sharpe 在 −3.34 到 0.07 之间；作者的解释是微调把十组收益压扁了（脚注 25）。
- 在金融数据上从头预训练（第 5.1.4 节，表 11）：Chronos（small）窗口 512 年化 36.84%、Sharpe 5.42；按 TimesFM 2.0 缩小的 20M 模型年化 30.36%、Sharpe 3.66；都明显好于现成模型，仍不及树。作者的结论是通用领域的预训练对金融预测不够。

Fu、Hirano、Imajo，「Financial Fine-tuning a Large Time Series Model」（arXiv 2412.09880v1）：从 TimesFM 1.0（200M）出发，在作者称约 1 亿个点的价格序列（股票、指数、外汇、加密货币等，日与小时；训练与验证截至 2022 年底，测试 2023 年起）上继续预训练，损失改为对数价格的 MSE。市场中性组合的 Sharpe（表 IV，不计成本）：S&P 500 上微调后 1.68、原模型 0.42、AR(1) 1.58；TOPIX 500 上 1.06、−1.75、−0.82。作者说原模型在 7 个预测长度里有 4 个不如随机。

合起来的读法：现成的零样本预测在日度个股收益上接近噪声；按原损失微调收效很小，组合层面甚至变差；在大量金融数据上继续或从头预训练才有起色，但仍未稳定胜过梯度提升树。两篇的数字都是不计成本的毛收益，且是美国、日本等市场。

## 已知的批评

- 预训练语料与基准重叠：一个模型的预训练语料常是另一个模型的测试集（arXiv 2510.13654）；为此有了用全新数据、严格零样本评价 12 个基础模型的 TIME 基准（Qiao 等，ICML 2026，PMLR v306）。TimesFM 论文自己排除了 Electricity、Traffic、Weather，也承认 Darts 上 llmtime 的数据污染「无法排除」；2.5 的 GiftEvalPretrain 按其数据卡设计成与 GIFT-Eval 测试集不重叠，但与 ETT 等其他基准的关系，包作者没有核实。
- 「线性模型就够」：Zeng 等（AAAI 2023）显示一层线性模型（DLinear）在 ETT 等长预测基准上胜过当时多数 Transformer。论文的表 2 包含 DLinear；表 3 里 Darts 的 ARIMA 好于 TimesFM；表 5 里同语料预训练的 PatchTST 零样本版（0.35）与 TimesFM（0.36）相当。这些基准多是有强季节性的电力与交通序列，日度股票收益几乎没有这类结构。
- 论文的 ETT 结果只用测试集的最后一个窗口（为了让 llmtime 算得起），统计误差大。

## 与本项目问题的差别，以及它意味着什么

| | 论文 | 本项目 |
|---|---|---|
| 序列 | 电力、交通、搜索与浏览量等，季节与趋势强 | 约 2,500–4,700 只 A 股的日线，短（一只股票至多几千个交易日，新股更短）、噪声大、彼此强相关 |
| 目标 | 一条序列未来的水平，MAE | 同一天整个截面上其后若干天到几周收益的排序 |
| 输入 | 单变量 | 价量、财务、指数都可见；TimesFM 只读单条序列，看不到截面 |
| 评价 | 零样本 | 每个决策只能用当时可见的数据训练与选择 |

意味着：直接拿零样本的收益预测排序，与上面的金融证据一致，大概率接近噪声；有希望的是它更擅长的、有持续性的量（波动率、成交量、换手），以及把它当作一个时间序列编码器，在本项目自己的标签上学一个截面打分。三种用法：

1. 零样本输出作特征。逐日对每只股票的若干序列做零样本预测：收益（点预测与分位）、已实现波动的代理（|对数收益|、对数高低价差）、对数成交量或换手。可用的特征有预测的中位数、分位间距（10%–90% 宽度是一个波动预测）、预测与最近值之差。打分头只读这些特征（线性、小 MLP 或 LightGBM），按截面标准化后排序。
2. 微调。全参数、LoRA（`peft`，示例用 r=4、`all-linear`）或冻结主干只训新头；损失可以是截面的相关或排序损失：一个批次放同一天（或几天）的整个截面，用预测的其后 h 天累计收益（或中位数除以分位宽度）与实现收益算负 IC、ListNet 等。按原 MSE/分位损失微调是 Rahimikia 等报告变差的那种做法，可以作为一个对照点。
3. 嵌入接截面头。取每只股票最后一个 token 的 1280 维隐状态（或几个序列的拼接），降维后接一个截面头（线性、MLP、跨股票的注意力），在本项目标签上训练；主干冻结或轻量微调。

喂什么：收益序列均值近零、方差随时间变化，模型内部会逐序列标准化，所以喂原始对数收益即可，不必自己再标准化；价格水平（论文语料多是水平序列，Fu 等用对数价格）可以作为另一种输入比较。复权要按时点可见的口径。上下文 256 或 512（32 的倍数，研究年早期部分股票不够 512）；论文与 Rahimikia 等都发现更长的上下文更好。停牌日要么删去（按交易日序列），要么填前值，写下选哪种。

代价（A100 80 GB，与最多三条回放共享；按矩阵乘法的 FLOP 估算，未实测，先用冒烟量）：上下文 512 时一条序列一次前向约 7–8 GFLOP，翻转不变再翻倍。约 4,000 只 × 2,400 天逐日零样本预测是约 1e17 FLOP，bf16 下大约半小时到两小时，可以在研究年上一次算好、按日期缓存（每个预测只用到当天以前的数据）；回放里一个决策日的整个截面不到一秒。一遍微调（每股每天一个窗口，约 1,000 万个窗口，前向加反向约三倍前向）也是 1e17 量级，约一小时；隔几天抽一个窗口可以降到十几分钟。全参数微调 2.3 亿参数加 AdamW 的状态约 4 GB，显存主要花在激活上，批大小按冒烟时的峰值定。
