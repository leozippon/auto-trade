# TimesFM 时间序列基础模型的复现、移植与评估·20 万元账户（timesfm_200k，20261121）

本目录是参考包，会话里在 `refs/`：每次尝试开头从签入的版本与核对过摘要的论文载荷重新复制，可写，改动不保留。包里没有起步策略。

## 方向

所有者要求从近三年 ICLR、ICML、NeurIPS 的论文里挑出可能用于金融市场的方法，让会话复现、微调，再判断它能不能产生赚钱的策略（原话在 `refs/references/proposal.md`）。本臂的论文是 A decoder-only foundation model for time-series forecasting（TimesFM，ICML 2024）。它的主张：一个分块输入、只有解码器的 Transformer，在约千亿点的真实与合成序列上预训练后，不做任何训练就能接近各数据集上专门训练的监督模型；关键部件是预训练得到的权重，在 Monash 的 18 个数据集上按 naive 缩放的 MAE 几何平均为 0.6846（N-BEATS 0.7005），在 4 个 ETT 数据集上平均 MAE 0.36（论文表 4、表 5）。

模型库里已有 TimesFM 2.5（`/mnt/pretrained/timesfm-2.5-200m-transformers`），不需要另外的权重；它比论文里的 1.0 上下文更长、多了分位输出头、预训练语料也不同，所以本臂是在用 2.5 复现一篇关于 1.0 的论文。两者的差别、论文的数字、官方代码、检查点的加载与注意事项、金融数据上已有的证据，都在 `refs/references/claims.md`。其中金融数据上的证据要先读。

问的是：在本项目按时点可见的 A 股数据与决策节奏上，用这个检查点（在会话自己的数据上微调它，或者用它的分位预测与嵌入作打分的输入）比同样输入的强基线多出什么；多出的部分是不是来自预训练的权重。

## 三个阶段

1. 复现。在论文自己的设定上复现它的零样本 ETT 结果（表 5）：ETTh1、ETTh2 两个数据集，各 7 个变量，按 `repo/v1/experiments/long_horizon_benchmarks/run_eval.py` 的切分（前 8,640 行训练、其后 2,880 行验证、再 2,880 行测试，到第 14,400 行为止）用训练段的均值与标准差逐变量标准化，上下文 512，预测 96 与 192 步，每个变量单独作一条序列；`transformers` 版一次前向最多给 128 步，192 步要把前 128 步的中位数接到上下文后面再解一次（官方 2.5 代码的自回归做法）。论文的读法是测试段最后一个窗口上 7 个变量、全部步数的平均 MAE；论文 1.0 的四个数是 ETTh1 0.45、0.53，ETTh2 0.35、0.62，平均 0.49。目标：2.5 检查点在同样读法上的四项平均不高于 0.54。最后一个窗口只是一次抽样，所以同时报测试段上所有不重叠窗口（步长等于预测长度，`run_eval.py` 的做法）的平均 MAE，并与同窗口上重复最后一个值的 naive 预测比，TimesFM 在四项上都应明显低于 naive。窗口的确切取法论文没有写全，写下你用的是哪一个。加载与调用见 `claims.md` 的「怎样加载模型库里的检查点」；这一阶段只需要推理，几分钟内跑完，官方代码只作阅读与对照（它认的权重格式与模型库的不同）。达不到目标时写下差多少、可能的原因（版本差别、窗口取法、归一化、`forecast_context_len` 与补零），再进入下一阶段；复现失败不等于方法无效，也不是停止的理由。
2. 移植与微调。先在本项目研究年上做一个健全性检查：对每只股票的日已实现波动代理（例如 |对数收益| 或对数高低价差）做零样本的次日预测，与「重复最后一个值」和「过去 20 日均值」比误差，按年份报；它若连 20 日均值都赢不了，写下来，这决定了零样本特征值得押多少。然后把方法移进策略包：只用合同允许的库（`transformers` 的 `TimesFm2_5ModelForPrediction`、`peft`、`torch`）重写，作者代码与 XReg 的 `jax` 依赖不能被策略导入；在 `fit` 里只用当时可见的数据训练，按会话选定的再拟合节奏更新。`claims.md` 的末节给了三种用法：零样本的收益、波动、成交量预测与分位宽度作打分输入；以截面相关或排序损失微调（全参数、LoRA 或新的输出头）；取最后一个 token 的嵌入接截面打分头。喂什么序列、上下文多长、补零与截零的处理，超参与结构都可以为 A 股调整，每个改动在记录里写一行理由。微调出的权重写在 `context.state_dir`。微调的规模（全参数还是 LoRA、喂多少股票与多长的上下文）按冒烟量出的显存峰值与 `fit` 时限定，不按回放快慢；试过的规模要跑完并记下读数，中途停掉的不算试过。
3. 评估。按下一节的对照读结论。

## 所有者的要求

本臂被测试（`test`）的候选必须以论文方法为主要打分：打分来自 TimesFM，要么是微调后的预测本身，要么是一个只读 TimesFM 输出（预测、分位、嵌入）的打分头，不是在别的打分上加一个小幅倾斜。把 TimesFM 特征加进手工特征集的 LightGBM，是量增量的诊断读数，与候选同批验证，不测。树排序器、去掉预训练权重的版本与其他基线是对照，在 `validate` 里与候选同批验证，不测。方法读得比对照差时，照样测最好的方法版本，并在记录里写明差距：这正是本臂要的答案。本臂做完，是记录里的结论有下一节的读数撑着，不是验证期的步测完了：测完最后一步会话就结束，记录之后不能再补。两次 `test` 之间的研究用来推进阶段二与阶段三（新的方法版本、补上的对照与种子），不要在预算还剩大半时把同一个候选连着测完。

## 让结果读得出来的对照

- 预训练权重有没有用：对着同一结构、同一管线、只把预训练权重换成随机初始化、在本项目研究年上训练的版本读（`TimesFm2_5ModelForPrediction(config)` 不加载权重），特征的取法、打分头、训练量与更新节奏都相同。候选是 LoRA 或冻结主干时，随机初始化的版本只能训练全部参数（随机权重上的适配器没有意义），优化步数与候选对齐，并在记录里写明。论文与 `claims.md` 引用的金融研究都表明在金融数据上从头训练可能更好，所以这个对照赢了也是答案。
- 微调有没有用（候选经过微调时）：对着同一个检查点冻结、不微调的零样本版本读，打分头与更新节奏相同。
- 方法有没有用：对着同样输入、同样标签与同样持仓规则的 LightGBM 排序器读；「同样输入」指 TimesFM 读到的那几条价量序列，由它们算出的手工特征（各窗口的收益、波动、成交量变化）给树。
- 对照跟着被测试的配置走：要送去 `test` 的那份配置与它的对照在同一批 `validate` 里重放；那份配置之后改了（标签、特征、训练量或持仓规则），对照随它改过、再同批跑一次。在更早的配置或旧代码上跑过的对照，不算它的对照。
- 读一个对照的数之前，先确认它做的是名字说的事：它照常建仓与调仓（成交笔数与换手和候选同量级），与候选只差该差的那一处；读数与候选逐位相同，说明那处改动没有生效。没确认过的对照，不进结论。
- 种子基的个数在第一次复制之前定下，候选与对照用同样的种子基。一个差小于同一配置换种子的散布时不算发现（组合读数的散布见技能 `validation-readings`，预测层面的散布用几个训练种子自己量）；单个种子上的差不下结论。
- 同一种子基的回放要可复现：宿主会在后面的步里把同一个候选重放，两遍读数不同，就分不清一个差来自改动还是来自运算次序。20261119 轮有一个 GPU 模型的一次重放与前一次在 486 个交易日里差了 116 天，很可能是因为只开了 `warn_only=True`。固定训练与推理的全部随机源；用 PyTorch 时在第一次 CUDA 运算之前调用 `torch.use_deterministic_algorithms(True)`，报错的运算换成确定性的写法。送去 `validate` 之前，离线用同一种子基把同一段 `fit` 与打分跑两遍，确认输出逐位相同；做不到时把两遍之间的差写进记录，并和换种子的散布一起算进「不算发现」的门槛。
- 先在预测层面比：研究年上逐日的打分与其后收益的截面秩相关，按日配对（筛选脚本 `source_refs.signal_screen_ref`）；它的统计功效远高于组合读数，也不花回放时间。组合层面的同批 `validate` 再确认。离线算出的打分要由策略包里的同一份代码、按同样的再拟合节奏与可见性得到（先在几天上与回放里的打分核对）；检验不了本臂主张的离线比较，不拿来下结论。
- 已测季度上的读数只是一个季度一次的抽样：不要按已揭示的季度挑持仓只数或其他参数，也不要把一个季度写成实力。
- 放弃方法之前至少要有：阶段一的结果、两种以上配置（例如零样本特征与排序损失微调）在预测层面的配对比较，以及一次方法与两个对照同批的 `validate`。只比过一次就关掉，不算结论。

## 记录

在工作区 `notes/paper_record.md` 里维护一份记录，每个阶段结束时更新，会话结束后它随工作区存档，是后来的读者判断本臂结果的依据：
- 阶段一：跑了什么、得到的数与论文的数、差别与原因；
- 阶段二：健全性检查的数；移植时改了什么、为什么，合同之外的依赖怎样替换；喂了哪些序列、上下文多长、怎样处理停牌与新股；
- 阶段三：每次比较的候选、对照、种子基、预测层面与组合层面的读数（带节点名）；
- 结论，三选一并给出证据：方法复现了并且比对照多出多少、多出的部分是否来自预训练权重；复现了但不比对照好；没能复现（卡在哪里）。

## 本臂的数据与账户

- 价量数据：主板与创业板的日线，研究年里每个交易日约 2,500（第一个研究年）到 4,700（最后一个研究年）只股票，一场研究年回放约 1,701 个决策日；季度财务带公告日期。TimesFM 读每只股票自己的序列，看不到截面与财务，这些只能进打分头或对照。
- 时点：一个决策日的预测只用到当天视图里可见的最后一根日线；以某天为终点、期限 h 个交易日的标签，要等期限末那天的价格进入决策视图之后才能用于训练或更新。
- 预训练模型的知识截止：TimesFM 2.5 在 2025-09 发布，晚于全部研究年与已测季度，语料只公开到来源一级（`claims.md`）。这是接受的限制，不是避开模型的理由；读数可能因此偏乐观，记录里写明。
- 20 万元账户的算术，不是持仓配额：同时持有 10、20、40 只时每只约 2 万、1 万、5,000 元，最低佣金使单边成本约 7.6、10.1、15.1 bp，往返另加卖出印花税。包不设持仓只数、单票权重、调仓频率或价格上限。
