# Fold-ready 探索计划

一折跑多轮 `batch_validate`：第一轮并列比较机制，后续轮次围绕站住的机制比门控、持有期与仓位规则。每一步都要产出可执行候选或明确淘汰。有父本时，必须先完成一次与父本可执行逻辑不同的完整 Validation；父本对照由宿主在会话前跑好，不要自己重跑。

1. 读本轮 `data_summary.json`、`unit_reference.json` 与各域 schema；按 `pit-field-map.md` 逐一核对六个机制用到的数据集是否在本轮快照里、覆盖从哪一年开始、T-1 行在 08:30 是否可见。缺数据集的机制记「不可测」。
2. 固定不变量并写进工作区笔记：可交易性过滤（T-1 未停牌、ADV20 成交额 ≥ 3,000 万元、T-1 收盘价上限、剔除科创板/北交所或说明为何保留、剔除 ST 或说明）、篮子 8–15 只、等额现金、费用缓冲 3%、无信号日持币。这些是声明值。
3. 离线普查（不占回测预算，只用输入窗，不碰验证区间）：对每个机制统计逐季事件数、覆盖股票数、cohort 与其匹配对照在 1/3/5/10 日持有期上「次日开盘→持有期末开盘」的前瞻收益差及其逐季符号。匹配对照按同日、同规模分位、同换手分位、同行业（可得时）抽取。事件数不足（任一季度 < 30）的机制判「不可测」并记录；符号在多数季度一致且相对对照为正的机制才登记候选。截面型机制（领涨-跟涨、放量滞涨）可用 `python /mnt/tools/screen.py --help` 所述的筛查脚本先看 rank IC 与头部超额。
4. 第一轮 `batch_validate`：至少三个互不相同的机制并列，每个候选的 `hypothesis` 写清 cohort 定义、入场出场、持有期、匹配对照与否证条件；对照本身若要占用一个 Validation 名额，只给最有希望的机制配。
5. 第二轮起围绕站住的机制：门控变体（有/无市场宽度门）、持有期（3/5/10 日）、cohort 内排序（在 `fit(context)` 里用 T-1 字段拟合 logistic 或深度 ≤ 3 的小树，`REFIT_PERIOD="quarter"`，标签是已实现的持有期收益是否跑赢匹配对照）对照等权 cohort、仓位上限。一次只改一个组件。
6. 每个候选按 README 的「没有边际」清单读，四个季度子窗分别报相对对照的超额、事件数、成交数、拒单率、集中度。事件数与拒单率是本方向的一等公民：封死涨停买不进、跌停卖不出的路径要写清并汇报。
7. 用 `step_rollback` 把胜出节点恢复到 `output/` 再 `finish_fold`。六个机制全部证伪时以 `finish_fold(outcome="no_edge", reason=...)` 弃权（首折记为 `baseline_missing`），留下证伪结论；不得用剩余预算换成通用因子。

## 组合纪律

- 一次 Validation 只改一个机制或一个组件；不要一开始就把几个弱机制堆成不透明打分。
- 机制之间只在两个都单独站住之后才允许合并，且合并要与最佳单机制同批比较。
- 不用 MA 过滤、指数择时或任何未登记的过滤器救一个落败的机制。

## Validation 否证

- 任何 `available_at`、T-1、复权锚或单位错误：结果无效，不讨论收益。
- cohort 相对匹配对照的中性化超额 ≤ 0，或只在一个季度子窗为正：淘汰。
- 收益集中在不可成交的涨停开盘、少数事件或单一行业：淘汰。
- 加手续费、滑点、涨跌停与手数约束后优势消失，或 2 倍滑点下超额转负：淘汰。
- 门控变体不优于无门控的同一 cohort：门控没有信息，保留更简单的版本。
- 拒单率 > 30% 或空信号日占比使年内成交数不足 20 笔：判「不可执行」而不是「有边际」。
