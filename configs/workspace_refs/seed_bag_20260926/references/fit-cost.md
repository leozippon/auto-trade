# `fit` 成本：K 个种子要多花多少

自写笔记。本臂的腿只差分数平均了几个 booster，所以新增的成本全在 `fit`：一次季度重训里，面板、标签与 158 列特征只建一次，然后依次训练 K 个只差种子的 booster；决策侧每个复核日多做 K − 1 次预测，毫秒级。这一页把量级与纪律写死，具体读数只在 `refs/sources.md`。

## 三条上限

| 边界 | 值 | 性质 |
|---|---|---|
| 一次 `fit` 的墙钟 | 运行事实 `budgets.strategy_fit_timeout_seconds`（基准 **3,600 秒**） | `batch_validate` 的并发池按本批实际并发路数放大它，只补偿本批自己引入的争用 |
| 一次决策的墙钟 | `budgets.strategy_inference_timeout_seconds`（基准 **360 秒**） | 超时与抛错一样，整场回放失败 |
| 策略容器 | **8 核 / 16 GiB**，`/tmp` 与 `/dev/shm` 各 2 GiB（算在 16 GiB 里） | `--memory-swap` 与 `--memory` 同值：超了不是变慢，是直接 OOM（退出码 137） |
| 显卡 | 本臂 `gpu_count = 0` | 载体是 CPU 上的 LightGBM 与 numpy，没有任何一步需要 CUDA |

## 一次重训里钱花在哪

- **面板与特征（K 无关）**：读三年多的成分并集日线、算 158 列、堆训练矩阵——单种子一次拟合的大半时间在这里。
- **每个种子一个 booster（随 K 线性）**：每个成员新建自己的数据集（分箱随种子变）、冷启动最多 600 轮、续训 +150 轮，都带 50 轮早停。这条载体的标签很吵，早停来得很早：作包冒烟里一次冷启动加一次续训之后，每个成员的模型文件只有 25–61 棵树，所以每多一个种子只多几秒。

作包冒烟（第四研究年同一个 70 天窗口，依次跑在主机负载 8–50 之间，冷 / 续训，`refs/sources.md`）：`c_s7` 17.4 / 39.1 秒，`b5` 31.6 / 43.7 秒，`b10` 44.7 / 164.8 秒（续训那一次跑在主机负载约 45–50 时）；容器峰值三条腿都在 2.2 GiB 上下——K 个 booster 依次训练、依次释放，内存不随 K 涨。作包的种子普查在研究期末视图上 8 次 `b5` 拟合读 27.9–54.9 秒。**一条腿一次整期 16 次重训（4 次冷、12 次续训），`b10` 的全部拟合按冒烟读数外推约 15–35 分钟**，最慢的一次也离单次 3,600 秒的上限二十倍以上；第 1 批四路按三路并发跑，每路的上限还会被放大。

## 本包要求的三件事

1. **整期批次之前，`c_s7`、`b5` 与 `b10` 各跑一次 `smoke_backtest`**（窗口上限 5 天，同一个 `start` 复用），读 `resources.fit_seconds`、`peak_memory_bytes` 与买单元数据里的 `seeds`；`b10` 进不进第 1 批按 `refs/families.md` 的规则由这一次的秒数决定。`smoke_backtest` 不花回放年，也不计 trial。5 天的窗口只量到开头那一次冷启动；续训的秒数在完整期结果里读（作包的 70 天宿主冒烟里续训那一次比冷启动慢，主机负载与续训各占多少分不开）。
2. **同一个 `start` 复用**：`window_build_seconds` 是那个窗口一次性的开窗成本，付一次，永远不要乘以天数。
3. **秒数按区间读**：同一条腿、同一个窗口在两个时刻可以差将近一倍（作包冒烟在主机负载 15–50 之间跑）；耗时结论按多日回放的平均读，最坏情形按重载读。

## 三条实现纪律

- **线程数写死在 8**（`knobs.PARAMS["num_threads"]`），多路并发时让每一路自己抢满会互相拖垮；成员依次训练，不要并行训练成员。
- **训练面板按成分并集下推 `ts_code`**，不下推就是把全市场的行读进 16 GiB 的容器。
- **每个成员只接续它自己的文件**（`primary_s<种子>.txt`）；重训计数器只在 `fit` 里写，`generate_orders` 只把它抄进订单元数据。缺任何一个成员的文件就报错，不要退回少几个成员的平均。
