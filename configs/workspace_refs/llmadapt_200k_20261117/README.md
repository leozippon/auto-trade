# 持续学习的标题语言模型·20 万元账户（llmadapt_200k，20261117）

本目录是参考包，会话里在 `refs/`：每次尝试开头从签入的版本重新复制，可写，改动不保留。包里没有起步策略。

## 方向

研究一个读公告标题的预训练语言模型，并让它在回放里随新到的标题与到期的结局持续学习（适配器、可训练的顶层或全参数微调，由会话决定）。问的是：语言模型读出来的东西，在价量与财务特征之外有没有增量；让它持续学习，比把它冻结只当编码器多出什么。

方向之内的候选，是一个在回放里加载模型库的语言模型或嵌入模型、并随结局到期更新它从文本学到的部分（适配器、可训练的顶层或全部参数）的策略；去掉文本分支的孪生与冻结语言模型的孪生是对照，不是这个方向本身。所有者的原话和每个词在本臂里指什么，在 `refs/references/proposal.md`；与本方向相邻、已经关闭的实现在 `refs/references/families.md`。

宿主怎样读验证记录、读出什么，规则在系统提示与运行事实里，本包不复述。自建模拟器可以用于筛选想法，不能替代宿主撮合或成本模型。

## 算力（所有者的要求）

所有者认为现有的策略太简单、没有充分用上 GPU，要求更多地使用 GPU 算力，甚至明确指定用语言模型（原话在 `refs/references/proposal.md`）；本臂是明确指定语言模型的一臂。所有者的要求：本臂测试的策略必须在回放里加载模型库的语言模型或嵌入模型并在卡上运行；不读文本、或把文本换成关键词计数的候选只能作对照。

在本臂里这指：语言模型在回放里读当时可见的标题，在卡上做前向，持续学习的版本还在卡上做更新；用哪个模型、多大、怎样学，由会话决定。语言模型不在回放里运行、卡上只训练一个几万参数小网络的策略，不满足这条要求：20261115 轮两臂造的就是这种小网络，3.3 万到 5.8 万参数，卡上峰值不到 0.5 GiB。冻结语言模型的孪生也在卡上运行语言模型，满足这条要求；去掉文本分支的孪生不满足。

卡的型号与张数在运行事实里；模型库各模型的吞吐与显存、标题的数量、一场回放里每种用法的开销、几条并行回放怎样分卡，见 `memory/curated/pretrained-costs/SKILL.md`。

## 让结果读得出来的对照

本臂的结论只能从下面的对照读出，所以持续学习的候选与这两个孪生在同一批里、同样的种子基上验证；怎样实现由会话决定。

- 文本有没有增量：对着同一策略去掉文本分支、只留价量与财务特征的孪生读，在同一批里验证。登记册的说法是「文本的贡献要用去掉文本的同载体直接量，置换标签的对照代替不了它」。
- 持续学习有没有增量：对着同一个语言模型冻结、只作编码器的孪生读。关掉的只能是这个机制：冻结孪生上学到的部分（例如打分头）与持续学习的版本同样频率更新、用到同样新的已实现样本、优化量相当，两者只差语言模型自身学不学。按季冷重训在两次重训之间是冻结的，赢它的差距混着更新频率与新数据，不能归给持续学习。
- 两个配置之差小于同一配置换种子基的散布时，它不是证据；两个种子基同号也不够，没有差别时同号的机会就有一半。20261115 轮实测：同一份代码只换训练种子，研究年全段的残差信息比率相差 0.08 到 1.15。要分开比这更小的差，用预测层面的逐日配对比较（见建议）或更多种子基；种子基的个数在第一次复制之前定下。
- 最后测试的是会话判断最好的候选，它必须满足「算力」一节：冻结语言模型的孪生更好时测它是正当的，所以它按候选验证，不标成对照；去掉文本分支的孪生只作对照，不测。一个清楚的否定结果也是结果。

## 运行资源

卡上已有的显存占用来自同机的其他作业或本实验并行的其他回放；宿主既没有逐候选的显存硬上限，也不预留显存：在剩余显存内放开使用，不必因此回避 GPU。训练与大批量推断前后看一眼 `nvidia-smi` 与 `free -h`，只在自己的进程将耗尽内存或显存时缩小批量。本实验不接券商、不下真单；回测与可能的模拟交易（Paper）记录都不构成实盘交易授权。

## 时点与状态

`state_dir`、`fit` 与 `REFIT_PERIOD`、两个容器和 Paper 的语义都在合同 README（开头一节与 Caching across calls），模型库的加载与适配器的写法在它的 Pretrained models；回放里什么留得下、Paper 每天要从盘上读回什么、逐日更新怎样做得便宜，在 `memory/curated/replay-state/SKILL.md`。这里只补那里没有的。

- **Paper 不重放 `fit`。** 每个该 `fit` 的日子都在新容器里：后一次 `fit` 要接着用的（适配器或权重、优化器状态、统计量、待到期的预测）每天写进 `state_dir`；能从当时视图重建的（面板、财务表、特征）可以只放在内存，新容器第一次调用时重建，不必每天写盘。
- **随时间增长的状态。** 状态若随回放增长（每天追加样本、扩大训练集或缓存），几天的冒烟看不到期末的 `fit` 耗时与内存峰值；提交完整研究年的批次前，在研究年靠后的一天再冒烟一次。
- **确定性要策略自己保证。** 卡上训练的模型，固定种子也不一定得到同一个模型，同一份字节的两次回放就可能下出不同的单；实测的例子与核对办法在 `memory/curated/deterministic-fit/SKILL.md`。
- **标题文本。** `text_index` 只有 `anns_d`，每行只是标题加一条 PDF 链接，正文不在种子里。回放在每晚 23:15 的文本节点放行标题，T 日 08:00 的决策看到前一晚的节点；研究年里的标题只带公告日期（`available_at` 为当日 23:59:59），所以 D 日的标题最早用于 D+2 起第一个交易日的决策。同股票、同日、同标题的重复约占各研究年的 0.3%–1%，`text_index` 不合并它们，需要条数时按（股票、日期、标题）去重。
- **预训练模型的读数要这样看。** 模型发布之前的日子可能在它的训练数据里，经它们得到的研究年与验证期读数可能因此偏乐观（各模型的发布月份见合同 README 的 Pretrained models）。这是本实验接受的局限，不是回避它们的理由，也不要求为此配一个不用预训练权重的对照。把当时可见的标题、行情编码成表示或特征，或在它们上面训练，是正当用法；让模型按股票名或日期回忆其后的行情不是。

## 规模与时间

回放的墙钟不计入任何会话预算。20261115 轮两个逐日更新的臂实测：策略每个决策日约 2.5–5.5 s，一场研究年回放（1,701 个决策日）1.2–3.7 小时，卡的利用率不到 1 %；这几秒里训练只占零点几秒（按代码估算），其余是每天重建特征、重读财务表与保存 150–175 MB 的状态。所以模型做大，加的主要是卡上的时间，而那张卡原本闲着。每天哪些东西不必重算、不必写盘，见 `memory/curated/replay-state/SKILL.md`。十二次 `test` 都从验证期起点重放，合计 4,731 个决策日。

## 账户与成本

费用参数、可买板块与随机选股对照的构造见运行事实（`broker_replay`、`acceptance_rules.graded_series`）与合同 README 的 DailyBroker quick reference；下面只是 20 万元账户的算术，不是持仓配额。同时持有 10 只，每只约 2 万元，最低佣金折合约 2.5 bp，单边约 7.6 bp；20 只时每只约 1 万元，最低佣金折合约 5 bp，单边约 10.1 bp；40 只时每只约 5,000 元，最低佣金折合约 10 bp，单边约 15.1 bp；往返另加卖出印花税。换手越重、单笔越小，这笔算术越是决定净收益的第一项。包不设持仓只数、单票权重、调仓频率或价格上限。
