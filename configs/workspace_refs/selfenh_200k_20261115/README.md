# 自我增强的副本群与选择·20 万元账户（selfenh_200k，20261115）

本目录是参考包，会话里在 `refs/`（每次尝试开头重新复制）；包里没有起步策略。

## 方向

研究一群由同一个模型分出来的副本：每个副本在回放里持续学习、并放大自己固有的偏好，允许其中一些变坏，再按已经实现的结果留下变好的。问的是：分化加选择，能不能胜过一个按季冷重训的同样的模型，也胜过不做自我增强的同样一群副本。

方向之内的候选，是一个把学到的状态从一次决策带到下一次、并按上面的机制更新它的模型；按日程从头重训的模型是对照，不是这个方向本身。所有者的原话和提案里每个词在本臂里指什么，在 `refs/references/proposal.md`；与本方向相邻、已经关闭的实现在 `refs/references/families.md`。

宿主怎样读验证记录、读出什么，规则在系统提示与运行事实里，本包不复述。自建模拟器可以用于筛选想法，不能替代宿主撮合或成本模型。

## 让结果读得出来的对照

下面说的是读数能说明什么，不规定做法。

- 一个机制有没有帮助，只能对着同一架构、关掉这个机制、在同一批里验证的版本读。登记册的说法是「任何把持久化当卖点的实验，必须同批跑冷启动对照」，来由之一是 `xs_transformer_1m_20260922` 的受控腿里冷启动胜过了热启动。本方向还有第二个这样的对照：同样一群副本，只换种子、互不影响，不做自我增强。
- 两个配置之差小于同一配置在不同种子基之间的散布时，它不是证据，除非在至少两个种子基上同号。
- 最后测试的是会话判断最好的候选。关掉机制的版本更好时测它是正当的，所以可能胜出的配置按候选验证，不标成对照；一个清楚的否定结果也是结果。

## 运行资源

卡上已有的显存占用来自同机其他作业，宿主既没有逐候选的显存硬上限，也不预留显存：在剩余显存内放开使用，不必因此回避 GPU。训练与大批量推断前后看一眼 `nvidia-smi` 与 `free -h`，只在自己的进程将耗尽内存或显存时缩小批量。本实验不接券商、不下真单；回测与可能的模拟交易（Paper）记录都不构成实盘交易授权。

## 时点与状态

`state_dir`、`fit` 与 `REFIT_PERIOD`、两个容器和 Paper 的语义都在合同 README（开头一节与 Caching across calls），这里只补那里没有的。

- **Paper 不重放 `fit` 的容器。** 它每天都是新起的，要接着学的东西只能从 `state_dir` 读回。
- **随时间增长的状态。** 状态若随回放增长（每天追加样本、扩大训练集或记忆），几天的冒烟看不到期末的 `fit` 耗时与内存峰值；提交完整研究年的批次前，在研究年靠后的一天再冒烟一次。
- **同一份字节不一定下出同一本账。** 宿主不检查同一份字节两次回放的单是否相同（合同 README 只管随机数的种子），卡上拟合的树就曾让同一份字节给出不同的账；确定性要策略自己保证。
- **标题文本。** `text_index` 只有 `anns_d`，每行只是标题加一条 PDF 链接，正文不在种子里。回放在每晚 23:15 的文本节点放行标题，T 日 08:00 的决策看到前一晚的节点；研究年里的标题只带公告日期（`available_at` 为当日 23:59:59），所以 D 日的标题最早用于 D+2 起第一个交易日的决策。同股票、同日、同标题的重复约占各研究年的 0.3%–1%，`text_index` 不合并它们，需要条数时按（股票、日期、标题）去重。
- **预训练模型的读数要这样看。** 经它们得到的研究年与验证期读数可能因记忆而偏乐观（各模型的发布月份见合同 README 的 Pretrained models）。这是本实验已知并接受的局限，不是回避它们的理由：宿主在之后的数据上另行读数；要分清记忆与信号，配一个不用预训练权重的对照候选。把当时可见的标题、行情编码成表示或特征是正当用法；让模型按股票名或日期回忆其后的行情不是。

## 规模与时间

一次研究年回放的墙钟时间是全部 `fit` 的时间加上宿主与决策的开销；单日省下的时间按整段的决策日数放大。量过的参照：20261113b 一轮七个研究年共 1,701 个决策日，一个按季度在卡上重训的树排序器（`valid_021`，一张 L20 上三条回放并排）跑完用了 1.9 小时，其中 29 次 `fit` 共 0.45 小时（第一次 46.5 s），宿主开销约 350 s。逐日 `fit` 在当前回放框架上没有实测的整期腿；按这些分量估算（不是实测），每天更新 u 秒的模型一场研究年回放约 350 s + 1,701 ×（u + 0.5 s），u = 5 s 约 2.7 小时、30 s 约 14.5 小时。十二次 `test` 都从验证期起点重放，合计 4,731 个决策日。

## 账户与成本

费用参数、可买板块与随机选股对照的构造见运行事实（`broker_replay`、`acceptance_rules.graded_series`）与合同 README 的 DailyBroker quick reference；下面只是 20 万元账户的算术，不是持仓配额。同时持有 10 只，每只约 2 万元，最低佣金折合约 2.5 bp，单边约 7.6 bp；20 只时每只约 1 万元，最低佣金折合约 5 bp，单边约 10.1 bp；40 只时每只约 5,000 元，最低佣金折合约 10 bp，单边约 15.1 bp；往返另加卖出印花税。换手越重、单笔越小，这笔算术越是决定净收益的第一项。包不设持仓只数、单票权重、调仓频率或价格上限。

## 建议（可以不采纳）

- 要分辨机制开与关，预测层面的比较比组合读数的统计功效高得多：在研究年上逐日算打分与其后实现收益的截面秩相关、按日配对，它用上每天的整个截面，组合只持有几十只；筛选脚本（`source_refs.signal_screen_ref`）对任何逐日的截面打分给出这类秩相关。
- 小模型的 N 个副本可以堆成一个批在卡上同时更新；逐个串行时，每天的更新开销是一个副本的 N 倍。
- 较早的持续学习实现、它们的对照与结果在 `refs/references/families.md`。
