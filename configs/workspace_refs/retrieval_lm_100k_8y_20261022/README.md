# 检索相似历史案例·价量形态与公告标题·全 A / 10 万 / 八年（retrieval_lm_100k_8y，20261022）

本目录是只读参考包，会话里挂在 `refs/`；`output/` 开局就是 `refs/starter/` 的一份可写副本。

按顺序读：本文（方向、要回答的问题、测试台与模型的事实、时点与匿名化规则、经济账、预算与止损线）；`refs/references/open-rules.md`（账户、对照、预算与提名的共同规则，与本文同为合同）；`refs/families.md`（这份记录上已经关了什么，含上一轮的两项持续学习）；`refs/starter/`；`refs/examples/lib/llm_cases.py`（上下文路径的例子，起步包不调用）；运行记忆 `research-8y-data-surface`（数据合同，核对过，不要再派子代理重推）与 `residual-label-benchmark`（标签的基准腿与复权）。

## 方向

所有者的提案：对一只股票此刻的价量形态与文本信息，从历史里检索相似的案例，用这些案例后来的结局预测它的未来。两个挑战：一个持续更新的外部记忆——新的案例结局一揭晓就入库，检索永远基于截至当下的全部经验；以及创新的检索与上下文（元）学习——怎样定义「相似」、怎样从检索到的案例里学出预测，包括让一个大模型在上下文里读这些案例再作判断。

落到这个账户上：一个案例是一只股票在一个决策日的样子（那天决策能看到的价量形态与标题）加上它其后 20 个交易日的残差收益秩；记忆在每一场回放里从按时点的历史建起、逐日增长；每个决策日给每只可交易股票打分，书照起步包的规则买分数最高的名字。记忆怎样存、键怎样构造、怎样检索与加权、模型怎样部署与推断都由会话设计。

## 要回答的问题

每个问题各带一组配对比较：每一对同键、同记忆、同标签、同书（席位、复核节奏、保留带、行业上限），只差要检验的那一处；候选改了键或记忆，对照跟着改。候选与它的对照在同一个 span 上，对照登记 `control: true`；对照与一个已经在同一 span 上验证过的节点逐字节相同时，引用那个节点，不再重跑（`open-rules.md` §3 第 2 条）。一句话主张写在验证之前。

- **Q1（主问题）检索对参数模型。** 在一个按时点到期的价量形态与公告标题的案例记忆上，用检索到的案例的结局预测（候选），能否胜过同一组键、同一份记忆上按季冷重训的参数模型（C1，起步包的 `SCORER = "cold_quarter"`）？主张按包的度量：配对的主动 IR 差不低于 0.30，且 `open-rules.md` §5 的三处朴素选名（Y1–Y4、Y5–Y8、Y7–Y8）各高至少 1 pp；C1 在两个种子基上各跑一条，候选对两条都要成立。起步包的检索不抽随机数，它的成交与种子行无关，所以它对两个 C1 种子是同一条读数；会话自己的候选若含随机抽样，就按种子基一一配对。
- **Q2 相似性对随机邻居。** 同一份检索，案例的结局换成同一天另一个案例的结局（`NEIGHBOURS = "placebo"`：按（代码、日期）的固定哈希在当天的截面里错位一位）。这样的安慰剂保留候选逐日的分数动态与换手，只拿走「相似的案例结局相似」这一点。
- **Q3 持续更新对冻结记忆。** 同一份检索，记忆停在回放第一个决策之前已到期的那些案例（`MEMORY = "frozen"`）。
- **Q4 文本对纯形态。** 同一份检索，键里去掉文本块（`TEXT = False`，不加载编码器）。
- **Q5 上下文推断。** 把检索分数最高的一张短名单交给进程内的大模型，让它读每只股票与它最相似的几个案例（形态与结局），预测这只股票的结局分位，按它重排短名单（`refs/examples/lib/llm_cases.py`）。两个对照：同一张短名单不经模型——就是检索候选本身，逐字节相同时直接引用；以及打乱检索的安慰剂——模型看到的是按固定哈希随机抽的案例而不是最相似的案例（`rerank(..., placebo=True)`）。候选胜过前者而不胜过后者，说明模型用的是自己对形态的先验或对研究期的记忆，不是这些案例；只有对两者都成立，才算案例推理。

Q2–Q5 的主张都写成：候选在三处的朴素选名各比它的对照高至少 1 pp（`open-rules.md` §5 第 1 条），主动 IR 差照实报告。Q1 先做；Q2–Q4 在 Q1 的整期候选上做；Q5 用剩下的预算。

## 测试台：会话自己发现不了的事实

- **卡。** 本臂认领两张 L20（每张约 44.4 GiB 可用），会话里 `nvidia-smi` 可查。批里并行回放的候选按顺序轮流各挂一张卡，一条腿（一个候选的拟合容器与推断容器）只用它那一张；单独一场回放（冒烟、只有一个候选的批）挂两张卡，可以张量并行（策略里 `torch.cuda.device_count()` 可查）。会话容器两张都挂。一条腿只能指望自己那张卡上自己放进去的东西：别指望卡上还有别人的空间，也别给另一条腿留。
- **容器。** 策略容器（`fit` 与 `generate_orders` 跑在这里）8 CPU、16 GiB 内存（swap 同值，越界即被杀）、2 GiB 的 `/tmp`、2 GiB 的 `/dev/shm`、256 个进程，没有网络。本臂的 `fit` 每次至多 10,800 s、`generate_orders` 每次 360 s，两腿并行的批里各乘 2。会话容器 8 CPU、16 GiB、512 个进程、1 GiB 的 `/tmp`。
- **状态。** `context.state_dir` 只在 `fit` 里可写（`generate_orders` 里只读，内核挂载），每场回放开始时是空的、结束就丢弃，不跨回放保留任何东西。`fit` 与 `generate_orders` 在两个容器里，只通过 `state_dir` 通信。Paper 账户的拟合状态逐日保留；它每天早上新开推断 worker，把此前每一次决策按原顺序重发一遍来恢复模块状态（拟合 worker 不重放）：贵的东西在 `fit` 里算、落盘，`generate_orders` 只读。要留到回放之后的读数只有订单 metadata 一条路，一次调用的订单连同 metadata 至多 1,000,000 字节（按 UTF-8 计），按日写短摘要。
- **合同。** `main.py` 的 `generate_orders(context)`、可选的 `fit(context)` 与字面量 `REFIT_PERIOD`；允许的库以 `output/README.md` 为准，`re`、`random`、`os`、`time`、`hashlib`、pickle、joblib 都不在其中，正则走 pandas 的字符串方法；文件只读 `context` 的目录、只写 `state_dir`，策略不能建目录、列目录或删文件（起步包的记忆因此把所有文件平放在 `state_dir` 下，由一个索引文件点名）；一条种子线。改完先过 `smoke_backtest`。
- **文本。** `context.asof_dir + "/text_index"` 是 parquet 分片目录，列 `text_id, dataset, ts_codes, title, available_at, library_file`，`dataset == "anns_d"`，每个交易日约 3–4 千行。可见规则、副本与匿名化写在 `refs/starter/lib/text.py` 的模块说明里；`decision_days` 在 2018、2021、2024、2025 的四个决策日上对照真实的 as-of 视图逐行核对过（20261019 轮）。

## 模型

策略能用的模型只有本臂钉住的预训练模型库：会话里 `/mnt/pretrained`、策略里 `context.pretrained_dir`，下面十个 Hugging Face 布局的目录，只读。主机上的公共模型目录对所有用户可写、一部分属于别的用户，所以臂只从钉住的库里读权重；库在建臂时按清单摘要钉住，每个容器启动前核对。策略容器没有网络，够不到任何托管模型，也够不到会话里起的服务：模型只能在本腿的进程里、本腿的卡上推断。

| 目录 | 类型 | 大小 | 发布 |
|---|---|---|---|
| `Qwen3.8-27B-FP8` | 生成，270 亿参数，64 层（48 层 Gated DeltaNet 线性注意力 + 16 层门控注意力），块式 FP8 权重；多模态检查点，按纯文本用 | 28.5 GiB | 2026-08 |
| `Qwen3.8-27B` | 同一模型的 bf16 权重，给改结构的工作；单卡放不下，要两张卡张量并行（批宽 1） | 51.7 GiB | 2026-08 |
| `Qwen3.5-9B`、`Qwen3.5-4B`、`Qwen3.5-2B`、`Qwen3.5-0.8B` | 生成，Qwen3.5 混合注意力，bf16 | 18 / 8.8 / 4.3 / 1.7 GiB | 2026-02 |
| `Qwen3-1.7B`、`Qwen3-0.6B` | 生成，普通注意力，bf16 | 3.8 / 1.5 GiB | 2025-04 |
| `Qwen3-Embedding-8B`、`Qwen3-Embedding-0.6B` | 文本嵌入，最后一个 token 池化，4096 / 1024 维，前缀截断后仍是嵌入（Matryoshka） | 15 / 1.2 GiB | 2025-06 |

发布月份取自各目录 README 与发布页的日期；没有一份 README 写明训练数据的截止日期。

**进程内的 vLLM。** 写法、加载时间、显存与可重现的条件以合同 `output/README.md`「Pretrained models」一节为准；本包要用到的是：

- 每条腿一个引擎，建在拟合 worker 里（`fit` 与 `generate_orders` 在同一张卡上的两个容器里，只能有一个放引擎），整场回放复用（模块级缓存）；Paper 每天早上的新 worker 重新加载一次。推断 worker 重发旧决策时不碰模型。
- `Qwen3.8-27B-FP8` 一张卡放得下（权重约 28.5 GiB）。开局：不编译（`enforce_eager=True`）约 2–3 分钟，编译约 6.5 分钟，冷磁盘再加约 1 分钟读权重。提示吞吐量：不编译约 2,300–2,600 token/s，编译约 3,050–3,200 token/s（20 个约 1,000 token 的并发提示，或例子的 415 token 的对话）。这颗混合模型的线性注意力状态一张卡上约容 180 个并发序列，`max_num_seqs` 要低于它（默认的 256 起不来）。bf16 的 `Qwen3.8-27B` 一张卡放不下，只能在批宽 1 时两张卡张量并行。
- 显存：引擎按 `gpu_memory_utilization` 占整张卡的份额（默认 0.9）。同一张卡上还有拟合进程自己的张量——起步包的编码器约 1.2 GiB、记忆到研究期末约 1.8 GiB（扩容那一刻短暂多出一份）、每天检索约 1.3 GiB 的临时张量——所以例子取 0.80，并在建引擎之前把本进程缓存的块交还。
- 可重现：同一份字节的两场回放要下同样的单。只有不编译（`enforce_eager=True`）、温度 0、每个决策日的提示作为一个固定的批、按固定的次序送进去时，输出在不同容器与不同卡上才逐位相同；编译的引擎、前缀缓存（vLLM 默认开）与改变批的组成都会改变输出。例子因此不编译、关掉前缀缓存，一天的短名单一次送进引擎。关掉思考是 `chat_template_kwargs={"enable_thinking": False}`，模板随之渲染一个空的思考块，答案跟在后面。
- 同一张卡上 `Qwen3.5-9B` 在 262k 上下文时约 232 s 就绪；`Qwen3-Embedding-8B` 约 105 s 就绪，512 条短文本（约 8.6k token）1.6–3.7 s。

**会话里的 `vllm serve`。** 会话容器里可以在后台起 `vllm serve <路径>` 探索（提示怎么写、短名单多大、什么延迟），它随会话容器结束；它占的是本臂的卡，`smoke_backtest` 与 `batch_validate` 之前停掉它（`open-rules.md` §6）。会话在研究期末视图上用它读到的东西，是对那一张视图的研究，不是策略的输入：策略要用模型，就在自己的进程里加载。

**部署与推断由会话自己探索与优化**：引擎参数（显存份额、上下文长度、并发序列数、是否编译）、一天之内的批处理（一天的短名单一次送进引擎）、在 `fit` 里批量做按时点正确的预计算（第一次 `fit` 可以一次处理整段初始记忆，因为那些日子都已过去），以及批宽 1 时两张卡的张量并行。起步包只做最小的那一份。

## 时点规则：记忆怎样建、怎样增长

- **一个案例**是一只股票在决策日 D 的样子：D 那天的决策读到的那根日线（D 的前一个交易日）为止的价量形态，加上 D 能看到的标题；它的结局是那根日线的标签——从 D 的开盘到 20 个交易日后开盘的残差收益，在当天的截面上取秩中心化（`lib/features.py`，照运行记忆 `residual-label-benchmark`）。
- **入库的时刻。** 案例的键由 D 自己那天的 `fit` 写下；结局要等标签的前向窗口收盘——D 之后第 20 个交易日的开盘价进入视图，即 D 之后第 21 个交易日的决策——由那天的 `fit` 写下，案例从这时起才能被检索、被训练。任何检索都看不到一个决策当时不可能知道的结局，每个案例的键也恰好是它自己那天的决策能看到的数据。
- **节奏。** `REFIT_PERIOD = "day"`：每个交易日的 `fit` 写下当天的键、写下刚到期的那一天的结局（通常一天），再给当天的名字打分。回放的第一次 `fit` 先从按时点的历史建起初始记忆：回放第一个决策之前 `MEMORY_DAYS`（500）个决策日，到期的入库，最近 21 天的待到期。
- **不跨回放。** 记忆只活在一场回放的 `state_dir` 里：每场验证、冒烟与冻结产物的重放都从按时点的数据重新建起；Paper 账户的记忆逐日保留、继续增长，它每天重发的旧决策只读各自那天写下的分数。任何在回放之外建起、带进回放的记忆（会话在研究期末视图上算好、放进 `models/` 的东西）都是前视。
- **规模。** 研究期末一条整期腿的记忆约 910 万个案例；起步包的键 104 维（形态 40、文本 64），卡上 float16 约 1.8 GiB，主机上的结局、日期与代码约 0.2 GiB，`state_dir` 里的文件约 2.2 GB。检索在卡上按 65,536 个案例一块算距离，每天全部名字一次查询，240 万个案例时约 0.4 s、940 万个时约 1.1 s；在 CPU 上同一份代码用 float32，慢几十倍，只是合同要求的退路。

## 匿名化与泄漏

- **模型知道研究期。** 每个模型的预训练语料都覆盖研究期（2017-07..2025-06），没有一份 README 写明截止日期：按发布月份算，Qwen3-Embedding 的 2025-06 之前、Qwen3.5 的 2026-02 之前、Qwen3.8 的 2026-08 之前都算在模型的知识里。所以研究期上的每一个上下文读数都是受污染的——除非打乱检索的安慰剂（Q5）读不出比对照更好的结果，即模型拿到随机案例时并没有靠记忆选对名字。完全干净的只有模型发布之后的日期：对 27B 是 2026-08 之后，也就是 Paper 上的日子。研究期之后、发布之前的那一段对 27B 同样在它的知识里。
- **嵌入的残余。** 起步包的标题嵌入用的是 2025-06 发布的 `Qwen3-Embedding-0.6B`，研究期整段在它的语料里。嵌入不直接读结局，但它把同一件事件的标题放得彼此相近，而那件事件后来怎样，可能也在它的语料里；研究期上的文本读数带着这份残余。
- **提示里能放什么。** 交给生成模型的提示只能带由键算出的数字（形态的累计超额、近五日超额、换手倍数、有无标题）与案例结局的分位，按 A、B、C 重新编号——没有证券代码、公司名、日期、年份、价格水平，也没有标题原文。标题只经由选出邻居的嵌入进入上下文路径。会话若要把标题文字放进提示，只能放 `llm_cases.redact` 处理过的形式：先经 `lib/text.anonymise` 去掉发行人，再去掉所有数字与拉丁字母、去掉书名号与引号里的内容（产品、项目与合同名），截到 24 个字——剩下事件类型；并且要接受模型可能从措辞里认出事件。
- 起步包对标题本身的匿名化（去掉简称前缀、`universe` 名称、六位代码，把「……有限公司」缩成「公司」）沿用 20261019 轮，写在 `lib/text.py` 的模块说明里。

## 经济账

一条整期腿约 1,941 个决策日。起步包（检索、文本打开）在 L20 上：第一次 `fit` 建初始记忆 105–252 s（研究年越晚越慢；大头是把窗口里几十万条去重后的匿名标题过一遍编码器，约 1,770 条/s），之后每天的 `fit` 从 2017 年的约 3 s 涨到 2025 年的约 8 s（中位 5.5 s，随记忆与 as-of 视图一起长），决策每天约 0.7 s；整期一条腿 4.2 小时（一张卡；其中 `fit` 3.1 小时、决策 0.4 小时、宿主建视图约 1 小时）。C1 每季重训一次，每次约 2 s（940 万个案例的记忆里抽 200 万个，训 3 遍）。

27B 的账按一张卡算：开局不编译约 2–3 分钟、编译约 6.5 分钟（每个拟合 worker 一次）；提示吞吐不编译每秒约 2,300–2,600 token、编译约 3,050–3,200（几处实测见上文「模型」与文末「实测」；以本臂自己的量为准）。例子的一次对话约 415 个提示 token、输出不到 8 个 token：

| 用法 | 每个用到的日子的提示 token | 每天约 | 一条整期腿 |
|---|---|---|---|
| 每天给全部约 4,400 个名字各一次 | 约 180 万 | 10–13 分钟 | 320–430 小时，不可行 |
| 每天一张 60 名的短名单 | 约 2.5 万 | 约 10 s | 约 5.4 小时，加每个 worker 一次开局 |
| 只在书能交易的日子（复核日约 96 个，加上有空席的补位日；冒烟的整期腿上是 112 天）用 60 名短名单 | 同上 | 同上 | 约 20 分钟，加每个 worker 一次开局 |

所以生成模型只能是短名单、只在复核与补位日、或按市场一天一次的部件；每只股票每天的文本工作留给小编码器。Paper 上每天早上新开拟合 worker，引擎每天重新加载一次；推断 worker 重发旧决策时不该碰模型，例子因此只在 `fit` 里调用它。

**并发。** 批宽 2：两条腿各占一张卡，互不争用。起步包一条整期腿的实测峰值：显存 7.8 GiB，容器内存 14.1 GiB——这是 cgroup 的读数，含可回收的页缓存（`state_dir` 的 2.2 GB 文件与 as-of 视图的读取），离 16 GiB 的上限只剩约 2 GiB。上下文路径的 3 天端到端比起步包多用约 2.5 GiB 内存（引擎核心是同一容器里的另一个进程），显存到 38.7 GiB：整期跑它之前，先在一条整期腿上量内存，必要时缩小进程里的副本。27B FP8 的引擎占 0.80 的卡时，同一张卡上不能再放第二条腿。批宽 1 的腿两张卡都归它：bf16 的 27B 只能这样跑，两卡张量并行。20261019 轮三路并发共用一张卡时腿的显存峰值 17.8–42.2 GB、互相挤掉过（三条腿因此退还）；本轮一卡一腿，读每条腿 `resources.peak_gpu_memory_bytes`，超过 40 GiB 就别让它与任何东西共卡。

## 起步包

`starter/` 是一本能跑的最小基线，不是机制的菜单：

- **形态**（`lib/features.py`）：最近 20 根日线上，每天相对中证 1000 的超额对数收益，除以这只股票自己 60 根日线的超额收益标准差，逐日累加，第 k 天再除以 √k——随机游走下每个元素约为标准正态；加上每天的换手率对它自己 60 日平均换手的对数比，除以 0.5。共 40 维，单位不随市场水平、个股波动或规模变。收益只在相邻两根日线之间定义（停牌后复牌那一步不算），不做跨股票的标准化，所以一只股票的形态只取决于它自己的窗口与历史，不取决于面板读多远、里面有哪些股票。窗口里至少 15 根日线、波动与平均换手有限才算有效。
- **文本**（`lib/text.py`、`lib/encoder.py`）：一只股票在一个决策日的文本是最近 5 个决策日里首次可见、匿名化并去重后的全部标题；冻结的 `Qwen3-Embedding-0.6B` 取每条标题最后一个 token 的隐状态、归一化、截前 64 维再归一化（不加检索指令，查询与邻居都是标题），一只股票的文本向量是这些标题向量的均值。进程内按标题缓存，一天只编码当天新见的标题。
- **键**（`lib/learn.keys`）：形态 40 维，加上归一化的文本向量乘以 √(1.0 × 40)，使文本块与形态块对不相关的两对键贡献相当（`TEXT_WEIGHT`）；没有标题的股票文本块为零。
- **记忆与检索**（`lib/memory.py`）：键与结局按决策日存成 `state_dir` 里的平铺文件，由 `memory.npz` 点名；进程内缓存只是加速，冷 worker 从文件读出同一份 float16 记忆。每个名字取欧氏距离最近的 64 个已到期案例，权重 exp(−d² / (0.5 × 这 64 个 d² 的中位数))，分数是结局的加权平均。
- **C1**（`lib/model.py`）：同样的键上一层 64 宽的网络，每季第一次 `fit` 从初始化开始，在当时记忆里至多 200 万个案例上训 3 遍，季内不动。它看到的数据与检索完全相同，只差把案例压进固定的权重、每季一次，而不是每天重新读最近的案例。
- **分数**（`lib/learn.py`、`lib/score.py`）：一天的全部工作在 `fit` 里做完，写下 `scores_<日期>.npz`；`generate_orders` 只读它，不碰模型与卡。
- **旋钮**（`lib/knobs.py`）：`SCORER`（`retrieval` / `cold_quarter`）、`MEMORY`（`continuous` / `frozen`）、`NEIGHBOURS`（`similar` / `placebo`）、`TEXT`，以及形态、文本、记忆与核的各个常数；Q1–Q4 的对照都是这几个旋钮的一处改动。
- **书**（`lib/trade.py`，规范起步库的原件）：20 席等额，月度复核、保留带 2.0、每个申万一级至多 3 只；`SHUFFLE` 是打乱分数的对照 `c_shuf`（`lib/controls.held_shuffle`）。

`refs/examples/lib/llm_cases.py` 是上下文路径的例子，起步包不调用它，起步包的字节也不依赖它：复制到 `output/lib/llm_cases.py`，在 `lib/learn.score` 里检索之后、只在 `llm_cases.needed(context)` 为真的日子调用 `llm_cases.rerank(...)`。它在本腿的卡上建一个 vLLM 引擎（`Qwen3.8-27B-FP8`），给短名单（默认 60 名）里每个名字拼一段对话：它自己的形态描述，加上它最近的 8 个案例的形态与结局分位；贪心解码、关掉思考，把回答里第一个 0–100 的整数当作预测分位，按它把短名单排在其余名字之前，回答里没有数字的名字保留原来的检索分数。`placebo=True` 时模型看到的是按（代码、日期）的固定哈希随机抽的 8 个案例。

## 预算与止损线

`max_replay_years` 是 96，批宽 2 时一批两条腿并行。一种不浪费的花法：

- **探针**（研究期前半 Y1..Y4，每条腿 4 年）：在几种结构不同的检索设计之间挑，约 12–16 年。
- **Q1**：整期候选与 C1 的两个种子基，24 年。
- **Q2–Q4**：安慰剂、冻结记忆、纯形态，各一条整期腿，24 年。
- **Q5**：上下文候选与打乱检索的安慰剂，16 年；不经模型的那个对照是检索候选本身，引用即可。
- **提名的种子复现**：一条整期腿 8 年（冻结门对任何定义了 `fit` 的提名都要求，即使它的成交与种子无关）。

合计约 84–88 年，留 8–12 年给收尾前要补的对照。止损：第一对整期腿上候选对 C1 的两个种子基都差 0.3 IR 以上，Q1 对这个构造关闭；此后至多两次重新设计（键、核、记忆的形状），检索与上下文路径的设计是开放轴，不受这两次的限制。整期候选没有胜过 C1 时，诚实的结局就是 `no_edge`，把每一对的读数逐条写上——那也是一个完整的答案。

## 开放轴

键的构造（窗口长度、归一化、加不加横截面的位置、文本怎样进来、用 8B 嵌入还是 0.6B）；距离与核（学出来的度量、按日期或行业限邻居、带宽、邻居数）；记忆的形状（全部历史还是滚动窗口、去重、压缩、分层索引）；从案例里学预测的方式（核平均、局部回归、在检索到的案例上元学习的小网络）；上下文路径（模型大小、提示的内容与形状、短名单多大、模型给分位还是给排序、一天一次还是只在复核日）；席位与复核节奏。方向之外的想法不做，写进收尾 `reason` 的「没测的」。

## 上一轮学到的

20261019 轮的两项持续学习（`refs/families.md` 末两行）在一个读匿名化标题的小语言模型载体上，都没有在种子平均上胜过按季冷重训。留下一条读数：标题只在逐日更新的头上起作用（去掉文本，持续头掉 0.70–0.80 IR，冷重训的头只掉约 0.04）。检索是另一条路：不改任何参数，每天直接读最新到期的案例——逐日更新的好处若在，它应当在这里出现，而不带梯度更新打坏排序的代价。那一轮的另外两条教训写进了本包：包里写的显存峰值远低于实测（三路共卡时 17.8–42.2 GB），本轮一卡一腿并在上文给出实测；同一份字节的对照在同一 span 上重跑了两次，本轮引用而不重跑（`open-rules.md` §3 第 2 条）。

## 限制

模型的预训练覆盖研究期（「匿名化与泄漏」）；GPU 核与 vLLM 的批不保证逐位确定；记忆不跨回放；Paper 每天重新加载引擎；2025 年之前标题的副本与研究期之后标题更早的可见时点（`open-rules.md` §2）。

## 实测

起步包的数在沙箱镜像 `9209baaee6eb`（torch 2.10、transformers 5.14，还没有 vLLM）里、一张 L20 上，用宿主的评估器在本臂的种子与真实 as-of 视图上量（`fit` 与 `generate_orders` 各在自己的容器里，与正式回放相同）；上下文路径端到端在带 vLLM 的镜像 `1a72f531d575` 里量；27B 单独的吞吐另在主机上 vLLM 0.27.1 的环境里量。

- **建臂前的冒烟**（轮次启动器的 `smoke`：每个研究年起点各 3 天，再一次整期）：通过，共 17,433 s（4.8 小时）。八段 3 天的回放各 134–477 s；整期一条腿 15,067 s（4.2 小时）：1,941 次 `fit` 合计 11,075 s（第一次 107 s，之后每天的中位数从 2017 年的 2.9 s 涨到 2025 年的 8.3 s，随记忆与 as-of 视图一起长），决策合计 1,438 s（每天 0.74 s），宿主建视图约 1 小时；容器内存峰值 14.1 GiB（cgroup 的读数，含 `state_dir` 文件与 as-of 读取的页缓存；没有分出匿名内存），显存峰值 7.8 GiB；记忆从 Y1 起点的 107 万个案例（480 天）长到研究期末的 913 万个（2,401 天），`state_dir` 2.2 GB；书在 112 个交易日下单（复核与补位）。
- **第一次 `fit`**（建 500 个决策日的初始记忆，检索、文本打开）：Y1 起点 105 s、Y8 起点 252 s，随年份里的名字与标题增多；文本关掉 9 s。初始记忆在 Y8 起点是 480 天、242 万个案例（每天约 5,050 个有效名字）。
- **每天的 `fit`**：2.0–4.9 s（文本关掉 3.3 s，C1 3.1–3.4 s）；大头是读日线面板（161 个交易日）与标题、编码当天新见的标题（约 1,770 条/s）、检索。
- **检索**：240 万个案例、4,379 个名字一次 0.41 s，显存峰值 1.6 GiB；940 万个案例、5,000 个名字 1.14 s、3.1 GiB（含 1.8 GiB 的记忆）。C1 在 940 万个案例里抽 200 万个训 3 遍 2.1 s。
- **峰值**（3 天的回放，八个年份起点）：容器内存 4.0–7.1 GiB，显存 5.9–8.6 GiB（大头是第一次 `fit` 编码几十万条标题时分配器保留的块；之后每天结束时交还）。
- **重现**：同一份字节在 Y8 起点同 3 天跑两遍（两个进程、两套容器），20 张订单逐位相同。
- **27B 的例子**（`Qwen3.8-27B-FP8`，一张卡，`enforce_eager=True`、`max_model_len` 8192、`max_num_seqs` 32、`gpu_memory_utilization` 0.80、bf16 KV；那时前缀缓存还开着，例子现在关掉了）：权重已在页缓存时加载 130 s，卡上 35.3 GiB，KV 缓存 6.19 GiB、75,483 个 token；一次对话 415 个提示 token，60 段对话 9.8 s、600 段 95.8 s（约每秒 2,550–2,600 个提示 token，含每段至多 8 个输出 token）；`enable_thinking=False` 时回答都是一个整数，720 段全部解析成功。
- **上下文路径端到端**（镜像 `1a72f531d575`，起步包加上复制进 `lib/` 的例子，`lib/learn.score` 在检索之后、`needed` 为真时调用 `rerank`；Y8 起点 3 天，一张卡）：第一次 `fit` 385–395 s（比不带模型多约 140 s：加载 27B 引擎，加上第一天 60 段对话的重排），之后每天 3.5–4.2 s（书满、不复核的日子不调用模型）；60 个名字全部重排，书从模型给了 82–96 分位的名字里买；容器内存峰值 9.5 GiB，显存峰值 38.7 GiB（引擎 0.80 的份额加上起步包自己的张量）。同一份字节跑两遍（两个进程、两套容器），20 张订单逐位相同。
