# 记忆的写入、容量与检索·10 万 / 八年（memory_100k_8y，20261030）

本目录是只读参考包，会话里挂在 `refs/`。包里没有起步策略：`output/` 开局是合同模板自带的最小基线（`output/README.md` 的「Default strategy」）。`refs/memory-framework.md` 是所有者的记忆框架原文，本文件不重复它，也不改写它的数学。同一份方向包会同时交给两个相互独立的会话，各自在隔离的工作区里从头做起，两边不共享中间结果。

## 方向

在八年研究期上，研究记忆本身：模型把此刻可见的市场信息写进参数化记忆（外积累加、按预测误差在线修正、一次性回归到全部已存记忆）或非参数化记忆（案例库、检索、上下文），在推断时按查询把它取回来；可以改的是写入规则、容量与遗忘的分配、检索方式、记忆与参数化预测器的分工，或者会话自己想出的别的组织方式。

要在研究期内回答的是同一个可证伪问题：**在相同的可见市场信息、相同的标签成熟规则、相同的组合构造与执行、相同的交易成本下，改进记忆的写入、容量分配或检索，能不能比同输入的适当对照带来可复现的、扣费后为正的收益增量。** 适当的对照不预先指定，但至少要有同输入、同标签或无机制的对照，比如同一批输入上的简单参数学习、定期冷重训、把记忆关掉的同一载体；对照弱到什么都说明不了时，读数再高也不算增量。

要的是两件事同时成立：一种有明确新意的记忆机制（不是把已有因子换个名字），以及可复现、扣费后能盈利的策略。分别报告账户绝对净收益、对基准和零技能面板的表现、以及对去机制对照的增量；只比一个亏损对照少亏，不能称为盈利。

做不做、做成什么样由会话决定：用什么科学假设、什么网络、哪种记忆（或干脆不用上面列出的任何一种）、是否用预训练模型、是否上 GPU，都不受规定；不强求把卡用满。判定的主要依据是宿主回放与现有裁决流程，不是自建模拟器的读数：自建模拟器可以筛想法，不能代替宿主，也不要自建撮合或成本模型去顶替宿主的那一套。

## 这份框架的位置

`refs/memory-framework.md` 是工作假说，不是已验证的定理，也不构成任何交易优势。文中按「干扰与信号之比」达到 1 估计的容量阈值，不等于「能严格拟合全部记忆」的容量，也不能直接换算为「每个参数存多少比特」；随机键值模型的容量估计与文中引用的经验比特数，需要分别检验。

它给出的容量与复杂度量级受两个约束，比较时要摆明：显式存 $K$ 与 $V$ 的非参数化记忆，其宽度、存储与每次检索的代价都随记忆条数 $M$ 增长，因此它和「固定参数预算」的模型不是同一种资源；金融标签几乎一定是有相关性、非平稳、带横截面依赖的，随机独立键值的近似在那里未必成立。

所以这份框架的用法是提假设、定对照、解释机制，不是引用它的容量公式当作预期收益。实证反驳它、或量出它的近似在金融数据上失效，都是合法结果。

## 运行资源

GPU 设备、卡数、回放并行度、CPU 和内存由本臂的启动参数决定，以宿主提供的 `budgets` 为准，不由研究方向固定。只使用分配给本臂的设备，在容器中按可见设备编号使用 GPU，不硬编码宿主物理卡号。模型大小与批量应适合实际资源，先冒烟测量耗时和峰值，再扩大运行；宿主没有通用的按腿显存硬限额。

实验、训练、推断、评测与数据处理前后按仓库规则执行 `nvidia-smi`、`free -h` 并记录，资源不安全时缩减或停止自己的工作，不影响其他作业。

本臂不接券商、不下真单；回放与可能的 Paper 记录都不构成实盘交易授权。

## 时点、标签与状态

- **标签何时可用。** 一个样本的结局（其后若干日的收益之类），要等它的预测期限走完、期限末那天的价格进入决策的视图之后，才能用来训练、写入记忆或更新参数；记忆库里任何一条案例都不能带着决策当时不可能知道的结局。研究期是 2017-07..2025-06。
- **状态只活在一场回放里。** `context.state_dir` 在每场回放开头是空的、结束就丢弃，所以权重、记忆与测试时累积的状态只能在每场回放里从按时点的数据建起：每场验证、冒烟与冻结产物的重放都重新来一遍，什么都不跨回放保留。会话在研究期末视图上训练好、放进 `models/` 带进回放的权重是前视。
- **随时间增长的状态要专门预算。** 如果记忆随回放增长（每天入库、每场都追加），三天的冒烟看不到它：此前一条把每天的新案例留在记忆里的检索腿，整期里记忆从回放开头的一百余万条长到研究期末的九百余万条，每天 `fit` 的中位耗时从约 2.9 s 涨到约 8.3 s，一条腿的显存峰值从三天冒烟的 38.7 GiB 长到整期的 44.2–44.3 GiB（那张卡每卡约 44.4 GiB 可用）。整期行的 `resources` 给出峰值；提交整期批次前在研究期靠后的一天再冒烟一次。
- **标题文本。** `context.asof_dir + "/text_index"` 是 parquet 分片目录，列 `text_id, dataset, ts_codes, title, available_at, library_file`，只有 `dataset == "anns_d"`，每行只是标题加一条 PDF 链接；正文不在种子里，容器也没有网络。回放在每晚 23:15 的文本节点放行标题，T 日 08:30 的决策看到的是前一晚的节点，所以 D 日的标题最早用于 D+2 起第一个交易日的决策。研究期的行几乎都只有日期；2025-01 之前多数公告送了两份（普通标题与加公司简称前缀的一份），按条数计的标题特征因此在 2025-01 掉约 30 %，需要条数时按（股票、决策日、去前缀标题）去重。
- **预训练权重知道研究期。** 预训练模型发布之前的日子都可能在它的训练数据里：研究期上经预训练权重读出的任何东西，都可能来自模型对那段行情的记忆。嵌入也一样：它把同一事件的标题放得彼此相近，而那件事后来怎样可能就在它的语料里。用到预训练模型、编码器或重排器时，配一个去掉模型或打乱输入的对照。

## 规模与时间

研究期 1,941 个交易日，日线约 850 万个股票日：每天的名字从期初约 3,100 个长到期末约 5,400 个（其中主板与创业板约 4,550 个）。研究期末的视图回看 108 个月，日线共约 920 万行。

一条整期腿的墙钟时间是全部 `fit` 的时间再加 `fit` 之外的部分（宿主建每天的视图、决策与 Broker）；既往运行中后者约 75–80 分钟，但这不是当前共享本机上的耗时保证，须先测量本腿。能按截面或按日成批算的就向量化地算，用满分到的核；方法受益时放上卡，因为单日省下的时间会按约 1,941 个决策日放大。自己的策略用 `smoke_backtest` 量几天的单日耗时，`batch_validate` 的每一行带墙钟秒数与 `resources.fit_seconds_summary`。Paper 账户的 `state_dir` 逐日保留，那里逐日增长的记忆会接着增长，`generate_orders` 里贵的计算每天早上都要把此前的决策重做一遍。

## 种子

`pit_views_seed_research_8y_fundanns_20261024`，每个决策视图回看 108 个月：日线（同一行并入每日指标、复权因子与涨跌停价）、逐研究年的 `universe`（名称、交易所、上市日、申万一级）、四张宏观表（`index_daily`、`index_dailybasic`、`index_weight`、`sw_daily`）、财务域十个数据集（`income_vip`、`balancesheet_vip`、`cashflow_vip`、`fina_indicator_vip`、`forecast_vip`、`express_vip`、`dividend`、`fina_audit`、`fina_mainbz_vip`、`disclosure_date`）与公告标题 `anns_d`。没有事件域（资金流、两融、龙虎榜、股东与质押）与分钟线；竞价只从 2025-01-16 起、每天 09:29 才可见，08:30 的决策看不到当天的。

## 研究期上与本方向相邻的教训

以下是这块面上已经读过的形状，用来避免重开同一条路；它们是具体实现的读数，不是「记忆无用」的判决，新机制若能解释旧结果，按新读数判。

- 逐日持续梯度更新（头永不重新初始化、参数分组按不同周期更新、带片段存储）在一个约 9.2 万参数的逐股 GRU + FFN 上，不及同架构的季度冷重训与只拟合一次的冻结模型；输出层更快的分层学习率没有赢过均匀或反向的学习率。
- 同一族在语言模型载体上重开：冻结的小语言模型读匿名化公告标题加十路日线特征、只更新一个约 3.6 万参数的头，种子平均上仍不胜冷重训；分层时钟没有得到支持；证据门控的逐日提交／回滚没有胜过季度冷重训，也分不开随机时刻的更新。
- 检索相似历史案例的起步构造（价量形态加标题向量的键、按时点增长的案例库、最近邻的核加权结局）赢了同键上一个按季冷重训的小网络，但那个对照本身是负的，在第二个种子基上后半段的差只剩 0.17 pp；相似性没有胜过随机邻居，持续入库在后半段与最后两年输给冻结的记忆。
- 在一个案例库上让 27B 模型在上下文里重排短名单，增量与喂随机案例的安慰剂分不开；经预训练权重读到的东西带有模型对研究期的记忆。
- 训练窗与近期加权（2 年窗、5 年窗、1.5 年半衰期的近期加权）、季度重训之间的每月热启动更新，都让同一本序列书在研究的后半段变差，同种子的季度重训对照反而最好。
- 适应构造在宿主上的增量落在噪声里：按市场状态给书开关仓、按近期表现给袖子重配权重、按状态改复核节奏、季度重拟合因子权重，都没有胜过静态版与滞后一年的安慰剂。

这些关闭判定的是被测过的实现与承载它们的书，仍在开放之列的包括持续记忆本身、别的载体、别的更新与检索规则，以及把记忆用在容量分配或遗忘策略上而不是逐日微调上。旧的失败理由也可以被推翻：如果新机制让某个旧读数在新对照下不再成立，把对照和读数一起写清楚。

## 建议（可以不采纳）

以下是此前各臂留下的做法，不是要求：怎样做由会话决定，不采纳不影响任何评判。

- **先把假设与对照摆出来。** 在研究期里动手之前，写清这条机制的科学假设、它要打的对照、以及什么读数会证伪它；预登记之后按已有预算迭代。同信息、同训练机会的去机制对照优先；如果机制改变了容量、参数量、可见信息或训练机会，把改动写明，不要把由此带来的提升记在记忆机制上。
- **算力。** 策略容器的核、内存与卡见运行事实 `budgets.strategy_container_note`。记忆与训练窗随回放增长时，先在小样本上量峰值与单日耗时，再在研究期靠后的一天复量，然后提交整期批次。
- **对照。** 筛选脚本（`source_refs.signal_screen_ref`）可以在花任何回放之前把很多想法筛到少数几个；`run_null_control` 的随机同名组合能说明收益是不是来自这个机制；同一载体上把记忆关掉、把写入规则换成不作任何修正的累加、把检索换成随机邻居，都是这一族自然的对照。
- **机制解释与读数并重。** 读数没过门的臂要写清是哪一层机制没起作用；「统计没过门」不能代替机制解释，反过来，机制讲得通也不能代替扣费后的宿主读数。
