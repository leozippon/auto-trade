# 特征族、学习器、对照与消融

记号：`T` 为决策日（08:30），`T-1` 为最后一个可见交易日。`C/O/H/L/V/A` 为按 `anchor = adj_factor(T-1)` 冻结前复权的收盘/开盘/最高/最低价、成交量（股）与成交额（元），`turn` 为换手率（小数）。事件窗口一律按 **`available_at`** 落在 `(T - k 自然日, T]` 或按各表自己的日期列取「最新可见」，两者不混用；每一族的窗口在下表里逐列写死，实现与本地核对面板必须共用同一个构造函数（单一事实源）。缺值保持为 `NaN` 交给 LightGBM 自己选方向，**不填 0**；每族另带一个 `has_*` 指示列，让「有没有这条信息」显式进入模型，而不是让模型从 NaN 的花纹里反推。

全部特征在进入模型前统一处理：有限值过滤 → 逐列按当日可见截面的中位数/MAD（×1.4826）标准化并截到 ±3（`has_*` 与计数列不标准化）。不在全历史股票全集上算统计量，不用未来截面。

## 股票池（所有候选与对照共用，不得逐候选变动）

T-1 未停牌且有日线行；剔除 `.BJ`；剔除科创板（`688`/`689` 前缀，200 股起买不起）；`universe.name` 含 `ST`/`*ST`/`退` 的剔除；`universe.list_date` 距 T 至少 120 个自然日；ADV20（`daily.amount` 20 日均值，元）≥ 3,000 万元；T-1 收盘价 ≤ 30 元。四个抽样调仓日实测该池 2,951–3,643 只（见 `sources.md`）。

## 族 A — 卖方一致预期（`report_rc`，9 列，T-1）

去重是硬前提：先按 `available_at <= inference_at` 过滤，再对业务键 `(ts_code, report_date, org_name, author_name, quarter)` 取 `create_time` 最大的一条；保守盖章行的时刻完全相同（22:00:00），并列必须再按 `(report_date, org_name, author_name)` 打破，否则同一份数据两次运行给出不同篮子。`quarter` 是**财年**标签不是日历季度：`FY0` = `quarter[:4] == report_date[:4]` 的行，`FY1` = 年份加一的行；两者不得混算。窗口内每券商只取最新一条，不对所有行取均值（31.2% 的相邻预测 `eps` 完全没变，那是券商重发旧数字）。

| 列 | 定义 | 窗口 |
|---|---|---|
| `eps_rev_fy0` | FY0 的 `eps` 在 `(T-20d, T]` 的每券商最新均值，减 `(T-60d, T-20d]` 的同口径均值，除以 `max(|前窗均值|, 0.05)`；两窗各不足 2 家券商记 `NaN` | 20/60 自然日 |
| `eps_rev_fy1` | 同上，取 FY1 | 20/60 |
| `np_rev_fy0` | 同上口径作用于 `np`（万元），除以 `max(|前窗均值|, 1e3)` | 20/60 |
| `rev_breadth_60` | `(上调家数 − 下调家数)/配对家数`：`(T-60d, T]` 内每券商取该股 FY0 的最近两条可见预测比较；配对不足 3 组记 `NaN` | 60 |
| `disp_60` | `(T-60d, T]` 每券商最新 FY0 `eps` 的标准差 / `max(|均值|, 0.05)`；少于 3 家券商记 `NaN` | 60 |
| `cover_60` | `ln(1 + (T-60d, T] 内出具 FY0 预测的不同 org_name 家数)` | 60 |
| `cover_chg` | `cover_60(T) − cover_60(T-60d)`（覆盖度动量） | 60/120 |
| `rating_score_60` | `(T-60d, T]` 每券商最新 `rating` 的序数映射均值；只映射 15 个已核对词（买入/增持/中性/减持/卖出及其推荐、优于大市、跑赢行业等同义写法），映射不到的行**留空不猜**（约占当前财年行的 9.4%） | 60 |
| `has_analyst` | 上述窗口内是否至少一家券商 | — |

失效模式：`report_rc` 的秒级 PIT 时钟只从 2023 年起成立（2020–2021 全部是 22:00 日级保守盖章），任何盘前/盘后分层在早期输入窗上不可测；`非个股` 类研报仍带具体 `ts_code` 与 `eps`（占 15.9%），按 `report_type` 过滤会砍掉六分之一的数据，要过滤先量出前后覆盖差。

## 族 B — 两融余额（`margin_detail`，7 列，**T-2**）

`margin_detail` 行在次日 09:00 盖章，08:30 决策时最新只到 **T-2**。任何写成 `rzye(T-1)` 的公式都是前视。金额列（`rzye`/`rqye`/`rzmre`/`rzche`/`rzrqye`）是元，`rqyl`/`rqmcl`/`rqchl` 是股，两者不得相加。`daily.circ_mv` 在快照里已归一为元，可直接相除。

| 列 | 定义 | 窗口 |
|---|---|---|
| `rzye_chg_20` | `rzye(T-2)/rzye(T-22) - 1` | 20 个可见交易日 |
| `rzye_chg_5` | `rzye(T-2)/rzye(T-7) - 1` | 5 |
| `rzye_to_circ` | `rzye(T-2) / circ_mv(T-2)`（实测中位 3.85%） | T-2 |
| `rzmre_share_5` | 5 个可见日的 `rzmre / daily.amount`（同日、同为元）均值 | 5 |
| `rq_ratio` | `rqye(T-2) / max(rzye(T-2), 1)` | T-2 |
| `rzye_z_60` | `rzye` 在 60 个可见日上的 z-score | 60 |

## 族 C — 大宗交易（`block_trade`，7 列，T-1）

两级聚合是硬要求：先聚成 `(ts_code, trade_date)` 事件，再聚成窗口；跳过这一级会让一个拆成 340 笔的名称-日主导排序。单位：`vol` 万股、`amount` 万元、`price` 元/股；`daily.amount`/`circ_mv` 已归一为元。折溢价的分母只能从 `daily` 按同一 `(ts_code, trade_date)` 关联并用**未复权**当日价。

窗口按 `available_at` 的**自然日**计：30 自然日 ≈ 20 个交易日，90 自然日 ≈ 60 个交易日。列名沿用交易日的习惯写法，实现按自然日，两者不得混用。

| 列 | 定义 | 窗口 |
|---|---|---|
| `disc_pre_20` | 金额加权 `price/pre_close - 1`（主口径） | 30 自然日 |
| `disc_close_20` | 金额加权 `price/close - 1`（必须同批跑的第二口径） | 30 |
| `press_60` | `Σ(amount × 1e4) / Σ daily.amount`（分母为同期 60 个交易日的成交额之和） | 90 |
| `inst_buy_share_20` | `buyer == "机构专用"`（精确字符串）的金额 ÷ 非过桥金额；`buyer == seller` 的过桥笔（占 9.4%）分子分母同时剔除，窗口内全是过桥笔时记 `NaN` | 30 |
| `inst_sell_share_20` | `seller == "机构专用"` 的同口径占比 | 30 |
| `n_events_60` | `ln(1 + 窗口内不同 (ts_code, trade_date) 事件数)` | 90 |
| `has_block_20` | 窗口内是否有大宗事件 | — |

买卖两侧必须分列：卖方为机构席位的成交中位折价恰为 0.00%，与营业部卖方的 −6.99% 是完全不同的定价习惯，混进一个加权折价里是未处理的混淆。`price/close - 1` 在代数上包含当日涨跌幅（与 `pct_chg` 的 Spearman −0.349），所以 `disc_pre_20` 是主口径。制度水位非平稳（2024Q1 有 39.8% 的笔恰好成交在收盘价、折价中位 −0.99%；2025Q4 折价中位 −9.98%），跨折的水平比较没有意义，排名必须显式 tie-break 并汇报并列块大小。

## 族 D — 股东结构（`stk_holdernumber` / `stk_holdertrade` / `top10_floatholders`，8 列）

三张表的可见时点不同：`stk_holdertrade` 是 `ann_date` 当日 19:00（**T-1**），`stk_holdernumber` 与 `top10_floatholders` 是 `ann_date` 当日 23:59:59，而披露节点 `cn_nightly_disclosure_full` 在 23:05 启动，所以它们在 08:30 只到 **T-2**（自然日节点，周一早上的截止是周日 23:05）。

`stk_holdernumber` 的重复行是逐字节重复（18,864 个重复键组里 `holder_num` 全部一致），`drop_duplicates()` 即可；同一 `(ts_code, end_date)` 有多个 `ann_date` 版本时（14,088 组两版、429 组三版）取**可见的最大 `ann_date`**。只有 50.3% 的行落在 0331/0630/0930/1231，差分必须限定在报告期端点上。`top10_floatholders` 的 `end_date` 有 5.2% 落在非报告期（0205/0206/0208 等，349 个不同 MMDD），相邻两期直接差分会错位。

| 列 | 定义 | 窗口 |
|---|---|---|
| `hn_chg_1` | `holder_num(最新报告期)/holder_num(上一报告期) - 1`，两端必须都是报告期端点且相邻 | 相邻两期 |
| `hn_chg_2` | 跨两期的同口径变化 | 相邻三期 |
| `log_hn` | `ln(holder_num)` | 最新可见期 |
| `mv_per_holder` | `ln(circ_mv(T-1) / holder_num)` | 最新可见期 |
| `insider_net_60` | `Σ 带符号 change_vol`（`in_de=="IN"` 为 +、`"DE"` 为 −，股）÷ 流通股数 `circ_mv/close`，窗口按 `available_at` | 60 自然日 |
| `insider_net_180` | 同上 | 180 |
| `top10_float_chg` | 最新报告期十大流通股东 `hold_float_ratio` 之和，减上一报告期的同口径之和；任一端点不是报告期或缺期记 `NaN` | 相邻两期 |
| `has_holder` | 是否至少有一个可见的报告期对 | — |

`stk_holdertrade` 去重按 `(ts_code, ann_date, holder_name, in_de, change_vol)`；`change_ratio`/`after_ratio` 是**百分数**，`change_vol`/`after_share`/`total_share` 是股，且 `total_share` 是该股东交易后的持仓而不是公司股本。`avg_price` 有 34.4% 缺失，不要用它推金额。全窗 76,601 条减持对 18,352 条增持，方向严重不平衡，减持腿才是主要样本。

## 族 E — 筹码分布与解禁供给（`cyq_perf` + `share_float_complete`，8 列）

`cyq_perf` 行在 `trade_date` 当日 19:00 盖章（**T-1**；交易日节点，周一早上最新是上周五），零重复键、零空值，覆盖 95–100% 的可选池。`winner_rate` 是 0–100 的百分数（实测最大 100.55，用前截到 `[0, 100]`），`cost_*`/`weight_avg` 是元/股的成本价位而不是比例。

`share_float_complete` 的 `available_at` 是 `ann_date` 当日 23:59:59，走 events 默认晚间节点（23:35），因此**公告在 08:30 只到 T-2**；但 `float_date` 是**未来**解禁日（实测 `float_date - ann_date` 中位 189 天），所以「未来 N 日的解禁压力」是 PIT 合法的前瞻量。聚合规则（本包实测得出，见 `sources.md`）：先 `drop_duplicates()`，再对每个 `(ts_code, float_date)` 只保留**可见的最大 `ann_date`** 那一版（同一次解禁被多次重述，混版求和会得到 360% 这种不可能的比例），然后在该版内对逐持有人行的 `float_ratio`（占总股本的百分数）求和。该规则下逐事件解禁比例中位 7.84%、p95 66.6%，残余尾部仍有少数超过 100%，一律截到 100 并汇报被截比例。

| 列 | 定义 | 窗口 |
|---|---|---|
| `winner_rate` | `cyq_perf.winner_rate`（百分数，截 `[0,100]`） | T-1 |
| `winner_chg_20` | `winner_rate(T-1) − winner_rate(T-21)` | 20 |
| `cost_spread` | `(cost_85pct − cost_15pct)/weight_avg` | T-1 |
| `px_to_cost50` | `C(T-1)/cost_50pct(T-1) − 1` | T-1 |
| `px_to_wavg` | `C(T-1)/weight_avg(T-1) − 1` | T-1 |
| `unlock_next90` | `float_date ∈ (T, T+90 自然日]` 的事件解禁比例之和（上述规则，截 100） | 前瞻 90 |
| `unlock_past30` | `float_date ∈ [T-30 自然日, T)` 的同口径之和 | 回看 30 |
| `has_unlock_90` | 未来 90 日是否有解禁 | — |

失效模式：未来 90 日有解禁的名字只占可选池 3–6%，`unlock_*` 两列在绝大多数行上是 0（不是 `NaN`——「没有解禁」是确定的零，与「没有数据」不同，必须分开编码）；`winner_rate` 单独已被判为动量/波动换皮，如果消融显示整条边际都来自族 E 且族 E 的重要性又集中在 `winner_rate`，按 `exploration-plan.md` 的规则判为换皮而不是新族。

**列数上限声明为 60，线程数声明为 5。** 线程数不是 8：`batch_validate` 会并发跑 3 个候选容器，3×5=15 ≤ 16 核配额，而 3×8=24 的超订正是 `explore_github` 一次 `fit exceeded 3600s` 的根因（该折自诊断记在 `logs/notes/review_20260909/T4_traces_explore_github.md`：单机 264–450 秒的 `fit` 在三路并发下涨到 3600 秒以上）。

**预算的真正大头是面板构建，不是提升树。** 本包在沙箱镜像里对 `starter/` 实测（合成切片，746 只 × 118 个特征日、约 9.5 万行、5 线程）：读取 1.2 秒、一次性预计算 2.5 秒、面板构建 91 秒、4 点网格加最终重训 1.9 秒。也就是说树模型几乎免费，逐特征日的事件窗聚合才是成本。因此 `starter/lib/features.py` 里三条优化是**声明要求**而不是可选项：事件表按 `visible_at` 排序一次后用 `searchsorted` 取切片（不做全表布尔扫描）；`margin_detail` 与 `cyq_perf` 这两张稠密日频表按「日期位次」索引一次（不在每个特征日重排全表）；滚动窗口（ADV20、60 日成交额之和）在 `prepare` 里算一次。真实折的事件表比合成切片大数倍，因此**必须在会话沙箱里对真实输入窗实测一次**：单机 `fit` 目标 ≤ 6 分钟，超过 10 分钟就把列数压到 45 以下、把特征日网格从 5 放宽到 10，或缩短事件窗，再重测。三路并发下的目标是 ≤ 20 分钟，硬上限 3600 秒。列数或网格每变一档都要重测。

## 学习器规格

- LightGBM `objective="regression"`（对 rank 标签）。网格事先写死 4 点：`num_leaves ∈ {31, 63}` × `learning_rate ∈ {0.05, 0.1}`；固定 `feature_fraction=0.8`、`bagging_fraction=0.8`、`bagging_freq=1`、`min_data_in_leaf=200`、`lambda_l2=10`、`num_boost_round ≤ 600` 由带禁运的时间序列验证早停（50 轮）决定，`num_threads=5`。选中的网格点写进 `context.state_dir` 与订单 metadata；**不在 Validation 结果上调参**，每个网格点都是一次试验。
- **标签**：对特征日 `T`（= 决策日前一交易日），`label(T) = C_{T+1+h}/C_{T+1} - 1`（qfq 收盘价），`h = 20`；`excess(T) = label(T) − 当日截面均值`；`target(T) = 截面 rank(excess)` 映射到 `[-0.5, 0.5]`。只保留标签完全实现的行。收盘口径是被执行方式决定的：买单挂 15:00（这样同日 09:30 的卖出所得已入账），标签的入场价就必须是 Broker 真正付的那个价。卖出挂 09:30，比标签的出场早半个交易日——这是**声明的近似**，主候选与两个对照完全一致地承担它，因此不影响比较；不要用开盘口径的标签配收盘口径的成交。
- **训练面板的日期网格**：每 5 个交易日取一个特征日（`FEATURE_STRIDE=5`）。24 个月输入窗给出约 100 个特征日、约 3,000 只/日，扣掉标签禁运后约 25 万行——足够 53 列的树模型，又把面板构建压在两分钟内。网格步长是声明值，不是待调参数；改它必须重测 `fit` 墙钟并在 `hypothesis` 里写明。
- **持有期与再平衡必须一致**：`h = 20` 且每 20 个交易日再平衡。实现上「每 20 个交易日」写成**每个自然月的第一个决策日**（A 股一个自然月平均 20.3 个交易日）：这条规则只读「最后一个可见 Bar 是否还在本月」，不需要任何策略状态，因此冷启动的 worker 与热 worker 必然给出相同订单；用「可见交易日计数取模」会随读取窗口的起点漂移。T4 把 `explore_github` 的「10 日标签 + 5 日再平衡」记为无理由的错配（仓位在半个标签窗内就换掉了）。本包不允许 `h ≠ 再平衡周期`，除非这个错配本身被登记为当轮假设，并且同批带一个 `h = 再平衡周期` 的对照。选 20 而不是 5 的理由写在这里：本包所有事件特征都是 T-1/T-2 盖章、按周到季更新的量，D1 实测分析师修正腿在 H=20 的 IR 是 0.41、H=5 只有 0.20；20 日持有在本账户上年成本约 1.8–2.2%，5 日持有约四倍。
- **重训与切分**：`REFIT_PERIOD="quarter"`。每次 `fit` 在决策时刻 `D` 只看 `available_at <= D` 的行；训练样本必须满足 `T + 1 + h <= D - 1`（标签已完全实现）。可见决策日序列的最后 60 个交易日作验证片，训练片与验证片之间再空出 `h = 20` 个交易日的禁运，即训练片右端 ≤ `t − (h + gap)`、`gap = h`。这与 `explore_github` 冻结包的 `split_fit_dates`（60 日验证 + 与 `h` 等长的禁运）是同一形状，只是 `h` 从 10 换成 20。
- **中性化**：默认在**分数层**做——booster 打分后，对同截面的 `log(circ_mv)`、`mom_20`、`turn_20`、`vol_60` 与申万一级行业哑变量（`universe.l1_code`）做 OLS 取残差，再排序。特征层中性化登记为变体，两者不同批混用。行业口径在 2021-12-13 切换，输入窗跨越时行业只按决策日冻结的 `universe` 取。
- **持久化**：`s = booster.model_to_string()`；`np.save(context.state_dir + "/model.npy", np.array([s]))`，另存标准化参数、网格选点与特征名顺序。决策期 `lgb.Booster(model_str=str(np.load(...)[0]))`，每次 `generate_orders` 重新加载（重训会替换文件而不重启 worker）。加载处自检长度与特征名顺序，不符即 raise 并翻退化标志。
- **显式退化**：样本不足、booster 训练失败或有效覆盖过低时退回族 P 的等权符号打分，并在订单 metadata 里标明退化——不要静默切换。整个 Validation 大部分决策都在退化路径上时判该候选失败。

## 两个必须同批比过的对照

| 对照 | 定义 | 它回答什么 | 未通过的后果 |
|---|---|---|---|
| **C-PV（归因对照）** | 同一学习器、同一超参网格、同一标签、同一切分、同一篮子与过滤，**特征只有族 P 的 14 列** | 边际是不是来自事件面 | 主候选未在中性化超额与空对照分位上同时超过它 → 事件特征没有加进任何东西 → **整个机制关闭**，`finish_fold(outcome="no_edge")` |
| **C-EW（无学习器对照）** | 同一特征集（族 A–E），**不训练**：每列按事先声明的方向做截面 rank，等权求和，再做同样的分数层中性化与同一套篮子规则 | 学习器本身有没有价值 | 主候选中性化超额 ≤ C-EW → 保留更简单的 C-EW 版本，学习器记为无边际 |

C-EW 的方向声明（合成前乘号，使高分做多，写进第一轮 `hypothesis`）：`eps_rev_fy0` +、`eps_rev_fy1` +、`np_rev_fy0` +、`rev_breadth_60` +、`disp_60` −、`cover_chg` +、`rating_score_60` +、`rzye_chg_20` −、`rzye_chg_5` −、`rq_ratio` −、`disc_pre_20` +、`inst_buy_share_20` +、`press_60` −、`hn_chg_1` −、`insider_net_60` +、`top10_float_chg` +、`winner_rate` −、`unlock_next90` −。未列出的列（`has_*`、水平量、`disc_close_20`）不进 C-EW 的合成。

`run_null_control` 的空对照按 `circ_mv` 十分位重抽同名数量的随机组合，对本臂是恰当的零假设（篮子只有 15 只、名字选择就是全部主张）；但族 C 与族 E-解禁的可选子集远窄于市值十分位池，所以**任何以族 C 或解禁为唯一功臣的结论，还必须带一个池内匹配对照**（同日、同申万一级、同规模分位、同期有事件但打分落在后 50% 的等权篮子）。

## 预登记的特征族消融

第一轮胜出后，第二轮同批跑五个「去掉一族」的候选，其余全部与胜者相同：

| 候选 | 特征集 | 判读 |
|---|---|---|
| `abl_noA` | P + B,C,D,E | 中性化超额相对胜者的落差 = 族 A 的贡献 |
| `abl_noB` | P + A,C,D,E | 同上 |
| `abl_noC` | P + A,B,D,E | 同上 |
| `abl_noD` | P + A,B,C,E | 同上 |
| `abl_noE` | P + A,B,C,D | 同上 |

判读规则：落差为正且四个子窗同号 ≥3 的族记为「有贡献」；所有五个落差都 ≤ 0 时，边际其实来自族 P 或来自噪声，回到 C-PV 的判定。**单族独占**（某一族的落差 ≥ 胜者相对 C-PV 全部超额的 80%）且该族在可选池的覆盖率 < 20%（族 C 9–16%、解禁 3–6%）时，判为覆盖/规模伪装，不得提名；覆盖率 ≥ 20% 时可以提名，但必须在 `hypothesis` 与结果笔记里写明它已退化为单族信号，下一轮按单族的证伪条件重测。

## 明确不做

- 在 `generate_orders` 里训练或更新任何模型。
- 用 `top_list`/`top_inst` 的净买入或席位金额进入打分：龙虎榜家族已被 `explore_github` 在 fold_2024Q2 打开又未能收束，且逐日只覆盖 60 上下的名字；本包只允许把它们当作排除性诊断（例如汇报候选篮子里有多少只在最近 5 日上过榜），不进特征集。
- 用 `moneyflow` 任何字段：它已经是 `explore_github` 冻结包的特征块（`mfflow`），进入本包会让「新特征集」的主张失效。
- 把 Alpha158/Alpha360/WQ101/GTJA191 的任何算子加进族 P：族 P 是**声明冻结的 14 列**归因基线，扩充它等于换掉对照的含义。
- 用 `report_rc` 的 `tp` 当目标价（它是利润总额，万元）、用 `imp_dg` 当评级变动标志（全空）、用 `stk_surv`（家族已关闭）。
- 用未复权价算跨日收益，或假设 `adj_factor` 逐日非降。
