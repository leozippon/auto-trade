# 排序、持仓与 n_drop

转述 Qlib `TopkDropoutStrategy` 的公开机制：大约持有 `topk` 只；每次再平衡丢掉当前持仓里分数最差的 `n_drop` 只，并从最新高分未持有股票里补进同样数量。默认示例常见 `topk=50`、`n_drop=5`。这是换手控制，不是收益保证。

本环境没有 Qlib executor。用当前 `context.account.positions` 当持仓，自己发买卖草图。

## 分数

`score = X @ w`，`X` 是已 z-score 的特征矩阵。

权重来源：

1. **默认：在 `fit` 里拟合。** `w = (X'X + λI)^{-1} X'y`（ridge 闭式解），或对二分类标签（收益前若干分位为 1）做少量梯度步的 logistic，二选一。只用推断时已经实现的可见历史样本，拟合窗长度与标签口径事先声明；`λ` 也预先声明，不按 Validation 搜索一大网格。整条拟合链路放在 `fit(context)` 里跑完（它有独立的 `budgets.strategy_fit_timeout_seconds` 预算），系数写到 `context.state_dir`；`generate_orders` 只读系数、算当日特征、出单，受单日 `budgets.strategy_inference_timeout_seconds` 约束。
2. **对照：符号加权。** 价值/质量/低波给正或负的先验符号，绝对值相等。
3. **对照：秩加权。** 先把特征变成截面 rank，再等权。
4. **退化路径。** 样本不足、`X'X` 奇异或有效覆盖过低时退回 2 或 3，并在 metadata 里标明本次发生了退化。退化必须可见，不能静默。

第一轮的线性基线自己实现闭式解，不要直接用 sklearn `Ridge` 或 LightGBM 叶子分数顶替它——那样比较的是库的默认超参，不是本包的口径。库模型排序器是后续轮次的结构性变体（见 `README.md`、`rewrite-plan.md`），必须与自实现线性版同窗、同标签口径比较。

## top-k + n_drop

设当前持仓代码集合为 `P`（数量可能因拒单而小于 k），最新合法排名为 `R`。

1. 在 `P` 里按最新分数从低到高，最多标出 `n_drop` 只为卖出；已不在合法宇宙或不在 `R` 的持仓也卖。
2. 目标集合先保留 `P` 中未被卖掉的部分。
3. 从 `R` 里按分数从高到低，把尚未在目标中的代码补进，直到目标达到 `k` 或候选人用尽。
4. 卖出目标外全部持仓；买入目标内尚未持有的代码。
5. 买入按等权现金或等风险，向下取整到 100 股，本地递减现金并留费用缓冲。

对照实验：关掉 n_drop，每天直接换成最新 top-k。若全换更好，说明换手控制没有帮助，不要为了「更像 Qlib」而保留。

## 订单纪律

- 卖先于买。不要假设同一次卖出已经变成现金。
- `execute_at` 不早于 `inference_at`；日频默认下一 09:30。
- 排序键必须稳定：分数降序，并列用 `ts_code`。
- 空信号返回 `[]`。
- metadata 可写 `k`、`n_drop`、有效覆盖、权重来源；不要写未发生的收益。

## 常见失败

- 把 NaN 填 0 后，缺数据的股票反而进 top-k。
- 用今日尚未可见的日线当特征。
- 用未来收益更新当天 `w`。
- 在 `generate_orders` 里重新拟合权重——拟合属于 `fit(context)`，`generate_orders` 只 `np.load` `context.state_dir` 里的系数。
- 整折都停在等权/符号加权对照上，从未真正跑出一次拟合候选。
- 大部分决策其实走在退化路径上，却按拟合版本汇报结论。
- 复制 Qlib 的 CSI300 回测表当作本折已经达到的成绩。
