# Fold-ready 10 步改写

目标不是复现 Qlib 的 CSI300 报表，而是检验：T-1 日频截面分数 + 受控换手，在本环境含成本 Validation 里是否还站得住。

1. 读本轮 `data_summary.json`、daily schema、单位表。确认 OHLC、成交量/额、换手列的真实名字。缺列就改映射，不要臆造 `KMID`/`ROC5` 等 Qlib 列名一定存在。
2. 固定股票池、`k`、`n_drop`、再平衡频率和现金缓冲。先用小 `k`（例如 20–50）和 `n_drop`（例如 2–5）做可交易基线，不要一开始就拟合。
3. 按 `context.asof_version` 读有界 T-1 日线尾窗。08:30 丢弃 `trade_date` 为今日或更晚的行。复权用 T-1 冻结锚，见因子包同一纪律。
4. 只实现 `features.md` 里的四组本地特征，先各做截面 z-score，NaN/Inf 丢行。先用等权或符号加权合成一个分数，完整 Validation。
5. 加上 `ranking.md` 的 top-k 与 n_drop：尽量保留与当前持仓的交集，只替换最差的 `n_drop` 只。对照「每日重排 top-k、无换手控制」。
6. 若等权已可交易，再试 **可见历史上的 ridge/OLS**。标签只能用推断时已经实现的收益（例如用更早的特征预测随后已经走完的开盘到开盘或收盘到收盘）。禁止用未来收益拟合当天权重。
7. 样本不足、矩阵奇异或有效覆盖过低时，显式退回等权/符号加权，并在订单 metadata 里标明。不要静默调用 sklearn。
8. 可选：一棵深度 ≤2 的 if/then 规则（例如低波动且近端收益为负）。规则必须事先写死阈值来源（截面分位，不是 Validation 拟合）。规则树不能变成手工 LightGBM。
9. 否证：含成本后不优于等权流动性篮子；换手控制没有降低成本优势却损失收益；权重在相邻子窗符号乱翻；分数只在极少股票或单一行业上工作。
10. 把最小完整胜出方案写入 `output/main.py`。不要提交训练脚本、qlib yaml、`joblib` 模型或 `models/*.pkl`。

## 明确禁止

- `import sklearn` / `lightgbm` / `qlib` / `joblib` / `torch`。
- 在推断时 `read_pickle` / 加载 `.pt`。运行 ABI 不挂载 `models/`。
- 把 Qlib 示例里的 CSI300 年化、IC、超额抄进注释当目标。
- 在策略内实现另一套日频回测或组合优化器。
- 用未来 `Ref($close,-2)` 标签在当日拟合。Qlib 那样做是他们平台的 T+1 处理；本环境 Broker 已经处理 T+1，策略不得偷看未实现收益。

## 对照

| 候选 | 必须比过的更简单版本 |
| --- | --- |
| 等权特征 | 纯流动性/市值过滤篮子 |
| ridge/OLS | 同一特征的等权或符号加权 |
| n_drop | 每日全换 top-k |
| 规则树 | 没有规则的线性分数 |

更简单的不差，就留更简单的。
