# Fold-ready 探索顺序

一次只测一个机制。不要把五个社区故事合成一个不透明打板评分。
有父本时，必须先完成一次与父本不同的完整 Validation。

1. 读本轮 `data_summary.json`、events/daily/auction/universe schema、单位表。确认 `inference_time` 确实是 09:29，并确认 `auction` 域存在。缺竞价域就退回「只用 T-1 日终标签、不使用缺口过滤」的变体，并在结论里写明，不要编造竞价。
2. 确认今日 `daily` 行仍不可见；今日 `stk_limit` / `suspend_d`（约 08:45）与今日 `auction`（09:29）在本轮清单上是否可见。`adj_factor` 盖章 09:30，09:29 仍只用 T-1 复权。
3. 先交一个极简可交易基线：T-1 `limit=='U'` 且流动性过关的小篮子，09:30 等权，记录空信号日、拒单、换手、开盘相对开盘的含成本表现。
4. 单独验证 **首板次日**。08:30 不能用未观察到的低开过滤；09:29 才允许用竞价/昨收缺口作可选过滤。对照：同日同流动性首板篮子、无缺口过滤。
5. 单独验证 **一进二**。它比「所有首板」更苛刻，必须相对首板次日做增量检验，而不是改名重复。
6. 单独验证 **炸板修复**：T-1 `limit=='Z'`、流动、非跌停。对照：同收益/换手/市值匹配但不是 Z 的股票。
7. 再测 **连板龙头**（高尾部）。对照：同高度封板、不施加 open_times/封单排名。
8. 最后才测 **弱转强 / 情绪冰点** 作为门控。门控必须相对「无门控的同机制篮子」有增量；没有增量就丢掉门控。
9. 每个候选都要报：候选数、空仓日、Broker 拒单（尤其一字/涨停开盘）、行业集中、含成本 next-open 表现。
10. 把唯一幸存机制写入 `output/main.py`。失败则留下证伪，不叠均线或因子厨房。

## 执行草图

- `period=day`，`execute_at` 用推断日 09:30（Asia/Shanghai），不要用 09:29 当成交时钟。
- 竞价价只作研究过滤。Broker 在 09:30 用当日日线 `open`；竞价域不是成交价来源。
- 卖先于买；按调用前现金快照本地递减并留费用缓冲。不要把同一次卖出当成已到账。
- 买入手数向下取整到 100 股。涨停开盘被拒是结果，不是要绕过的 bug。
- 状态从可见行和 `context.account.positions` 重建，不要依赖可变全局「昨日候选」。

## 统一否证

- 含成本的次日开盘到开盘，不优于匹配对照。
- 看起来赚钱的部分来自把 T-1 收盘价当成可成交价。
- 收益集中在不可成交的涨停开盘；Broker 拒单后优势消失。
- 用 `fd_amount` / 日终 `first_time` / `open_times` 假装当日已成交或可排队。
- 把 `kpl_list` 或 `limit_step` 当成当日可买入证明。
- 使用 09:30 之后的分钟、当日 `limit_list_d`（16:00 才可见）或被快照剥离的 `limit_amount`。
- 聚宽/论坛宣传数字被写进预期。
