# Fold-ready 探索计划

目标不是复现任何单列读数，而是检验一件事：**分钟级 tick 规则算出的签名订单流（经派生事件表 `intraday_flow` 逐股票日提供），能否让一个只做多的截面篮子挣到供应商日频资金流之外的边际。** 一折跑多轮 `batch_validate`。有父本时，必须先完成一次与父本可执行逻辑不同的完整 Validation；父本对照由宿主在会话前跑好，不要自己重跑。

## 第 0 轮：不占回测预算的离线普查

用 `shell` 在输入窗上跑，不启动回测。任一条不合格就在第 1 轮的 `hypothesis` 里声明，不要硬凑。

1. **两张事件表是否真的选进来了**：`data_summary.json` 的 `events.datasets` 必须同时列出 `intraday_flow` 与 `moneyflow`；再报 `intraday_flow` 的行数与日期覆盖（**`snapshot` view 与 `valid` view 分别读，不得由前者推断后者**）。缺 `intraday_flow` 即本臂不可测，`report_issue` 后如实弃权。
2. **覆盖终点**：报 `intraday_flow` 在本折可见区间里的最后一个 `trade_date`，以及它与 `daily` 最后一个交易日的差。这张表跟随分钟按日层，当前终点是 2026-08-18；一旦本折区间的尾部没有行，`ofi_21` 会整段失效，必须先说出来再谈收益。
3. **两条过滤的剔除率**：`nret < 200` 与 `sealed_limit` 各剔掉多少股票日。参照值 0.3%–3.4%/日（2026-03-31 为 0.04%）。**> 40% 即本机制关闭**。
4. **单位与取值域**：`unit_reference.json` 里 `events.intraday_flow.ofi_1d`/`ofi_amt_1d`（无量纲）、`zero_share`（小数）、`nret`（计数）、`events.moneyflow.*_amount`（万元）。实测 `ofi_1d` 应落在 [−1, 1]，完整交易日 `nret = 239`。
5. **逐列健全性**：A 面五列、B 面六列，各报覆盖率、`NaN` 率、1%/99% 分位与**规模中性 rank IC 的符号**。任何一列符号与 `families.md` 的声明相反，就把它从等权合成里去掉并写进 `hypothesis`；不要事后翻符号。
6. **两面覆盖率必须可比**：在四个季度的月末决策日上报可选池大小与两面各自的非空率。参照实测（2026-03-31、池 3,343 只）：`ofi_21` 99.86%、`mfimb_21` 99.92%。差距若拉大到几个百分点，硬门比的就是覆盖而不是信号，必须先统一池。
7. **窗口成色**：报每个调仓日 `ofi_21` 由满 21 个可用股票日形成的比例（`min_periods=15` 的部分窗口占比）。两面都受同一条规则约束，差异必须一起报。
8. **成本预算实测**（下节）。

## 计算预算

改用派生日频表之后本臂不再有昂贵环节：两个特征面都是一次有界的事件域读取加一次逐股滚动均值。实测（沙箱镜像 `autotrade-sandbox:latest`，8 CPU，真实 as-of 布局，`events` 并集 208 万行 / 202 个交易日 / 池 3,343 只，`num_threads=5`）：

| 环节 | 实测 |
|---|---|
| A 面构建（`intraday_flow` 读取 + 过滤 + 21/5 日窗口 + 上下行分腿） | **6.6 秒 / 202 个交易日** |
| B 面构建（`moneyflow`） | 5.8 秒 |
| `o2` 一次完整 `fit`（面板 + 4 点网格） | **17.2 秒** |
| `c_mf` 一次完整 `fit` | 17.9 秒 |
| 一次 `generate_orders`（冷 worker，四条腿） | **6.0–6.6 秒** |

对照：改用 `intraday_flow` 之前，同样五列要流式扫过分钟分区，26 个交易日就要 30.8 秒（1.2 秒/交易日），一次决策 35 秒。

声明与护栏：

- **线程数 `num_threads=5`**。`batch_validate` 三路并发共享 16 CPU 的策略容器配额；`explore_github` 就是在 `num_threads=8` × 3 路下把一次 264–450 秒的 `fit` 撑到超过 3600 秒、白烧两个回测名额。**不要靠一次空载实测就登记候选。**
- **特征数 A 面 5 列 / B 面 6 列**。成本已经不是约束，约束变成多重检验余量：每加一列就多一次试验，而同一个数据面已经被测过十个构造、九个被证伪。要扩到 10 列以上必须先说清它为什么不是又一次事后挑选。
- 一次 `fit` 约 17 秒，是 3600 秒基准上限的两百分之一；`FIT_LOOKBACK_TRADE_DAYS = 260` 仍然保留，因为它同时限定训练窗口的长度，是研究口径而不只是性能护栏。
- 决策路径保留两条护栏：非再平衡日直接返回 `[]`，以及只用最近 40 个可见交易日形成窗口。两条都不再是性能所必需，但它们让冷 worker 与热 worker 的结果逐字节相同。

## 第 1 轮：四条腿，一次 `batch_validate`

| 候选 | 特征面 | 打分器 | 身份 |
|---|---|---|---|
| `o1` | ofi 5 列 | 等权 rank 合成 | 主候选 |
| `o2` | ofi 5 列 | LightGBM 4 点网格 | 主候选 |
| `c_mf_ew` | moneyflow 2 列（有方向） | 等权 rank 合成 | **`o1` 的硬门对照** |
| `c_mf` | moneyflow 6 列 | 同一 LightGBM | **`o2` 的硬门对照** |

四者共用同一股票池、同一标签（`h=20`）、同一再平衡节奏（20 个交易日）、同一 `topk=15`、同一半篮上限、同一分数层中性化、同一执行时点。`hypothesis` 必须写清：两面的列清单、标签口径与禁运长度、网格 4 点、等权合成的方向声明与「分档列无方向因此不进合成」这条不对称、`o2` 首季退化、以及下面的判定规则。

预算允许时四条一批（4 次回测 / 24）；若只能三条，先跑 `o1` / `c_mf_ew` / `o2`，`c_mf` 放第 2 轮——**但不得只跑 `o1` 与 `c_mf`**，那是跨对比较，混了两个改动。

### 预登记的首折判定规则

`ofi` 面通过，当且仅当以下全部成立：

1. `o1` 的 `benchmark.neutralized_excess_return` **>** `c_mf_ew` 的同一项，**且** `o1` 的 `null_control.excess_percentile` **>** `c_mf_ew` 的同一项。
2. 四个季度子窗中至少 3 个的超额同号，且不是单季独撑。
3. `cost_sensitivity.excess_at_2x_slippage > 0`，且整窗毛超额折年化 ≥ **5%**。
4. `null_control.excess_percentile ≥ 0.75`。
5. 零成交过滤剔除率 ≤ 40%；每个调仓日可选名字 ≥ 1,500；意图买单拒单率 ≤ 30%。
6. `o2` 与 `c_mf` 在**四个子窗**上都可比（两面都是日频事件表，训练条件对称）；`o2` 的中性化超额 > `c_mf` 的同期，则记「学习器在本面有增量」，否则记「无增量」并保留 `o1` 形态。第 6 条不成立不关闭家族——关闭家族的只有第 1 条。任何一折的订单 `reason` 出现 `_degraded` 都要当缺陷查。

未通过时的分支，逐条写死：

- **第 1 条不成立** → 分钟面没有在供应商日频资金流之上加进任何东西 → **本机制关闭**，不再换变体重试。按基线锚点规则提名过硬门的最好节点（很可能是 `c_mf_ew`），在折内记录里逐字写明两条腿的中性化超额与空对照分位，并写明「锚点不是本臂的机制」；下一折若不重新登记即终止本臂。
- **第 1 条成立、第 3 条不成立** → 机制真实但在 10 万元账户不可交易。第 2 轮只登记成本/执行变体（下节第 1、2 项），不扩特征；仍不成立即以「不可交易」关闭。
- **第 2 或第 4 条不成立而其余成立** → 不提名，第 2 轮跑列消融找出噪声列去掉后复测一次；仍不成立即关闭。
- **第 5 条不成立** → 先修过滤与篮子（实现问题不是机制问题），修完重跑一次仍不成立则如实弃权。

## 第 2 轮起：一次只改一个可分离组件

按下列顺序，每轮取一个，与当轮基准同批比较：

1. **执行时点**：卖买两腿都放 09:30（现在是卖 09:30 / 买 15:00，为的是卖出所得先入账）。这是探针里 `gap=1、次日开盘进场` 口径的直译，也是成本最省的一次改动。
2. **换手预算**：半篮上限 7 改成分数迟滞（持仓跌出 `topk × 1.5` 才卖）。证伪：中性化超额 ≤ 基准，或 2 倍滑点下超额 ≤ 基准，或换手没有真的下降。
3. **列消融**：`ofi_21` 单列 vs 五列合成；`ofi_up_21`/`ofi_dn_21` 去掉。产出一张「列 → 中性化超额落差 → 四子窗同号数 → 该列覆盖率」的表。
4. **窗口**：21 日换 10 日、42 日或 63 日。`intraday_flow` 从 2020-01-02 起逐日都有行，长窗口随时可以形成，所以这一项现在没有数据约束——正因如此它更要一次只加一个窗口，不要一批扫过去。
5. **标签口径**：`h=10` 且再平衡同步改成 10 日（持有期与再平衡必须同步改）；或标签改成对沪深 300 的超额。
6. **机制无关对照**（诊断用，永不提名）：原设计的 `c_path`（`rv`、`rsjv`、两段量能占比）需要分钟 Bar，本臂读不到；替代版只能用 `max20` 加已声明的中性化列，`hypothesis` 里要写明它比原设计弱。

家族切换规则：本轮全部候选被证伪后，下一轮必须换机制家族而不是换窗口；但本包的候选空间只有上面六项，用尽即以 `no_edge` 弃权，不得回退到通用价量打分。

## 臂级终止规则

以下任一成立时，本臂的这条机制线关闭，后续 Fold 不再重开：

- 首折硬门未过（`families.md` 的硬门）。
- 连续两折以 `no_edge` 结束。
- 连续两折里 `moneyflow` 对照腿在本折新季度（`sub_windows` 最后一行）的中性化超额不低于主候选。
- 连续两折的整窗毛超额折年化 < 5%。
- 三折之内 `ofi` 五列在消融里没有任何一列拿到「落差为正且四子窗同号 ≥ 3」。

## 超参与多重检验纪律

网格事先写死 4 点，在 `fit` 内用带禁运的时间序列验证选点并把选中的点写进 `context.state_dir` 与订单 metadata；不在 Validation 结果上调参。每个网格点、每个消融、每个变体都是一次试验，读 `selection_statistics.deflated_sharpe_probability` 时按 `trials_so_far` 打折。`run_null_control` 只给决赛候选用（每折上限以运行事实为准）。**同一个分钟面已经被测过十个构造、九个被证伪**，所以本折的试验池不是从零开始的——这一点要写进结果笔记。

## 每个候选必须汇报的读数

除标准结果块外，逐折写进结果笔记：四个季度子窗分别的中性化超额、有效覆盖、换手、拒单率、规模倾斜；两条过滤的逐折剔除率；两面在每个调仓日的非空率区间与 `ofi_21` 的满窗比例；`intraday_flow` 在本折可见区间的覆盖终点；`o2` 的 booster 特征重要性（按列）与是否出现过 `_degraded`；一次 `fit` 与一次决策的实测墙钟。缺任何一项的结果不作为提名依据。

## Validation 否证（任何一条命中，结果无效，不讨论收益）

- 任何 `available_at`、T-1、复权锚或标签前视错误；用 `trade_date` 判可见。
- 用 `trade_date` 而不是 `available_at` 判可见；把 `intraday_flow` 当成 T-0 可见。
- 用未实现的收益拟合（标签窗越过推断时点，或训练/验证之间没有 20 个交易日的禁运）。
- 训练面板与决策截面不是同一个函数构建的。
- 中性化超额 ≈ 0 或规模倾斜显著为负。
- 加手续费、滑点、涨跌停与手数约束后优势消失，或 2 倍滑点下超额转负。
- `fit` 超预算或决策超时：不是策略结果，先把计算压回预算再谈收益。
- as-of 事件域读失败后回退了 `snapshot_dir`；或读事件域时没有先按 `dataset` 过滤。
- `intraday_flow` 在本折区间尾部没有行却没有汇报（窗口会静默失效）。

## 收尾

用 `step_rollback` 把胜出节点恢复到 `output/` 再 `finish_fold`；对照节点（`c_mf`、`c_mf_ew` 与任何机制无关对照）不得被提名——**唯一例外是首折的基线锚点规则**，那时必须在折内记录里写明锚点不是本臂的机制。不要提交训练脚本或 `models/*.pkl`；`models/` 只放跨折继承的静态资产，拟合产物一律留在 `context.state_dir`。
