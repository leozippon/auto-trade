# 研究会话探索计划

目标不是复现方向研究的读数，而是检验一件事：**在 GPU 上按季度重训的 GRU 日频量价序列排序器，能否让一个每周复核的 15 只只做多篮子在研究期内逐年挣到中性化超额，并在成本后留下余量。** 提名条件、变体轴与终止规则只在 `families.md`；可见时点与单位只在 `pit-field-map.md`；本文只排顺序与预算。

## 回放预算怎么算

一个会话的回放预算是 24 个 replay-year（以运行事实 `budgets` 为准）。一个完整研究期验证 = 4 个研究年 = 4 个 replay-year；`batch_validate` 一批最多 3 个候选，一批完整研究期 = 12 个 replay-year。起步包的实测成本（`sources.md`）：一次三种子 GRU 季度重训在 L20 上约 2–5 分钟，一个研究年 4 次重训约 10–20 分钟，加上约 244 次决策（非复核日约 0.3 秒，每周复核日几秒）与视图加载，一个 replay-year 约 25–40 分钟墙钟，完整研究期约 2–2.5 小时；`c_lgbm` 的训练在 CPU 上，每次重训几分钟。一批三路并发时可能落在同一张卡上，墙钟会变长，但不改变预算计数。

## 第 0 轮：不占回测预算的离线普查

用 `shell` 在输入窗上跑，不启动回测。任一条不合格就在第 1 轮的 `hypothesis` 里声明。

1. **设备**：运行事实 `budgets.strategy_gpu_count` 必须是 1；会话容器里 `torch.cuda.is_available()` 为 True，记下卡名与空闲显存。为 0 或不可用时本臂无法运行，写进结果笔记后以 `continue` 交还，不改写成 CPU 版本。
2. **单位**：`unit_reference.json` 里 `daily.vol`（股）、`daily.amount`（元）、`daily.turnover_rate`（小数）、`daily.adj_factor`；抽一个名字核对复权价在除权日前后连续。
3. **面板与股票池**：在每个研究年的一个复核日用 `starter/lib/panel.py` 的同一函数建面板，上报名字数、有完整 60 日序列的名字数、股票池大小（方向研究里约 2,500–3,300 只）。
4. **一次 `fit` 的实测**：`smoke_backtest` 的首个决策日会跑一次完整 `fit`，读它返回的 `phase_seconds.fit`；这一步占用回放容器，不占回测预算。墙钟超过 1,800 秒先修实现；改动了序列长度、特征或批次缓存的变体，在会话容器的卡上用 `torch.cuda.max_memory_allocated` 量一次训练显存，超过 12 GiB 先修实现。

## 第 1 轮：三条腿，一次完整研究期 `batch_validate`

| 候选 | `CANDIDATE` | 身份 |
|---|---|---|
| `g1` | GRU 三种子 | **主候选** |
| `c_lgbm` | Alpha158 + LightGBM | **汇报用对照**（不得提名） |
| `v_ens` | 两者等权 | **登记变体** |

三者共用同一面板函数、同一训练日期、同一股票池与周度篮子，`main.py` 只差 `CANDIDATE` 一行（12 个 replay-year）。先对 `g1` 跑一次 `smoke_backtest`。`hypothesis` 必须写清：序列长度与输入特征、标签、训练窗口与验证切分、种子、股票池、篮子与换手上限，以及 `families.md` 的提名条件。

## 第 2 轮：一个变体轴

用剩下的 12 个 replay-year 做一批完整研究期验证：`g1` 的一个变体轴上的两个取值，加上当前最好的 `g1` 家族节点作同批基准（若它已有完整研究期读数，可换成第三个取值）。轴的顺序：a 序列输入特征（先加 `daily` 里的估值与市值列，再加资金流）→ b 序列长度 → c 损失 → e 训练窗口 → d 集成权重。放不下时把读数与待裁决的分支写进 PRIOR，以 `continue` 收尾。

判定分支，逐条写死（判据本身见 `families.md`）：

- **`g1` 满足全部提名条件** → 可提名；与 `v_ens` 都满足时按冻结门读数与逐年稳定性取更好的一个，简单优先。
- **`g1` 逐年为正的研究年不足 3 个** → 不可提名；逐年分块与 `c_lgbm` 的逐年差写进 PRIOR，下一轮换一个变体轴，不调阈值。
- **成本条件不成立**（2 倍滑点超额 ≤ 0）→ 本臂的换手上限是固定部件，不得放宽；换一个让排名更稳的变体轴（序列长度或训练窗口）。
- **实现底线不成立**（训练超时、显存超限、决策超 60 秒）→ 先修实现，修完重跑一次仍不成立则放弃该变体。
- **`c_lgbm` 领先 `g1`** → 预期之内，写明整窗与逐年差，不触发关闭，也不把 `c_lgbm` 改作候选。

## 第 3 轮起

一次只改一个可分离组件，与当轮基准同批比较。本轮全部变体都不满足提名条件时，下一轮必须换轴而不是换阈值；按 `families.md` 的终止规则判断是否以 `no_edge` 结束。

## 每个候选必须汇报的读数

除标准结果块外，写进结果笔记：逐年分块的中性化超额；与 `c_lgbm` 的整窗与逐年差；最好 15 只的持仓来源（`per_stock`、`pnl_concentration`）；年换手、拒单率与费用；规模与 β 倾斜（`style_analysis.json`）；每次 `fit` 的墙钟（`phase_seconds.fit` ÷ 重训次数）与显存峰值；三个种子的验证 IC。缺任何一项的结果不作为提名依据。

## Validation 否证（任何一条命中，结果无效，不讨论收益）

- 训练用了标签尚未实现的信号日；在 `generate_orders` 里训练或更新权重；把训练好的权重放进 `models/` 以跳过重训。
- `daily` 按 `available_at` 过滤（该列不存在）或从 `snapshot_dir` 读数；有行级时点的域没有先按 `dataset` 过滤、或用 `trade_date`/`ann_date` 代替 `available_at` 判可见。
- 训练面板与决策截面不是同一个函数构建的；候选之间的股票池、篮子或换手上限不一致。
- 写了 CPU 回退路径，或在没有 CUDA 时静默继续。

## 收尾

冻结的是提名节点自己的不可变快照；`c_lgbm` 节点不得被提名。不要提交训练脚本；`models/` 只放跨会话继承的静态资产。
