# 学习型候选的 `fit` 成本纪律

自写笔记。本仓库在学习型臂上赔掉过最多的回放年——两次整期批次撞上 `fit` 上限，每次把整批的回放年一起赔掉。本臂有一条腿（DoubleEnsemble）的拟合是载体的好几倍，而且它每个季度都冷启动，所以这一页把要做的几件事写死。

## 三条上限

| 边界 | 值 | 性质 |
|---|---|---|
| 一次 `fit` 的墙钟 | 运行事实 `budgets.strategy_fit_timeout_seconds`（基准 **3,600 秒**） | `batch_validate` 的并发池按本批并发路数放大它（三路 = 三倍），**但只补偿本批自己引入的争用**；跨实验的争用不在补偿之内 |
| 一次复核决策的墙钟 | `budgets.strategy_inference_timeout_seconds`（基准 **360 秒**） | 超时与抛错一样，整个回放失败 |
| 策略容器 | **8 核 / 16 GiB**，`/tmp` 与 `/dev/shm` 各 2 GiB（都算在这 16 GiB 里） | **`--memory-swap` 与 `--memory` 同值：超了不是变慢，是直接 OOM 杀掉（退出码 137）**。会话容器是同一个边界，所以在 `shell` 里量到的峰值就是正式回放的口径 |
| 显存 | 本臂 `gpu_count = 0`，不分配显卡 | 载体与两件事全是 CPU 上的 LightGBM 与 numpy；**没有任何一步需要 CUDA** |

## 每条腿花多少（实测，读法见下）

完整数字、口径与主机负载在 `sources.md`。量级是：

- **`c_base` / `c_cold` / `lr1`**：一次冷拟合十几到三十秒，其中 booster 本身只占 3–8 秒，其余是三年窗口的面板与 158 个算子；进程峰值约 1.5 GiB，宿主回放的容器峰值 2.1–2.3 GiB。
- **`de1`**：一次拟合约为载体的 **3–6 倍**（宿主冒烟 134.6 对 40.1 秒；重负载的探针里近 200 秒对 30 秒）。三分之二以上的时间花在两轮 FS 的打乱重算上（`F × 包含该列的子模型数` 次全训练集预测）；三次 booster 训练与损失曲线加起来只占小头；内存与载体同档（进程 1.64 GiB，宿主容器峰值 2.36 GiB）。
- **`de_lr`**：比 `de1` 便宜一半多，因为排序子模型只长几棵树，FS 的每次预测都很轻。
- **三路并发**（两条 `de1` 加一条 `de_lr` 同时拟合、主机另有重负载）：每路秒数与单跑同档，内存每路仍约 1.6 GiB。**最坏情形离 1,200 秒还有数倍余量，离 3,600 秒一个数量级**。

**持久化的账要算清楚**：DoubleEnsemble 每季度都冷启动是构造决定的，但冷启动本身不是它贵的原因——载体的续训并不比冷启动快（实测 15.0 对 16.1 秒，与同谱系上一轮一致：**续训的理由是模型连续性，不是速度**）。它贵在集成本身。一次四年整期回放 16 次季度重训，`de1` 的拟合合计比 `c_base` 多出十几分钟到四十分钟（看主机负载），这是预算里要付的那一项——它花墙钟，不花回放年。

## 什么会把成本顶上去

1. **`knobs.DOUBLE_ENSEMBLE["models"]` 从 3 改成 6**（变体轴 a）：FS 的预测次数约变成 4 倍（后面每一轮都要把之前全部子模型重算一遍），外加三次 booster 训练。按实测外推，负载高时单次拟合进入 500–600 秒量级——**先用 `smoke_backtest` 量一次再进批次**。
2. **`REFIT_PERIOD` 从季度改月度**：一个研究年 4 次重训变 12 次，`de1` 的账同比例乘 3。
3. **`knobs.TRAIN_YEARS` 加一年**：训练行、面板与每次 FS 预测同比例涨。
4. **子模型的树数变多**：`de1` 第 2…K 个子模型训练第 1 个子模型早停时保留的树数；某个季度那棵树数高，FS 就同比例变贵。结果笔记里要报每次拟合的树数。

**每改一件，重量一次。**

## 本包要求的三件事

1. **整期批次之前，先在研究期靠后的槽上用 `smoke_backtest(start=...)` 跑一次每条要进批次的腿**，读 `resources` 里的 `fit_seconds` 与 `peak_memory_bytes`，写进结果笔记，并确认峰值离 16 GiB 有明确余量。第一研究年的读数不算数：那时训练窗口有一半落在成分数据下限之外。
2. **同一个 `start` 复用。** `window_build_seconds` 几乎全是那个窗口一次性的开窗成本（主机侧），**付一次，后面同一个 `start` 的探针直接复用，永远不要乘以天数**；整期批次从研究期开头开窗，根本不付这一笔。
3. **拟合的候选要报种子差。** 这个家族的方向研究在三个种子之间散开过 4 pp/年 的 alpha；DoubleEnsemble 的 FS 抽列也由同一个种子驱动。**比种子差还小的优势不是证据。**

## 三条实现纪律

- **线程数写死在 8**（`knobs.PARAMS["num_threads"]`），不是留给库去猜 CPU 数。多路并发时让每一路自己抢满会互相拖垮。
- **训练面板按成分并集下推 `ts_code`**。不下推就是把全市场三百多万行读进 16 GiB 的容器里。
- **单跑的秒数对主机负载极敏感**：同一条腿、同一个窗口，本包在两个时刻读到 16.1 与 29.6 秒。耗时结论按多日回放的平均读，不按一次探针。
