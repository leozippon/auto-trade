# 读数、出处与诚实的限制

## 这一页最重要的一句话

**本包有实测支撑的是可跑性、成本、逐字节的一致性与两个学习器在这个载体上的形状，不是「换学习器有增量」。** 文献给的只是一个方向；第 0.5 轮的离线门是本臂第一个真正的读数。本页的结构性读数都测在研究期 2021-07-01..2025-06-30 之内，没有任何研究期之后的行。

## 文献给了什么，搬得过来的是什么

**搬运结论（登记在 `README.md`）**：这些读数的协议是每天 50 换 5（年换手约 24 倍）、收盘成交、以市值加权沪深 300 为基准的原始超额，模型只训练一次，年份多在 2021 年价量因子衰减之前。它们的**水平**在本仓库的口径（月度复核、主动序列减同形状零技能面板、季度重训）里没有意义——Qlib 的 LightGBM 9 % 超额正好是本仓库同形状零技能面板的量级。**能搬的只有同一套特征、同一套协议下「DoubleEnsemble 排在 LightGBM 前面」这个方向**，三次复跑同向。排序损失的证据更弱：美国月度、无成本、多空两头都用，而本臂是只做多、只用顶部的书；A 股上 GBDT 排序目标没有找到像样的公开读数。

另外两条读法：Qlib README 里中证 500 的 DoubleEnsemble 行与 Linear 行组合读数逐位相同，是抄录错误，不要引用；Qlib 报出 DoubleEnsemble 读数的配置是每个子模型固定 28 轮、学习率 0.2、210 叶，本包不取那组树参数（`families.md`）。

## 起步包在沙箱镜像里的实测（容器边界内的探针）

**这不是宿主回放的读数**，是一次容器内探针：同一个沙箱镜像（LightGBM 4.7.0）、`--network none`、只读根文件系统、**8 核 / 16 GiB**（`--memory-swap` 同值）、2 GiB `/tmp` 与 `/dev/shm`、**无 GPU**，把第四研究年首个决策日（2024-07-01，锚点 2024-06-30，来自种子 `data/pit_views_seed_research_20260919`）的决策视图当作一次 08:30 决策的 as-of 视图，账户 100 万元、空仓起步，依次调用 `fit` → `generate_orders` → 再一次 `fit` → `generate_orders`。训练窗是完整的三年：190,660 个训练行、666 根训练 bar，16,974 个验证行、60 根验证 bar；可打分成分 283 / 300。

|---|---|---|---|---|---|---|---|
| `c_base` | **16.1 秒**（轻载） / 29.6 秒（重载） | 15.0 / 29.6 秒（续训） | 2.8–6.0 秒 / — / — | 0.4–0.6 秒 | 1.58–1.62 GiB | 49（续训后 61） | 1.000 |

| `de1` | **176.5 秒**（重载） | 193.7 秒（冷） | 8.7 + 4.1 + 5.5 / 0.7 / **51.7 + 70.5** 秒 | 1.0–1.1 秒 | 1.64 GiB | 49 / 49 / 49 | 1.000 |

「轻载 / 重载」是同一台主机上两个时刻的负载（1 分钟负载约 12 对 35–78，其余三条研究臂与别的作业同时在跑）；**同一条腿、同一个窗口在两个时刻差将近一倍**，所以耗时按区间读，最坏情形按重载读。

**最坏情形，登记在这里**：负载最重、三路 DoubleEnsemble 同时拟合时，单次 `fit` 实测最长 **193.7 秒**、内存每路不到 1.7 GiB。`batch_validate` 最多三路并发，最坏的组合就是这一组；它离本包给自己定的 1,200 秒线有 6 倍余量，离 3,600 秒上限一个数量级。K 从 3 改成 6（变体轴 a）时 FS 的预测次数约变成 4 倍，按这组读数外推单次 500–600 秒，仍在 1,200 秒之内，但要先量再进批次。

**逐字节的一致性（全部实测）**：

- **`c_base` 就是头包的载体**：同一个切片上，本包 `c_base` 写出的 booster 文件 sha256 与头包 `flow_block_20260923` 的 `c_base` 相同（`400e7a0e…`），第一天的书（50 只 × 股数）的散列也相同（`1b870103…`）。改同分规则之后重跑，书的散列不变——`c_base` 的分数没有并列。
- **`de1` 的第一个子模型就是 `c_cold` 的 booster**（同一个 sha256），**`de_lr` 的第一个子模型就是 `lr1` 的冷 booster**。
- **损失曲线的逐树累加与 LightGBM 自己的前缀预测逐位相同**（最大绝对差 0.0），所以只算前后 10 % 的树是精确的，不是近似。
- **可复现**：`de1` 在三次独立的容器里（一次单跑、两次并发）写出同一本书（散列 `533a890c…`），`de_lr` 两次写出同一本（`c7bbc843…`）。

## 两个学习器在这个载体上的形状（探针里量到的，决定了登记）

**DoubleEnsemble 的子模型不能按不加权的验证损失早停。** 第一版起步包让每个子模型都按载体规则早停，结果第 2、3 个子模型只长了 **4 棵与 3 棵树**（第 1 个 49 棵）：它们在重加权的损失上训练，却在不加权的验证损失上被判停，重加权还没起作用就停了，集成的排序几乎就是第 1 个子模型、也就是 `c_cold`。改成「第 2…K 个子模型训练第 1 个保留的树数」之后，三个子模型都是 49 棵，FS 留下 81 / 83 列（第四研究年首次重训）、77 / 79 列（下一个季度）。

**排序目标的增益形状**。在同一个训练窗上，用载体的参数点训练 lambdarank，只改增益与等级数，读早停树数与验证 bar 上的两个秩 IC（对标签、对标签绝对值）。**这是非退化检查，不是挑参数**：60 根验证 bar 同时是早停用的，读数偏乐观。

| 设定 | 早停树数 | 验证 NDCG@50 | 秩 IC（对标签） | 秩 IC（对标签绝对值） |
|---|---|---|---|---|
| 载体（L2 回归） | 49 | —（L2 0.0811） | **+0.083** | −0.133 |
| 指数增益，20 级 | 16 | 0.240 | **−0.113** | **+0.251** |
| 指数增益，5 级 | 2 | 0.348 | −0.011 | — |
| 指数增益，31 级（LightGBM 默认） | 8 | 0.205 | −0.120 | — |
| **线性增益，20 级（登记值）** | **2** | 0.572 | **+0.091** | −0.043 |
| 线性增益，学习率 0.02 / 0.01 / 0.005 | 13 / 11 / 8 | 0.578 / 0.573 / 0.586 | +0.074 / +0.067 / +0.067 | −0.075 / −0.084 / −0.067 |

**三条读法。** 第一，**指数增益学成了一次离散度押注**：它对标签绝对值的秩 IC 是 +0.25，对标签本身是负的——指数增益只奖励把最高一档放到顶上，对把最低一档放到顶上几乎不罚，于是模型去挑两头都可能落的高波动名字；一本只做多的书吃不到这个。所以登记线性增益，指数增益不在任何变体轴上。第二，**在载体的参数点上排序目标只长 2 棵树就早停**，降学习率也只到 8–13 棵，验证 NDCG 在前十轮之内见顶，决策日 283 只里只有约 64 个不同分数。本包不为它改参数点（那会同时换损失与模型容量），并列交给同分规则，读数写进 `families.md`。第三，这些都是**一个训练窗、60 根 bar** 上的读数，离线门才是判据。

## 宿主流水线实测（正式回放路径，非探针）

同一个起步包，走**真实宿主流水线**：控制台的创建前检查（`_round.normalize`，参数与本臂的轮次条目相同：100 万元、`benchmark_index = 000300.SH`、`gpu_count = 0`、回撤 0.45 / 0.30 与本轮的毕业门）→ `resolve_worker_options` → `worker._strategy_sandbox_from_spec`（断言 `gpu_count = 0`、`memory = "16g"`、`cpus = 8`）→ `ResearchPITSnapshotProvider`（种子 `data/pit_views_seed_research_20260919`、`required = True`，视图硬链接，准备 0.0 秒）→ `PITDailyEvaluationBackend.evaluate` 在沙箱镜像里回放，滚动 as-of 视图、真实 `AccountSnapshot`、真实 Broker 与成本。账户 100 万元，槽为第四研究年，**回放 70 个决策日（2024-07-01..2024-10-15），跨过 2024-10-08 那次季度重训**。

**续训在真实执行器下被走通并且可读**：`c_base` 的第二次重训（2024-10-08）是续训，订单元数据里 `refits` 1 → 2、`cold_refits` 保持 1，状态目录里的 booster 从 49 棵长到 50 棵——新季度的数据上续训只多长了一棵就早停。`lr1` 同样续训（2 → 8 棵）；`de1` 两次都是冷启动（`cold_refits` 2），与构造一致。

**月度复核被确认**：70 个交易日里三条腿都是 **4 个买入日 / 3 个卖出日**（2024-07-01、08-01、09-02、10-08），成分截面逐月滚动四张（`20240628` / `0731` / `0830` / `0930`），每次复核书都是 50 席。扣掉首日建仓（约 0.97），70 天换手约 0.98–1.03，年化约 **3.4–3.6 倍（双边）**，离 12 倍上限有三倍余量；整期回放的换手要按 P3 重测，不要用这个数外推。

**订单流是正常的，有一处要如实读**：买单全是 100 股整手，可打分池 281–283 只，买不起的成分 2.1–3.2 %，书覆盖指数权重 12.6–20.3 %（`de1` 最低）。**实际权重的下沿读到 0.0093（`de1`）/ 0.0126（`c_base`）/ 0.0167（`lr1`）**，目标是 0.02：某一次复核的最后一张买单在剩余现金截断之后只买到半个座位左右。这是按最近整手四舍五入加现金截断的已知后果（`references/capital-arithmetic.md`），**每次复核都要报实际权重对目标的偏离，不要当成噪声**。

**方向性的实现检查读数（不是成绩）**：β 0.815 / 0.898 / 0.958、`size_tilt` 0.946 / 0.931 / 0.928、`top_industry_weight` 0.228 / 0.198 / 0.191（P2 的 0.30 之内）、最大回撤 9.2 / 8.3 / 10.5 %（依次为 `c_base` / `de1` / `lr1`）。

**没有一次 OOM、没有一次超时、没有一次 loader 拒绝。** 拒单全部是 `missing_execution_price`（当天停牌的名字），在提名条件 9 的 30 % 之内。

**这 70 天的收益读数不可用于裁决**：`max_days` 路径不抽零技能面板，所以**没有任何主动统计量**；上面的 β、规模与行业读数只是实现检查，本页也有意不列这 70 天的超额。

## 诚实的限制

- **「换学习器有增量」没有实测支撑。** 本包只有成本、形状与方向性的文献，没有任何本仓库口径下的收益读数。
- **`de1` 与 `c_base` 之间有一处结构性的差**（冷启动对续训），只能靠 `c_cold` 拆开；续训在树载体上的价值本仓库从没量过（登记册 §4 的三条都来自深度学习臂）。
- **`lr1` 在载体参数点上几乎不长树**，分数大面积并列；它的书有一部分是由同分规则决定的。这是「只换损失」这条登记在这个载体上的真实样子，不是实现缺陷，但它让 `lr1` 的读数更吵。
- **排序目标下的 SR/FS 逐样本损失是本包的改写**（日内 z 分数差的平方），不是论文的；`de_lr` 的读数因此只对本包的定义负责。
- **起步包的探针与冒烟都只在第四研究年的一个窗口上**；子模型树数、FS 留下的列数与排序腿的树数都会随季度变，结果笔记要逐次报。
- **月末成分截面**是股票池这一面最大的限制，两张之间的真实调整看不见（`references/index-membership.md`），供应商会回填历史权重，幅度未量化。
- **科创板与北交所整族被起步包从下单池里剔除**（一手粒度不同），训练仍然用它们。
- **10 日标签配月度复核是一处已登记的错配**，它是本轮所有同载体臂的构造风险，不是一个可以顺手改掉的常量。
- **本包不假设本臂的账户与授权。** 起步包按 100 万元不带授权写成（50 席）；运行事实不符时按 `families.md` 改登记。
