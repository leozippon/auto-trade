# 记忆的写入、容量与检索·10 万元账户（memory_100k_rolling，20261031）

本目录是只读参考包，会话里挂在 `refs/`。包里没有起步策略：`output/` 开局是合同模板自带的最小基线（`output/README.md` 的「Default strategy」）。`refs/memory-framework.md` 是所有者的记忆框架原文，本文件不重复它，也不改写它的数学。同一份方向包会同时交给两个相互独立的会话，各自在隔离的工作区里从头做起，两边不共享中间结果。

## 方向

在研究期上，研究记忆本身：模型把此刻可见的市场信息写进参数化记忆（外积累加、按预测误差在线修正、一次性回归到全部已存记忆）或非参数化记忆（案例库、检索、上下文），在推断时按查询把它取回来；可以改的是写入规则、容量与遗忘的分配、检索方式、记忆与参数化预测器的分工，或者会话自己想出的别的组织方式。

要在研究期内回答的是同一个可证伪问题：**在相同的可见市场信息、相同的标签成熟规则、相同的组合构造与执行、相同的交易成本下，改进记忆的写入、容量分配或检索，能不能比同输入的适当对照带来可复现的、扣费后为正的收益增量。** 适当的对照不预先指定，但至少要有同输入、同标签或无机制的对照，比如同一批输入上的简单参数学习、定期冷重训、把记忆关掉的同一载体；对照弱到什么都说明不了时，读数再高也不算增量。

要的是两件事同时成立：一种有明确新意的记忆机制（不是把已有因子换个名字），以及可复现、扣费后能盈利的策略。分别报告账户绝对净收益、对基准和零技能面板的表现、以及对去机制对照的增量；只比一个亏损对照少亏，不能称为盈利。盈利与否、是否稳定，只看真实宿主账与回放结果：研究期的读数再好看，账面与稳定性不支持就仍然算未成立。

做不做、做成什么样由会话决定：用什么科学假设、什么网络、哪种记忆（或干脆不用上面列出的任何一种）、是否用预训练模型、是否上 GPU，都不受规定；不强求把卡用满。判定的主要依据是宿主回放与现有裁决流程，不是自建模拟器的读数：自建模拟器可以筛想法，不能代替宿主，也不要自建撮合或成本模型去顶替宿主的那一套。

## 这份框架的位置

`refs/memory-framework.md` 是工作假说，不是已验证的定理，也不构成任何交易优势。文中按「干扰与信号之比」达到 1 估计的容量阈值——外积的 $M\approx d_k$、最优线性与 ReLU 的 $2d_k$、幂次门控的 $d_k^p$ 与 softmax 的指数式——都是随机独立键值下的量级近似：它不等于「能严格拟合全部记忆」的容量，也不能直接换算为「每个参数存多少比特」，其中的经验比特数需要分别检验。

两个约束在比较时要摆明：显式存 $K$ 与 $V$ 的非参数化记忆，其宽度、存储与每次检索的代价都随记忆条数 $M$ 增长，因此它和「固定参数预算」的模型不是同一种资源；金融标签几乎一定是有相关性、非平稳、带横截面依赖的，随机独立键值的近似在那里未必成立。

所以这份框架的用法是提假设、定对照、解释机制，不是引用它的容量公式当作预期收益。实证反驳它、或量出它的近似在金融数据上失效，都是合法结果。

## 对照要能支撑归因

同时改训练窗口、更新频率、特征数或组合规则的对照，只能比较整套方案，不能把差值单独归因于白化（键的协方差校正）、遗忘或非线性：那种差值里混着容量、训练机会与换手。特定机制的主张要用真正只差关键因素的对照来支撑——同输入、同标签、同训练机会，只动被主张的那一处，必要时增加保持样本边际分布与交易约束的打乱对照。机制顺带改变了容量、参数量、可见信息或训练机会时，把改动写清楚，不要把由此带来的提升记在记忆机制上。

## 运行资源

GPU 设备、卡数、回放并行度、CPU 和内存由本臂的启动参数决定，以宿主提供的 `budgets` 为准，不由研究方向固定。只使用分配给本臂的设备，在容器中按可见设备编号使用 GPU，不硬编码宿主物理卡号。模型大小与批量应适合实际资源，先冒烟测量耗时和峰值，再扩大运行；宿主没有通用的按腿显存硬限额。

实验、训练、推断、评测与数据处理前后执行 `nvidia-smi`、`free -h` 并记录，资源不安全时缩减或停止自己的工作，不影响其他作业。

本臂不接券商、不下真单；回放与可能的 Paper 记录都不构成实盘交易授权。

## 时点、标签与状态

- **标签何时可用。** 一个样本的结局（其后若干日的收益之类），要等它的预测期限走完、期限末那天的价格进入决策的视图之后，才能用来训练、写入记忆或更新参数；记忆库里任何一条案例都不能带着决策当时不可能知道的结局。研究期的起止与各年的切分以运行事实为准。
- **状态只活在一场回放里。** `context.state_dir` 在每场回放开头是空的、结束就丢弃，所以权重、记忆与测试时累积的状态只能在每场回放里从按时点的数据建起：每场验证、冒烟与冻结产物的重放都重新来一遍，什么都不跨回放保留。会话在研究期末视图上训练好、放进 `models/` 带进回放的权重是前视。
- **随时间增长的状态要专门预算。** 记忆若随回放增长（每天入库、每场都追加），几天的冒烟看不到它：此前一条检索腿在整期里记忆条数持续增长，每天 `fit` 的中位耗时与显存峰值都随之后移，冒烟那天看着够用的余量到期末不够用。整期行的 `resources` 给出峰值；提交整期批次前，在研究期靠后的一天再冒烟一次。
- **标题文本。** `context.asof_dir + "/text_index"` 是 parquet 分片目录，列 `text_id, dataset, ts_codes, title, available_at, library_file`，只有 `dataset == "anns_d"`，每行只是标题加一条 PDF 链接；正文不在种子里，容器也没有网络。回放在每晚 23:15 的文本节点放行标题，T 日 08:30 的决策看到的是前一晚的节点，所以 D 日的标题最早用于 D+2 起第一个交易日的决策。较早的标题源数据往往只给公告日期，可见时点仍以视图中的 `available_at` 为准；有些年份的公告送了两份（普通标题与加公司简称前缀的一份），按条数计的标题特征会随之跳变，需要条数时按（股票、决策日、去前缀标题）去重。
- **预训练权重知道研究期。** 预训练模型发布之前的日子都可能在它的训练数据里：研究期上经预训练权重读出的任何东西，都可能来自模型对那段行情的记忆。嵌入也一样：它把同一事件的标题放得彼此相近，而那件事后来怎样可能就在它的语料里。用到预训练模型、编码器或重排器时，配一个去掉模型或打乱输入的对照。

## 规模与时间

研究期起止、各研究年与回看范围以宿主运行事实为准；实际数据规模和覆盖查本次运行的 `data_summary.json`。不要把暖机数据的起点当成研究起点；两者若出现无法解释的矛盾，应报告而不是自行改变研究边界。

一条整期腿的墙钟时间是全部 `fit` 的时间再加 `fit` 之外的部分（宿主建每天的视图、决策与 Broker）；后者的量级要先在本腿测量，不是共享本机上的耗时保证。能按截面或按日成批算的就向量化地算，用满分到的核；方法受益时放上卡，因为单日省下的时间会按整期的决策日数放大。自己的策略用 `smoke_backtest` 量几天的单日耗时，`batch_validate` 的每一行带墙钟秒数与 `resources.fit_seconds_summary`。Paper 账户的 `state_dir` 逐日保留，那里逐日增长的记忆会接着增长，`generate_orders` 里贵的计算每天早上都要把此前的决策重做一遍。冒烟的天数与验证的次数上限由工具与宿主执行，本包不复述。

## 数据域

本臂挂哪份种子、从哪一年起算、回看多少个月，由运行事实给出。此前的选择是日线（同一行并入每日指标、复权因子与涨跌停价）、逐研究年的 `universe`（名称、交易所、上市日、申万一级）、四张宏观表（`index_daily`、`index_dailybasic`、`index_weight`、`sw_daily`）、财务域十个数据集（`income_vip`、`balancesheet_vip`、`cashflow_vip`、`fina_indicator_vip`、`forecast_vip`、`express_vip`、`dividend`、`fina_audit`、`fina_mainbz_vip`、`disclosure_date`）与公告标题 `anns_d`。没有事件域（资金流、两融、龙虎榜、股东与质押）与分钟线；竞价若挂载，当天 09:29 才可见，08:30 的决策看不到当天的。单位按「文件 + 数据集 + 字段」查逐列的单位表，不仅凭同名字段推断。哪个域在这份视图里可用、覆盖到哪天，以 `visible_timeline` 的标志与 `data_summary.json` 的实际行数为准，零行也是一种答案。

离线筛选若对全历史使用期末的名称、ST 或行业归属，可能含事后筛选偏差，不能拿这种读数代替逐时点回放。

## 旧案例

以下是同一方向在更早那份数据的研究期上读到的形状，只是旧案例，规模与窗口都与当前不同，用来说明哪些路已经走过。它们是具体实现的读数，不是判决；新机制若能解释旧结果，按新读数判。

- 逐日持续梯度更新（头永不重新初始化、参数分组按不同周期更新、带片段存储）在一个约 9.2 万参数的逐股 GRU + FFN 上，不及同架构的季度冷重训与只拟合一次的冻结模型；输出层更快的分层学习率没有赢过均匀或反向的学习率。
- 同一族在语言模型载体上重开：冻结的小语言模型读匿名化公告标题加十路日线特征、只更新一个约 3.6 万参数的头，种子平均上仍不胜冷重训；分层时钟没有得到支持；证据门控的逐日提交／回滚没有胜过季度冷重训，也分不开随机时刻的更新。
- 检索相似历史案例的起步构造（价量形态加标题向量的键、按时点增长的案例库、最近邻的核加权结局）赢了同键上一个按季冷重训的小网络，但那个对照本身是负的；相似性没有胜过随机邻居，持续入库在后半段输给冻结的记忆。
- 在一个案例库上让一个 27B 模型在上下文里重排短名单，增量与喂随机案例的安慰剂分不开；经预训练权重读到的东西带有模型对研究期的记忆。
- 训练窗与近期加权（2 年窗、5 年窗、半衰期的近期加权）、季度重训之间的每月热启动更新，都让同一本序列书在研究后半段变差，同种子的季度重训对照反而最好。
- 适应构造在宿主上的增量落在噪声里：按市场状态给书开关仓、按近期表现给袖子重配权重、按状态改复核节奏、季度重拟合因子权重，都没有胜过静态版与滞后一年的安慰剂。

这些关闭判定的是被测过的实现与承载它们的书，仍在开放之列的包括持续记忆本身、别的载体、别的更新与检索规则，以及把记忆用在容量分配或遗忘策略上而不是逐日微调上。旧的失败理由也可以被推翻：如果新机制让某个旧读数在新对照下不再成立，把对照和读数一起写清楚。

## 建议（可以不采纳）

以下是此前各臂留下的做法，不是要求：怎样做由会话决定，不采纳不影响任何评判。

- **先把假设与对照摆出来。** 在研究期里动手之前，写清这条机制的科学假设、它要打的对照、以及什么读数会证伪它；同信息、同训练机会的去机制对照优先，预登记之后按已有预算迭代。
- **对照。** 筛选脚本（`source_refs.signal_screen_ref`）可以在花任何回放之前把很多想法筛到少数几个；`run_null_control` 的随机同名组合能说明收益是不是来自这个机制；同一载体上把记忆关掉、把写入规则换成不作任何修正的累加、把检索换成随机邻居，都是这一族自然的对照。
- **机制解释与读数并重。** 读数没过门的臂要写清是哪一层机制没起作用；「统计没过门」不能代替机制解释，反过来，机制讲得通也不能代替扣费后的宿主读数。
- **载体可以很小。** 容量、写入与检索的规则，和载体的绝对规模并不是一回事；先在小载体上把机制与对照分开，再考虑换更大的网络或加预训练权重。换载体时容量与训练机会一起变了，归因按上文的对照口径重新做。
