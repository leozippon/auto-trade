# AlphaQCM 公式化因子挖掘的复现、移植与评估·20 万元账户（alphaqcm_200k，20261121）

本目录是参考包，会话里在 `refs/`：每次尝试开头从签入的版本与核对过摘要的论文载荷重新复制，可写，改动不保留。包里没有起步策略。

## 方向

所有者要求从近三年 ICLR、ICML、NeurIPS 的论文里挑出可能用于金融市场的方法，让会话复现、微调，再判断它能不能产生赚钱的策略（原话在 `refs/references/proposal.md`）。本臂的论文是 AlphaQCM: Alpha Discovery in Finance with Distributional Reinforcement Learning（ICML 2025）。它用强化学习逐个 token 生成价量公式，把公式收进一个线性组合的因子池；主张是：方法的关键部件是 QCM 方差探索项（用分位数网络的输出按 Cornish-Fisher 展开回归出累计奖励的方差，选动作时加上 λ 倍的标准差），在 A 股 CSI 300、CSI 500 与全市场上，20 天收益的测试期 IC 达到 8.49%、9.55%、9.16%，高于 AlphaGen 与树模型。论文的设定、报告的数字与我们的数据之间的差别在 `refs/references/claims.md`。

问的是：这个方法在本项目按时点可见的 A 股数据与决策节奏上，比同样输入的强基线多出什么；多出的部分是不是来自它的 QCM 方差探索项。

## 三个阶段

1. 复现。论文的数据离线不可得，所以在本项目研究年数据上按论文超参做一个忠实的小规模替身：同样的六个价量操作数、代码里启用的算子集、常数与时间窗，同样的因子池（L1 权重、容量 P、互相关 0.99 的拒收）、同样的 QCM 智能体（IQN 骨干加 DQN 的 Q 网络，λ = 1），目标是 20 个交易日的收益。训练段取研究年的前面部分，验证段取其后一年，用来选 P 与检查点；研究年的最后一年不给挖掘器看。规模可以缩：P 取 20（再试 50），总步数从论文的 30 万步按量出的吞吐缩减，并写下缩了多少。健全性目标：在最后一个研究年上，挖出的池的逐日 IC 与秩 IC 为正，并且按日配对后高于同样大小的随机公式池（从同一文法随机抽 P 个合法公式，权重用同样方法在同一训练段拟合），差的 t 值大于 2（20 天收益逐日重叠，用不重叠的子样本或按块的标准误）；再给出训练集池 IC 随步数的曲线。论文的 IC 是另一时段、另一股票池上的数，只作量级参考。代码可以放在 `PYTHONPATH` 上直接运行；Qlib 读数、gymnasium 基类与 tensorboard 日志三处要替换，做法在 `refs/references/claims.md`，不需要额外的包。超过一次 shell 调用时限的训练按 shell 工具说明以分离作业运行并写检查点。达不到目标时写下差多少、可能的原因，再进入下一阶段；复现失败不等于方法无效，也不是停止的理由。
2. 移植与微调。把方法移进策略包：表达式、因子池与 QCM 智能体只用合同允许的库重写（作者代码里的其他依赖不能被策略导入），在 `fit` 里只用当时可见的数据挖掘，按会话选定的再拟合节奏更新；一次挖掘要多久先量出来，再定每次再拟合是重挖、接着挖还是只重拟合池的权重，每次 `fit` 的时限在运行事实的 `budgets` 里；规模（步数、P、网络宽度）按量出的耗时、显存与这个时限往上试，不按回放快慢，试过的规模要跑完并记下读数，中途停掉的不算试过。公式在决策时只用可见的日线求值，打分只在可交易的股票上排序。超参与结构可以为 A 股调整（目标的起点与期限、P、步数、λ、算子集），每个改动在记录里写一行理由。
3. 评估。按下一节的对照读结论。

## 所有者的要求

本臂被测试（`test`）的候选必须以论文方法为主要打分：挖出的因子池的线性组合决定排序，不是在别的打分上加一个小幅倾斜。树排序器、去掉关键部件的版本与其他基线是对照，在 `validate` 里与候选同批验证，不测。方法读得比对照差时，照样测最好的方法版本，并在记录里写明差距：这正是本臂要的答案。本臂做完，是记录里的结论有下一节的读数撑着，不是验证期的步测完了：测完最后一步会话就结束，记录之后不能再补。两次 `test` 之间的研究用来推进阶段二与阶段三（新的方法版本、补上的对照与种子），不要在预算还剩大半时把同一个候选连着测完。

## 让结果读得出来的对照

- 关键部件有没有用：对着同一管线、只把 λ 设为 0（论文 Table 2 的「无方差」）、总步数与再挖掘节奏相同的版本读；两者的 Q 网络、分位数网络、回放与 ε 都一样。
- 搜索有没有用：对着同样大小的随机公式池读；再加一个同样评估次数的随机搜索（随机合法动作生成公式，送进同一个池）更好，它分开了「强化学习」与「池的贪心筛选」各自的贡献。
- 方法有没有用：对着同样输入（同样六个价量字段的历史窗口）、同样标签与同样持仓规则的 LightGBM 排序器读。
- 对照跟着被测试的配置走：要送去 `test` 的那份配置与它的对照在同一批 `validate` 里重放；那份配置之后改了（标签、特征、训练量或持仓规则），对照随它改过、再同批跑一次。在更早的配置或旧代码上跑过的对照，不算它的对照。
- 读一个对照的数之前，先确认它做的是名字说的事：它照常建仓与调仓（成交笔数与换手和候选同量级），与候选只差该差的那一处；读数与候选逐位相同，说明那处改动没有生效。没确认过的对照，不进结论。
- 种子基的个数在第一次复制之前定下，候选与对照用同样的种子基，挖掘器自身的种子也要换；论文每个设定跑 10 个种子，种子间的散布与方法之间的差同量级。一个差小于同一配置换种子的散布时不算发现（组合读数的散布见技能 `validation-readings`，预测层面的散布用几个挖掘种子自己量）；单个种子上的差不下结论。
- 先在预测层面比：研究年上逐日的打分与其后收益的截面秩相关，按日配对（筛选脚本 `source_refs.signal_screen_ref`）；它的统计功效远高于组合读数，也不花回放时间。组合层面的同批 `validate` 再确认。离线算出的打分要由策略包里的同一份代码、按同样的再拟合节奏与可见性得到（先在几天上与回放里的打分核对）；检验不了本臂主张的离线比较，不拿来下结论。
- 已测季度上的读数只是一个季度一次的抽样：不要按已揭示的季度挑持仓只数、池的成员或其他参数，也不要把一个季度写成实力。
- 放弃方法之前至少要有：阶段一的结果、两种以上配置在预测层面的配对比较，以及一次方法与两个对照同批的 `validate`。只比过一次就关掉，不算结论。

## 本臂的数据与账户

- 操作数：论文只用六个价量字段 Open、High、Low、Close、Vwap、Volume。本项目的日线有开高低收、成交量、成交额与复权因子：Vwap 用成交额除以成交量，价格用当时可见的复权因子做后复权；决策在开盘前，能用的最后一根日线是前一交易日的。停牌日、新股与涨跌停要在求值与排序时显式处理（`refs/references/claims.md` 的末节）。季度财务（带公告日）可以作为额外的操作数加入，但只能在忠实的价量版本之后作为扩展，单独记录。
- 20 万元账户的算术，不是持仓配额：同时持有 10、20、40 只时每只约 2 万、1 万、5,000 元，最低佣金使单边成本约 7.6、10.1、15.1 bp，往返另加卖出印花税。包不设持仓只数、单票权重、调仓频率或价格上限。论文的目标是 20 天收益，持有期与之相近时换手不高，但每次调仓的成本仍要计入。
