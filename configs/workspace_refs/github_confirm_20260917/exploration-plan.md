# 执行计划

本臂的产出不是「找到更好的策略」，是**每折给交付产物记下一次可信的前向过渡**，顺带在头两折里把两个换手/成本变体一次性问清楚。绝大多数折的正确结局是 `no_edge`，这不是弃权文化，是排程设计。

预算（以运行事实为准）：每折 24 个 Step、24 次回测、3 个空对照槽、600 分钟墙钟、1600 次 LLM 调用；单次 `fit` 独立预算 3600 秒。`smoke_backtest` 不占回测槽。

## 第 0 步（每折都做，0 回测槽）：合同复核与父本对照

顺序固定，先做完再谈变体。

1. **列合同复核。** 读本轮 `data_summary.json` 与 `unit_reference.json`，按 `pit-field-map.md` 逐表核对：`daily` 的 11 列投影（含 `is_suspended`、`up_limit`、`adj_factor`）与 `circ_mv`/`amount`；`events` 的 `moneyflow` 九列投影；`fundamentals` 的四个 `*_vip` 数据集；`universe` 的 `list_date`。**缺任何一列，机制就不能原样跑**：显式失败、`report_issue`、本折 `no_edge`，不要靠改特征把它绕过去。
2. **原样冒烟。** 对**未经改动**的父产物跑一次 `smoke_backtest`，确认两件事：跑得通；订单的 `reason` 是 `a158_lgbm_rebal` 而**不是** `fallback_ewsign_rebal`，且订单 metadata 带有 `num_leaves`/`learning_rate`/`best_iter`/`n_boosters=1`。落在退化路径上就等于 booster 没训出来，这时的任何回测成绩都不是这份机制的成绩——查清楚原因再往下走，绝不把退化结果当成读数。
3. **父本对照读数。** 读宿主已经跑好的 `parent_control` 节点：全窗 `benchmark.neutralized_excess_return`、`cost_sensitivity.excess_at_2x_slippage`、`turnover`、`trade_count`，以及 `sub_windows` **最后一行**（本折新季度，这份产物真正的样本外前向记录）与它的 `null_control`。这一条是本臂每折的头条结论，写进折记录。
4. **可选池宽度审计（首折必做，之后只在读数异常时重做）。** 在会话沙箱里按决策日统计通过 `universe()` 的名字数，并单独统计被 `is_suspended` 剔除的只数。v11 只标盘中临时停牌，v9 连复牌日一起标（审计窗 946 个置位行里 747 行是正常交易日），因此这里应当看到**被剔除的只数明显偏少、可选池偏宽**。看到的和这个方向相反，说明视图或读取路径有问题，先查清再往下。
5. **单票权重审计（首折必做）。** 从父本对照的执行记录与逐日权益里读出实际到达过的单票最大权重及其分布，写进折记录。这是 `families.md` 里「组合层上限」那一节的唯一入口条件。

第 0 步做完，本折的必交产出就已经齐了。后面的批次是可选的。

## 首折：一批问完两个变体

1. **先写后跑。** 在工作区笔记里写下 V1 与 V2 的完整 `hypothesis`：改的常量、改成什么、为什么不属于关闭清单、预期在哪个指标上体现、以及 `families.md` 里它自己那张否证表的全部条件。写完之前不许提交回测。
2. **各自冒烟。** 两个候选各跑一次 `smoke_backtest`（0 槽）。这一步不是形式：源实验有过一次真 bug（`name 'uni' is not defined`）正是被冒烟在 0 槽拦下的。冒烟不过不许进批。
3. **一次 `batch_validate`，两个候选，2 个槽。** V1（`BAND = 1.5`）与 V2（`execute_at = T15:00`）。两者与父本除各自那一处外必须逐字相同——可执行指纹要不同于父本，但差异必须只有登记的那一处。
4. **按 `families.md` 判定。** 主比较对象是父本对照，不是空对照；分位只用来确认变体的超额不是骨架挣的。
   - **都没过** → `finish_fold(outcome="no_edge", reason=...)`，保留父本。这是最可能也完全正当的结局。
   - **过了一个** → 先跑 `run_null_control`（1 槽）确认分位 ∉ [0.40, 0.60]；若是 V1，还要把 `BAND ∈ {1.25, 2.0}` 两个邻域点同批跑一次（2 槽）确认结论不在邻域里翻转。全部站住后用 `step_rollback` 把胜出节点恢复到 `output/` 再 `finish_fold`。
   - **两个都过** → 提名新季度超额更高的那个；另一个保持登记状态，可在下一折对新父本再问一次。
5. **fit 超时协议（必须遵守）。** 源实验连续两折在 `batch_validate` 并行 fit 上超时、白耗 4 个槽，两次诊断都是环境争用而非候选成本。本臂沿用它的处置：批内 fit 超时 → **先零槽 diff** 候选与父本的 fit 路径（本臂的两个变体根本不碰 fit 路径，diff 必然干净）→ 同候选改用 `daily_backtest` **串行重试**（1 槽）→ 再次超时才可按候选失败处理。**不得因 batch 超时宣告变体证伪。**

## 第二折与第三折：只在还有悬案时开批

默认是只做第 0 步然后 `no_edge`。只有当上一折留下了**一个真正的悬案**才开批，且至多一个候选、一个槽：某个变体过了大部分门、只在一条上落败，而本折的诊断把这条落败归因于那个季度而不是机制本身（典型情形是父本自己的新季度超额也为负、两边一起负）。除此之外一律不开批。

在两折里都落在自己否证表上的变体，对本臂关闭，不得再登记。

## 交付截止：末三折不再提名

一份产物的自有前向过渡数 = 它被冻结之后剩下的折数。本臂的存在理由就是这个计数，所以它必须优先于任何折内的改进：

- 设本臂共 `F` 折，当前是第 `i` 折。**只有 `F − i >= 3` 的折允许提名新产物**（新产物至少拿到 3 次自有过渡，⌈2/3⌉ 规则下需要其中 2 次为正，是一次真实检验）。
- `F − i < 3` 的折**一律不提名**，哪怕候选过了全部门。这时把它的完整读数写进折记录作为下一轮的证据，本折 `no_edge` 收折。
- 理由要写在折记录里，不要含糊：末折才首次冻结的新机制自有过渡为 0，没有任何前向证据因而不毕业；本仓库已经两次栽在这上面。用一次窗内改进换掉整份交付，是本臂唯一不能做的交易。

一个变体在允许提名的折里过了全部门就直接提名冻结——它此后每一折都被父本对照在新季度上重放一次，那才是它真正的第二次、第三次确认。**不需要**为了「赢两次」再开一批把同一个变体重跑一遍。

## 剩余各折：确认

第 0 步 → 折记录 → `no_edge`。折记录里每折至少写清：父本对照的新季度超额与其空对照分位、全窗中性化超额与 2 倍滑点读数、`turnover` 与 `trade_count`、以及和上一折读数的对比。

连续三折父本对照的新季度超额为负时，结论是这条机制衰减了：把它写进折记录、用 `report_issue` 报给运营者（源实验还在同一条谱系上搜索，它需要这个读数），然后继续按排程 `no_edge` 走完。**不要**改机制去救它，也不要退回手写因子——那两件事都不在本臂的授权范围内。

## 元学习

本臂的 PRIOR 应当短：它没有家族队列要维护。每次元学习只需要维持三件事——父本对照新季度读数的逐折序列（连同各自的空对照分位与随机组合均值，单季符号必须与均值联读）、两个变体各自的状态（未测/在测/已关闭，附落败的那一条门）、以及交付截止规则下还剩几折可提名。若创建时继承了源实验的 PRIOR，**首次元学习必须把它重写到本臂的范围**：它的累计关闭清单与机制参数归属保留，它预登记的下一轮搜索项（损失结构变体、算子族扩展、新数据面家族等）在本臂一律作废——那些是搜索臂的队列，本臂禁止执行。
