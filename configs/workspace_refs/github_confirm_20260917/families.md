# 登记变体、对照与杀死条件

本臂只有**两个**登记变体。它们都不碰分数：特征、标准化、标签、估计器、网格、切分、禁运、`TOPK`、再平衡节奏全部冻结（完整列表见 `README.md` 的旋钮表）。两个变体各自只改一个可分离组件——一个改「什么时候把一只票换掉」，一个改「订单在哪一刻成交」。

每个变体在 `hypothesis` 里必须写全：改的是哪一个常量、改成什么、为什么这不是关闭清单里的轴、预期在哪个指标上体现、以及本节列出的全部否证条件。**先写后跑。**

## 对照：父本对照就是基线

宿主每折会自动把父产物在本折验证区间上重放一次（`parent_control` 节点，不占回测槽、不计 `candidates_evaluated`）。它就是本臂的基线，也是本臂唯一必需的对照——因为「继承的产物原样不动」正是被比较的那个方案。

读它有两条口径：

- **全窗**：`benchmark.neutralized_excess_return`、`cost_sensitivity.excess_at_2x_slippage`、`turnover`、`trade_count`、`pnl_concentration`。
- **新季度**：`sub_windows` 的**最后一行**。验证区间是截至本折季度的连续四个季度，前三个季度父本在上一折已经见过；只有最后一段是它真正的样本外前向记录。本臂的核心读数就是这一行，它同时也是账本给这份产物记下的那次自有过渡。

父本对照节点**不得被 `finish_fold` 提名**。保留父本要走 `finish_fold(outcome="no_edge", ...)`。

## V1 — 名次滞后带（no-trade band）

**改什么。** `lib/trade.py` 的 `build_orders` 里，把「按分数升序取最差 `N_DROP=2` 只强制卖出」换成一条**名次滞后带**：先在通过可交易性过滤且分数有限的名字上按分数降序算截面名次（名次 1 = 最好），一只持仓只有当它的名次落到 `TOPK × BAND` 之外时才卖出。其余一律不动。

- 登记点：`BAND = 1.5`，即 `TOPK=16` 时持仓名次跌出前 24 名才卖。
- 因可交易性或分数失效触发的强制卖出（`forced`、窗外持仓 `out_of_win`）**保持原样**，它们不是自由裁量的换手。
- 买入侧**不变**：卖完之后仍然按 `TOPK − 剩余持仓数` 从榜首依次补齐，等额预算 `(cash + sell_value) × CASH_FRACTION`，100 股整手，先卖后买。
- `REBAL_EVERY = 5` 不变——本变体改的是「换不换」，不是「多久看一次」。

**为什么这不是关闭清单里的轴。** 关闭的是 `topk` 邻域（篮子大小）、3 日再平衡（节奏）、名次线性加权（仓位大小）、跨重训日集成（模型）。`N_DROP` 从来没有被检验过：源实验的 PRIOR 把它列在「手设参数」里，它的整个证据就是当初随手定的 2。V1 改的是**换名规则**，篮子大小、节奏、权重、分数四样一样没动。

**假设。** 标签持有期是 10 个交易日，再平衡是 5 个交易日——仓位在信号半程之前就被换掉了。固定换 2 只等于强制每 5 天付两次往返成本，无论分数是否真的变化。若分数的名次在带内抖动的部分主要是噪声，滞后带能在几乎不损失打分信息的前提下把换手砍掉一大块，而换手在这个账户上一年值 1.8–2.2%。

**必须报告。** 全窗 `turnover`、`trade_count`、往返笔数、平均持有天数、每次再平衡的自由裁量卖出只数分布、以及四个季度子窗各自的超额。

**否证（命中任一即本折落败）。**

| 条件 | 判据 |
| --- | --- |
| 换手没降 | `turnover` 相对父本对照下降不足 15%——机制没有做到它声称的事，收益再好也不算它的功劳 |
| 没挣到边际 | 全窗 `benchmark.neutralized_excess_return` ≤ 父本对照 |
| 新季度输了 | `sub_windows` 最后一行的超额 < 父本对照同一行 |
| 成本敏感性 | `cost_sensitivity.excess_at_2x_slippage` ≤ 父本对照，或 ≤ 0 |
| 不一致 | 四个季度子窗同号少于 3 个，或超额只来自单个季度 |
| 空对照带内 | `null_control.excess_percentile` ∈ [0.40, 0.60] |
| 退化 | 大部分决策落在 `fallback_ewsign` 路径上 |
| 邻域翻转 | 过了上面全部门之后，`BAND ∈ {1.25, 2.0}` 两个邻域点里有任何一个把结论翻过来 |

邻域只在 V1 已经过了全部门、准备提名时才跑（同批两个候选，2 个回测槽）。没过门就不必花槽位。

**已知失效模式。** 带太宽时持仓会拖着衰减的名字越过标签半程，超额被持有期错配吃掉；卖得少 → 回收现金少 → 补仓少 → 篮子逐渐板结在老名字上（用平均持有天数与篮子换新率看得出来）。带太窄时它退化成原来的规则，`turnover` 不降，直接落在第一条否证上。

## V2 — 收盘执行（15:00 对 09:30）

**改什么。** `lib/trade.py` 的 `build_orders` 里 `execute_at` 从决策日 `T09:30` 改成 `T15:00`。**一个字符串，别的一律不动**：同样的分数、同样的名单、同样的数量算法、同样的先卖后买。

**为什么只有这两个时刻。** Broker 的 `resolve_execution_price` 只解析订单请求时点上的价格，从不取整或顺延：09:30 与 15:00 是日线 OHLC 里的精确观测，直接取当日 `open` 与 `close`；其他任何时刻都必须由调用方注入静态历史分钟价格源，本轮种子 `include_intraday=false`、没有分钟视图，因此其他时刻一律以 `missing_execution_price` 拒单。所以「执行时点」这个轴上只有两个可取值，V2 就是这两个值的对照，不存在第三个候选。

**假设。** 08:30 的决策在 09:30 成交，吃的是开盘的价差与跳空；在 15:00 成交，多等了六个半小时的信号衰减，但换来收盘时段更好的流动性。这两者哪个大是一个纯经验问题，只有带真实费用、涨跌停与整手约束的完整回放能回答，任何 rank-IC 探针都表示不了它。

**必须诚实写下的结构性代价。** 订单数量是用 **T-1 收盘价**估算的（08:30 决策时点看不到当日任何价格，这是 PIT 约束，不可绕过）。09:30 成交时估价与成交价只差一个隔夜跳空；15:00 成交时还要加上一整天的日内涨跌。同一次策略调用的多个订单共享调用前的账户快照，但 Broker 按队列顺序逐单更新真实现金，策略只能用本地变量递减预算——因此成交价高于估价时，队列靠后的买单会拿到 `insufficient_cash` 拒单。**V2 在上涨日会机械地抬高买单拒单率**，这是变体自带的成本，不是实现缺陷，必须测出来而不是绕过去。涨跌停拒单的画像也会变：早盘未封板、尾盘封板的票在 09:30 成交得了、在 15:00 会以 `daily_price_limit` 拒单，反之亦然。

**必须报告。** 按 `reason` 分类的拒单计数（至少 `insufficient_cash`、`daily_price_limit`、`suspended`、`insufficient_sellable`）、意图买入笔数与成交笔数、`strategy_exit_fill_count`、`turnover`、四个季度子窗超额。

**否证（命中任一即本折落败）。**

| 条件 | 判据 |
| --- | --- |
| 没挣到边际 | 全窗 `benchmark.neutralized_excess_return` ≤ 父本对照 |
| 新季度输了 | `sub_windows` 最后一行的超额 < 父本对照同一行 |
| 成本敏感性 | `cost_sensitivity.excess_at_2x_slippage` ≤ 父本对照，或 ≤ 0 |
| 成交质量退化 | 意图买入的拒单率比父本对照高出 10 个百分点以上——即便超额更好也不可交付，因为这份书实际上没被建起来 |
| 不一致 | 四个季度子窗同号少于 3 个 |
| 空对照带内 | `null_control.excess_percentile` ∈ [0.40, 0.60] |
| 退化 | 大部分决策落在 `fallback_ewsign` 路径上 |

**空对照的读法（对 V1 同样适用）。** V1 与 V2 都改了成交骨架——更少的往返、不同的成交时刻——随机组合按各自骨架重画，所以变体的分位与父本的分位**不能直接比大小**。分位在本臂只回答一件事：这个变体的超额是不是只来自骨架本身。排序一律用父本对照。

## 组合层上限（max weight / max holdings）：不登记

任务书允许在「源实验的 PRIOR 没有把它关掉」的前提下把组合层上限作为第三个变体。逐条核对下来，它不成立：

- **持仓只数上限**在这份机制里就是 `TOPK`。源实验的 PRIOR 明写「topk：16 冻结、不再探邻域」，并把 `topk 邻域` 列进累计关闭清单。以「上限」为名改 `TOPK` 就是重开一个已关闭的轴。
- **单票权重上限**没有被逐字关闭，但在这份机制里几乎是空操作：建仓时 16 只等额、可投预算 `CASH_FRACTION = 0.97`，每只入场权重约 6.1%，任何高于入场权重的上限只可能被两次再平衡之间（至多 5 个交易日）的漂移触发。宿主侧的 `max_single_name_weight` 还是按**期初权益**折算的固定金额、由 Broker 以 `single_name_weight_cap` 拒单，它是实验创建时定死的参数，不是策略可以在折内检验的组件。
- 仓位大小这个轴上真正被试过的形态（名次线性加权）已经在关闭清单里。

所以本臂**只登记 V1 与 V2**。作为替代，首折要做一次**零回测槽的审计**：从父本对照的执行记录与逐日权益里读出这份书实际到达过的单票最大权重及其分布，写进折记录。只有当审计显示有名字在 ≥ 5% 的决策日上超过 9% 权益时，「单票权重上限」才具备成为一个真实约束的证据，才可以在后续折里作为**第三个变体单独预登记**（形态只能是上限，绝不能顺带改 `TOPK`）。审计没到这个门槛就明确记录「不构成约束、本臂关闭该轴」，不再重提。

## 臂级规则

- **每折最多同批两个变体。** 首折 V1 与 V2 同批；此后只在某个变体已经赢过一次时才重跑它，另一个位置留空（见 `exploration-plan.md`）。
- **两折连败即关闭。** 某个变体在连续两折都落在它自己的否证表上，该变体对本臂关闭，不得再登记；两个变体都关闭后，本臂在剩余折里只做父本对照复核与 `no_edge` 收折——那仍然在给交付产物累积自有过渡，是有价值的产出。
- **机制衰减的诚实出口。** 父本对照的新季度超额连续三折为负时，结论是这条机制衰减了，不是本臂该换个变体再试。此时把结论写进折记录并用 `report_issue` 报给运营者（源实验还在同一条谱系上搜索，它需要这个读数），本臂继续 `no_edge` 走完排程，不得改写机制去救它。
- **不得为了凑一次冻结而提名。** 提名标准就是上面的门，一条都不放宽。`no_update` 在本臂是正常输出。
