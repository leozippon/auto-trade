# 机制确认与可交付性参考包（github_confirm，20260917）

本目录是只读 refs。本臂**不找新 alpha**，它只回答一个问题：把已经有正向前向证据的那条机制**原样冻住**，只管换手与执行成本，能不能在后续每个新季度上继续站住，并且交出一份**带有它自己前向过渡记录**的产物。

父产物不是空白模板：实验创建时以 `inherit_from` 把源实验最新冻结 Fold 的 `output/` 与 `models/` 整棵拷成只读快照，首个 Fold 的父本就是它。所以「机制」不需要在这里重新实现——它已经在你的 `output/` 里，连同它自己 25 KB 的 `README.md` 与 11 个 `lib/` 模块。本包只负责三件事：说清哪些东西被冻住、允许登记哪两个变体、以及第一折必须先验证什么。

按以下顺序读：

1. 本文：机制摘要、旋钮表、被冻结的边界、数据合同变更。
2. `families.md`：两个登记变体（V1 无交易带、V2 收盘执行）的完整定义、阈值与杀死条件；父本对照的读法；组合层上限为什么**不**登记。
3. `pit-field-map.md`：机制真正读到的那几张表的可见时点、单位与去重规则。
4. `exploration-plan.md`：首折的动作顺序（先读父本对照 → 一批跑两个变体 → 判定），以及后续折的收敛规则。
5. `sources.md`：证据来源、源实验的累计关闭清单原文、以及本包引用的运行教训。
6. `starter/README.md`：本包**没有** starter，原因写在那里。

## 为什么这条线值得确认

源实验是一条搜索臂：它在特征空间里一路搜，八折冻了五次。它父本对照的**新季度** `step_result`（每折验证窗只有最后一个季度是上一折之后新出现的，那一段才是父策略真正的样本外）序列是 `+0.37% / +7.39% / +3.43% / +4.49% / −4.62% / −6.60% / +6.61%`——七个真新季里五个为正，最近一个的空对照分位 0.96。这是本仓库唯一一条有前向正证据的谱系。

但搜索臂交付的产物有一个结构性问题：毕业裁决的（c）项要求**被评的这份产物自己**至少有 `confirmation_folds` 个前向过渡，且这些自有过渡还要单独满足 ⌈2/3⌉ 正超额。末个 Fold 才首次冻结的新机制自有过渡为 0，靠祖先的链条成绩不算数。本仓库已经两次栽在这上面。搜索臂随时可能在末折换掉产物；本臂把机制冻住，产物在每一折都以父本对照的身份被重放一次，因此交付时它的自有过渡等于折数减一——按构造满足（c）的计数，成绩则由它自己挣。

这也让两条臂的探索空间不重叠：源臂继续搜特征，本臂一列特征都不许动。两者合起来才是「继续搜」对「冻住机制、管换手与成本」的受控比较。

## 继承的机制（摘要）

一句话：**158 个 Alpha 算子 + 6 列成长/预告 PIT + 8 列资金流 PIT + 1 列上市年龄 PIT = 173 列**，截面 RobustZScore 后喂给一个**季度重训的单 booster LightGBM 截面回归排序器**，每 5 个交易日按分数换掉最差的 2 只、补齐到 16 只等额持仓，决策日 09:30 成交。

- 特征（顺序严格 158 → 6 → 8 → 1，三处名称表同序）：`lib/features.py` 的 158 列（9 根 K 线形态 + 4 个位置列 + 29 个算子 × 5 个窗 {5,10,20,30,60}）；`lib/vipf2.py` 的 `or_yoy / netprofit_yoy / dt_netprofit_yoy / op_yoy / fc_dir / fc_exp_rev`；`lib/mfflow.py` 的 `mf_amt_5 / mf_amt_20 / mf_pos20 / mf_trend520 / mf_vola5_20 / mf_elg_net5 / mf_lg_net20 / mf_amtturn20`；`lib/newage.py` 的 `age = log1p(决策日 − 上市日，日历天)`。
- 标准化：`features.robust_zscore`，逐截面 `(x − median) / (1.4826 × MAD)`，截断 ±3，缺失置 0；fit 与决策**同一个函数**。
- 标签：`h = 10` 个交易日的开盘到开盘复权收益 `O[s+11]/O[s+1] − 1`，只保留推断时已完全实现的行，逐截面 `pct_rank − 0.5`。
- 训练：全部在 `fit(context)` 内。4 点预注册网格 `num_leaves {31,63} × learning_rate {0.05,0.1}`，其余超参固定；训练/验证切分 = 可见窗最后 60 个决策 bar 作验证、训练段止于验证起点前 10 个 bar（禁运长度 = 标签持有期）；600 轮、早停 50、最小验证 L2 的 5% 高原内按 `(num_leaves, learning_rate)` 字典序选点。booster 以 `model_to_string()` 存进 `context.state_dir`，`generate_orders` 每次重建。
- 退化：任何 fit/score 失败置 `ens_bad` 旗，`generate_orders` 退到等权符号打分并把 `reason` 写成 `fallback_ewsign_rebal`。**显式退化，不静默**。
- 可交易性过滤（全部按 T-1 截面）：未停牌、开收盘价有限为正、`ADV20 ≥ 3000 万元`、收盘 ≤ 40 元、T-1 未涨停、板块白名单（沪主板 600/601/603/605、深主板 000/001/002/003、创业板 300/301；科创与北交所在外）、窗内 ≥ 60 根可见 bar。日线域没有 ST 列，因此**没有 ST 过滤**，这是已接受限制。

**唯一一处必须改的常量：`lib/data.py` 的 `DECISION_LOOKBACK_DAYS`。** 注释写着「100 日历天 ≥ 63 个交易日」，但这不成立：上交所日历在 2011–2026 年上任意 100 个日历日里的交易日数**最少只有 59** （2024-05-06 与 2024-05-13 两个决策日），而 `lib/features.py` 的 `_win(a, 60)` 需要 60 根。这次读取在打分器的 try/except 之外，因此不会退化成 `fallback_ewsign`，而是整个决策直接失败——源实验的 fold-10 父本对照就是在这一天上挂掉的；它的工作副本已改成 130，但**所有冻结产物仍然读 100**，本臂继承到的就是 100。

因此首折必须把它**一次性提到 `130`**：保证 60 根的最小值是 101，取 130 留出约 79 根的余量，让基于 shift 的 60 日算子远离全 NaN。这是本臂唯一被授权的机制改动，改完即冻结，此后不得再动。

副作用要在首折记录：窗口变长会让 `W["n_bars"]` 变大，一批很新的上市票因此越过 `MIN_BARS = 60` 进入可选池，池子会再宽一点点——和 `is_suspended` 的 v11 变更叠在同一折里，两者都要分别记数，不要混成一个读数。若继承到的副本已经读 130，则本臂不做任何改动，只在首折验证并记录这一事实。

`num_threads=8` 是必须保留的：沙箱报出的逻辑 CPU 数远多于实际可用核，LightGBM 的自动线程数会过订阅并造成病态慢。

## 本臂的第一个问题：v9 视图 → v11 视图

继承来的这份代码是在**快照缓存格式 v9** 的 PIT 视图上写成并验证的；本臂跑在 **v11** 上。两版之间只有两处内容变更，其中只有一处碰到这份代码真正读的列：

- **v11：`daily.is_suspended` 只标 `suspend_d` 的停牌行（`suspend_type="S"`）**。v10 及更早把复牌行（`"R"`）也一并置位，而复牌日是正常交易日。审计窗里 946 个置位行中有 747 行是正常交易的复牌日。`lib/trade.py` 的 `universe()` 用 `~W["suspended"][:, -1]` 做第一道过滤，因此在 v9 上它**误剔除了大量正常可交易的名字**，在 v11 上这些名字回到可选池。可选池变宽 → 打分截面变宽 → top16 的成分可能变。这不是 bug 修复带来的「更好」，它就是一个**不同的可选池**，机制在它上面的表现必须重新读。
- **v10：当日发布的宏观日频表改用收盘合同盖章（`contract_1730_from:<日期列>`），因此比 v9 早一个交易日可用。** 这份机制**一列宏观都不读**（源实验已判定宏观在本架构下实际关闭），所以这条对它没有影响。不要为此写任何适配。

因此第一折的第一件事不是跑变体，而是确认这份代码在 v11 上**原样跑得动、并且没有掉进 `fallback_ewsign`**。跑不动就显式失败并如实上报，不允许悄悄退化成等权符号打分再把结果当成机制的成绩。具体动作见 `exploration-plan.md` 第 0 步。

## 本轮几何与账户

开发窗按季度步进：每折的验证区间是截至本折季度的连续四个季度，相邻两折只差一个季度，因此**只有最后一个季度是父本没见过的新数据段**，父本对照也只在这一段上真正是样本外——比较父本与候选时按这个口径读 `sub_windows` 的最后一行。没有 Test 阶段，相邻两折之间跑一次元学习。

本臂的首折被刻意排在**继承产物的冻结折之后一个季度**，使每一折的新季度对这份产物都是真样本外。创建时的几何由轮次脚本按下面的规则算，不写死：设源实验账本上最后一条已完成 `fold` 记录的季度标签为 `Q`（`inherit_from` 拷的就是这条记录的产物），则本臂首折 = `Q + 1` 个季度，于是 `development_first_period = Q − (validation_periods − 2)`；`validation_periods = 4` 时即 `Q` 往前推两个季度。写包时 `Q = 2024Q3`，对应 `development_first_period = 2024Q1`、首折 `fold_2024Q4`、末折 `fold_2026Q1`，共 6 折 5 个自有过渡。**源实验仍在推进**，创建时必须重算；若重算后剩余折数少于 4（自有过渡少于 3），本臂已经不能服务它的目的，轮次脚本应当拒绝创建并如实报告，而不是造一条只有一两折的臂。

账户是 10 万元真实资金：佣金万一、最低 5 元/笔，过户费 0.1 bp，卖出印花税按成交日切换，方向滑点 5 bp。父本的书是 16 只等额、每 5 个交易日换 2 只 ≈ 每年 96 次换名 ≈ 600% 年换手；单只约 5,900 元时最低佣金一项就是 8.5 bp/边，一年成本拖累约 1.8–2.2%。冻结件在各折全窗测得的中性化超额跨折落在 +4.6% 与 +20.0% 之间（窗不同、不可直接比），所以这个成本是边际里**很大的一块**——V1 的存在正是为了检验能不能砍掉三分之一而不丢超额。

## 「没有边际」的读法，以及 `no_update` 是正当结果

本臂的主比较对象**永远是父本对照**（宿主每折自动跑好的那个节点，0 回测槽），不是空对照。变体改了成交骨架（更少的往返、不同的成交时刻），空对照的随机组合按各自骨架重画，父本与变体的分位**不能直接比大小**——分位在本臂只用来确认变体自己「不是靠骨架挣的」，不用来排序。

一个变体只有同时满足下面三条才允许提名：

- `benchmark.neutralized_excess_return` 严格高于父本对照的同名读数，且为正；
- 验证窗**最后一个子窗**（新季度）的超额不低于父本对照在同一段上的读数；
- `cost_sensitivity.excess_at_2x_slippage` 严格高于父本对照的同名读数，且为正。

外加它自己的家族判据（见 `families.md`）与交付硬门：`run_null_control` 分位 ∉ [0.40, 0.60]、非退化（大部分决策不在 `fallback_ewsign` 路径上）、四个季度子窗同号至少 3 个。

**两个变体都没过 → `finish_fold(outcome="no_edge", reason=...)`，保留父本。** 这在本臂是正当且常见的结果，不是失败：产物不被替换，这一折照样给它记下一次自有前向过渡。为了凑一次冻结而提名一个没过全部门的变体，是本臂唯一不可接受的行为。

## 硬合同

- 正式策略写在 `output/` 包内：入口固定为 `output/main.py` 的 `generate_orders(context)`，返回严格 JSON 订单数组；辅助模块放在 `output/` 下并用绝对导入；文件数与总字节数有上限（以运行事实为准）。
- 正式 import 只允许纯计算标准库、`numpy`、`pandas`、`scipy`、`sklearn`、`lightgbm`、`xgboost`、`statsmodels`、`torch` 及其子模块，以及 `output/` 内自己的模块。`gpu_count=0`，策略容器没有 GPU。注意继承来的 `lib/trade.py` 的板块白名单是纯 Python 实现的，因为 `re` 不在白名单里——改动它时不要引入正则。
- 拟合全部在 `fit(context)`（`REFIT_PERIOD="quarter"`，单次 fit 预算 `budgets.strategy_fit_timeout_seconds`，本轮 3600 秒），结果写 `context.state_dir`；`generate_orders` 只读它。`models/` 以只读 `context.models_dir` 挂载。
- 每一行输入必须 `available_at <= context.inference_at`。判可见只看 `available_at`，逐表边界见 `pit-field-map.md`。
- 不要把 refs 拷进 `output`；不要写死路径与股票代码。候选的可执行指纹必须不同于父策略——一个字节都不改的「候选」不是候选，父本对照已经覆盖它。
- Broker 负责 T+1、费用、涨跌停与成交；策略只发订单意图。`execute_at` 不能早于本次 `inference_at`。

## 禁止

- **改特征**：加列、删列、换构造、换数据源、改标准化，一律禁止。173 列是冻结的。
- **改模型**：换估计器、换损失（含 lambdarank）、改网格、改固定超参、改槽位数、改训练/验证切分或禁运，一律禁止。
- **改标签**：`h`、开盘到开盘口径、截面 rank 目标，一律禁止。
- **重开源实验的关闭清单**：清单原文见 `sources.md`，其中与本臂最近的是跨重训日集成、名次线性加权、3 日再平衡、`topk` 邻域、特征中性化、macro 状态条件化门控。它们不得以「改进」的名义重测。
- **登记 V1/V2 之外的第三个变体**（组合层上限为什么不算例外，见 `families.md`）。
- 手写价值/反转/动量/低波打分：本臂连作对照都不需要，父本对照已经是基线。
