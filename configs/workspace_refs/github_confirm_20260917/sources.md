# 证据、关闭清单与运行教训

## 这条机制的前向证据

源实验八折冻了五次。真正算数的不是全窗成绩，而是父本对照的**新季度** `step_result`：每折验证区间是截至本折季度的连续四个季度，前三个季度父策略在上一折已经见过，只有最后一段是它的样本外前向记录。按折序排下来的七个真新季读数（超额 / 空对照分位）：

`+0.37% (0.26) → +7.39% (0.79) → +3.43% (0.87) → +4.49% (0.24) → −4.62% (0.76) → −6.60% (0.72) → +6.61% (0.96)`

七正五。两个负读数值得单独记住：它们所在的季度**随机组合的均值本身就是负的**（−7.32% 与 −8.74%），两次实测都高于随机均值。源实验按预登记规则对绝对符号照样降级处理，没有拿「跑赢随机均值」当边际——本臂读单季符号时沿用这条纪律：**符号必须与 `null_control` 的随机均值和分位联读**，高换手的随机组合本身就能产出正或负的超额，「观测值高于随机均值」不是边际的充分条件。

冻结件（该折没有冻结时为当折父本）的全窗中性化超额跨折是 `+20.0 → +10.1 → −2.2 → +10.1 → +4.6 → +5.8 → +16.8 → +12.3`（窗不同、不可直接比）。最近一次冻结的读数：全窗超额 +13.25%、中性化 +12.27%、空对照分位 0.994（k=500，均值 −6.83%、p95 +6.81%）、`beats_parent` 为真（Δneu +5.53pp）、2 倍滑点下 +12.42%（盈亏平衡滑点 +79.7 bps）、单名贡献 9.25%、`turnover` 16.61、最大回撤 21.31%、261 单 121 笔、去偏 Sharpe 概率 0.802（trials=2）。

**去偏 Sharpe 概率要连同试验数一起读**：两三次试验时「去膨胀」几乎是空操作。本臂每折的候选数本来就少（首折 2 个），这个概率不构成独立证据。

资金流那一腿另有一份独立佐证：在一份把动量、换手、波动、彩票项与短期反转都放进控制集的截面研究里，供应商日频净流入的失衡度是该研究里最强的多头腿之一（20 日 +0.366%，t +3.01，五年里四年为正），并且扛住了它施加的全部控制。这条不是本臂的检验对象，只是说明 `mfflow` 那 8 列不是噪声。

## 源实验的累计关闭清单（原文，不得当改进重测）

以下逐字取自源实验最近一代 PRIOR 的「累计关闭清单」：

> 累计关闭清单（不得当改进重测）：上份清单全部保留（标签口径、特征中性化、C2/C3/D、WQ101、GTJA191、名次线性加权、3 日再平衡、k 槽位邻域、mf_single、旧谱系、vipF1 质量轴、筹码 A1/A2、topk 邻域、cyq_perf 两变体、macro 状态条件化门控、topk12+mf 归因、macro_const 风格效应、龙虎榜注意力排除/跟随稀疏编码、公告注意力计数类、kpl_list 题材榜、vipF2-topk12 窗内重冻结）新增：fr_ratio 流通占比水平、unlock_up60/unlock_d60 解禁占比、解禁抛压排除、vipF2 fc_dir/fc_exp_rev 主路径资格

两条与本臂距离最近的补充裁决，也逐字保留：

> topk：16 冻结、不再探邻域；候选需改 topk 时以独立组件预登记并附自身邻域与选点规则（高原/断崖判读）、尖峰点不满足交付条件。

> k 机制：维持关闭（F3 k 邻域证伪+F4 全窗 k1≥k3）

这些条目在源实验里是「重入需附差异声明」的条件式关闭。**在本臂它们是无条件关闭**：本臂根本不做特征与模型方向的探索，没有任何形态的重入是被授权的。

清单里唯一与本臂有交集的是 `名次线性加权` 与 `3 日再平衡` 与 `topk 邻域`——它们分别锁死了仓位权重、再平衡节奏和篮子大小。`N_DROP`（换名规则）与 `execute_at`（成交时刻）不在清单里，也从未被检验过：源实验的 PRIOR 把 `n_drop=2` 与 `5 日再平衡` 一起列在「手设（附理由）」参数里，`execute_at` 连提都没提过。这就是本臂只有两个变体的全部理由。

## 一个从未被处理的机制张力

标签持有期是 10 个交易日，再平衡是 5 个交易日：仓位在信号半程之前就被换掉。这是一个正当的设计选择（预测更长的横截面，交易更频繁以保持时效），但源实验的 PRIOR 与 skills 里都找不到对它的论证或消融。V1 正好落在这个张力上——如果换手的一半是噪声驱动的，滞后带既省成本又让持有期更贴近标签口径。**但这只是动机，不是结论**：V1 的判定全部按 `families.md` 的否证表走，不许拿这条张力当证据。

## 本臂设计所依据的规则出处

- **产物继承**：`inherit_from` 在创建时把源实验**最后一条已完成 Fold 记录**的冻结 `output/` 与 `models/` 拷进 `artifacts/strategy/_inherited/` 并锁只读；worker 使用前复核它仍只读且完整，源实验之后被删改都不影响本实验。恢复实验时不再读这颗种子。——`docs/pipeline-design.md` §3.1
- **自有过渡**：毕业裁决（c）项要求被评产物自己至少有 `confirmation_folds` 个前向过渡（默认排程下按各折 `parent_control.parent_strategy_artifact_id` 计数），且这些自有过渡单独还要满足 ⌈2/3⌉ 正超额；末折才首次冻结的新机制自有过渡为 0，不毕业。——`docs/pipeline-design.md` §3.3
- **成交时点**：`resolve_execution_price` 只解析订单请求时点上的价格，09:30 与 15:00 直接取当日 `open` 与 `close`；其他时刻必须注入静态历史分钟价格源，未注入时一律 `missing_execution_price` 拒单。本轮种子没有分钟视图。——`docs/environment-design.md` §3.3–3.4
- **Broker 约束**：T+1、整手、双边佣金最低费用、卖出印花税按成交日切换、方向滑点；滑点后成交价触及涨跌停以 `daily_price_limit` 拒单；现金不足、可卖不足、停牌、缺涨跌停均明确拒单；同一次调用的多个订单共享调用前账户快照，但 Broker 按队列顺序逐单更新真实现金。——`docs/environment-design.md` §3.4
- **`is_suspended` 语义与 v11 修正**：该标志只标 `suspend_d` 的停牌行；全日停牌当天没有日线行，因此有日线的置位只能是盘中临时停牌。复牌行此前被一并标记（审计窗 946 个置位行中 747 行是正常交易的复牌日），已随快照缓存格式 v11 修正，v10 及更早的视图一律拒绝复用。——`docs/data-documentation.md` §1.3 与 §4
- **宏观收盘盖章**：当日发布的宏观日频表在快照构建时按 `contract_1730_from:<日期列>` 改为数据日 17:30，因此比更早的格式早一个交易日可用。本机制不读宏观，此项对它无影响。——`docs/data-documentation.md` §3.3
- **单位**：`daily` 已归一化（`vol` 手 ×100 → 股，`amount` 千元 ×1000 → 元，`circ_mv` 万元 ×10000 → 元）；`events.moneyflow` 的 `*_amount` 保留源单位万元。——`unit_reference.json` / `src/autotrade/environment/data/unit_rules.py`

## 运行教训

跨实验的运行教训不重复写在参考包里：默认挂载的运行记忆在工作区 `memory/<来源>/` 下只读可读，索引见 `inputs/skills_index.json`。与本臂直接相关的四条：

- **`fit-state-pitfalls`**：booster 跨容器持久化与静默退化的指纹诊断。本臂第 0 步的「原样冒烟」就是它的应用——`fallback_ewsign` 是一条会安静吞掉整份机制的路径，必须按订单 `reason` 显式确认。
- **`panel-semantics-parity`**：可见性语义必须单一事实源。继承的三个 PIT 特征模块都是决策路径与 fit 路径共用同一个 `_evaluate` 构造器，改动 `build_orders` 时不要在别处复制一份可见性判断。
- **`grid-plateau-selection`**：5% 高原内按字典序选点的读法。本臂不改网格，但读父本 metadata 里的选点时按这条理解。
- **`shell-argv-usage`**：shell 的 argv 恒为字符串数组。源实验主层与子层合计犯过 10 次同形错误，是它单一最大的工具失败来源。

另外一条来自源实验、直接适用于本臂的运营协议：**批内 `fit` 超时不等于候选证伪**。源实验连续两折在 `batch_validate` 并行 fit 上超时、白耗 4 个回测槽，两次零槽 diff 都显示候选 fit 路径与父本一致（成本相当），改用串行 `daily_backtest` 重试后双双成功，判定为批并行回放争用。本臂的两个变体根本不碰 fit 路径，因此这条协议必然适用：先零槽 diff，再串行重试，再次超时才可按候选失败处理。
