# TabM 参数高效集成的复现、移植与评估·20 万元账户（tabm_200k，20261121）

本目录是参考包，会话里在 `refs/`：每次尝试开头从签入的版本与核对过摘要的论文载荷重新复制，可写，改动不保留。包里没有起步策略。

## 方向

所有者要求从近三年 ICLR、ICML、NeurIPS 的论文里挑出可能用于金融市场的方法，让会话复现、微调，再判断它能不能产生赚钱的策略（原话在 `refs/references/proposal.md`）。本臂的论文是 TabM: Advancing Tabular Deep Learning with Parameter-Efficient Ensembling（ICLR 2025）。它的主张：一个普通 MLP 同时表示 k = 32 个共享大部分权重、一起训练的子模型，推理时把它们的预测平均，就成为稳定而强的表格模型；关键部件是这种参数高效集成（BatchEnsemble 式的共享权重加每个子模型各自的缩放与偏置），在 46 个公开数据集上平均名次 2.8（带分段线性嵌入的 TabM†_mini 为 1.7），好于 XGBoost、LightGBM、CatBoost 的 3.2–3.4；在 8 个按时间划分的工业数据集上，与最好的树互有胜负。论文的设定、报告的数字与我们的数据之间的差别在 `refs/references/claims.md`。

问的是：这个方法在本项目按时点可见的 A 股数据与决策节奏上，比同样输入的强基线多出什么；多出的部分是不是来自它的参数高效集成。

## 三个阶段

1. 复现。在论文自己的设定上复现它的一个主要结果：在 Adult 上用作者的 `tabm` 包训练 TabM、普通 MLP 与 TabM_packed，超参取 `repo/paper/exp/<mlp|tabm|tabm-packed>/adult/0-evaluation/0.toml`，划分与预处理按 `claims.md` 第 3、4 节重建（`adult.data` 随机分成训练与验证，`adult.test` 作测试），每个模型至少 5 个种子。目标：TabM 的测试准确率均值落在论文 0.8575 的 ±0.003 之内，MLP 落在 0.8540 的 ±0.003 之内，且按种子配对 TabM 高于 MLP（论文的差是 0.0035）；TabM_packed 的参照是仓库结果文件里的 0.8580。可选：带分段线性嵌入的 TabM†_mini（论文 0.8700）与同一划分上的 LightGBM（论文 0.8713）。`repo/` 放在 `PYTHONPATH` 上即可导入 `tabm`；rtdl_num_embeddings 用 `pip install --no-index --no-deps --target <工作区目录>` 从 `refs/wheels/` 装。`paper/bin` 依赖镜像里没有的包，不必用，照 `repo/example.ipynb`（JSON，可当文本读）写训练循环即可。达不到目标时写下差多少、可能的原因，再进入下一阶段；复现失败不等于方法无效，也不是停止的理由。
2. 移植与微调。把方法移进策略包：只用合同允许的库重写（`tabm` 与 rtdl_num_embeddings 都不能被策略导入，要重写的几块见 `claims.md` 第 5 节），先在 Adult 上确认重写的版本与作者的包读数一致（差在种子散布之内），再接到 A 股上；在 `fit` 里只用当时可见的数据训练，按会话选定的再拟合节奏更新。超参与结构可以为 A 股调整，每个改动在记录里写一行理由；预计要改的几处（按日截面归一化、标签与损失、批次构成、验证段与标签重叠）见 `claims.md` 第 7 节。无论怎样改，k 个子模型都各自算损失再平均，推理时才平均预测。先用冒烟量出一次拟合的时间与显存峰值，对照 `fit` 的时限；规模（宽度、深度、k、训练轮数）按这两个余量往上试，不按回放快慢，试过的规模要跑完并记下读数，中途停掉的不算试过。
3. 评估。按下一节的对照读结论。

## 所有者的要求

本臂被测试（`test`）的候选必须以论文方法为主要打分：TabM 的输出决定排序，不是在别的打分上加一个小幅倾斜。树排序器、去掉集成机制的版本与其他基线是对照，在 `validate` 里与候选同批验证，不测。方法读得比对照差时，照样测最好的 TabM 版本，并在记录里写明差距：这正是本臂要的答案。本臂做完，是记录里的结论有下一节的读数撑着，不是验证期的步测完了：测完最后一步会话就结束，记录之后不能再补。两次 `test` 之间的研究用来推进阶段二与阶段三（新的方法版本、补上的对照与种子），不要在预算还剩大半时把同一个候选连着测完。

## 让结果读得出来的对照

- 关键部件有没有用：对着同一管线、只去掉集成机制的版本读，即 k = 1 的同一网络（就是普通 MLP），深度、宽度、输入与嵌入、标签、损失、批次、早停规则与最多训练轮数都相同，更新节奏相同；学习率从同一个小网格里各自选（论文附录 A.3）。还要对着 k 个独立训练的 MLP 取平均读（TabM_packed，一次训练完，输入、标签、损失与训练量相同）：k = 1 的版本只回答集成有没有用，这一个才分开「多个预测取平均」与「共享权重、一起训练」各贡献多少。
- 方法有没有用：对着同样输入、同样标签与同样持仓规则的 LightGBM 排序器读。
- 对照跟着被测试的配置走：要送去 `test` 的那份配置与它的对照在同一批 `validate` 里重放；那份配置之后改了（标签、特征、训练量或持仓规则），对照随它改过、再同批跑一次。在更早的配置或旧代码上跑过的对照，不算它的对照。
- 读一个对照的数之前，先确认它做的是名字说的事：它照常建仓与调仓（成交笔数与换手和候选同量级），与候选只差该差的那一处；读数与候选逐位相同，说明那处改动没有生效。没确认过的对照，不进结论。
- 种子基的个数在第一次复制之前定下，候选与对照用同样的种子基。一个差小于同一配置换种子的散布时不算发现（组合读数的散布见技能 `validation-readings`，预测层面的散布用几个训练种子自己量）；单个种子上的差不下结论，单次训练的差别可能只是初始化。
- 先在预测层面比：研究年上逐日的打分与其后收益的截面秩相关，按日配对（筛选脚本 `source_refs.signal_screen_ref`）；它的统计功效远高于组合读数，也不花回放时间。组合层面的同批 `validate` 再确认。离线算出的打分要由策略包里的同一份代码、按同样的再拟合节奏与可见性得到（先在几天上与回放里的打分核对）；检验不了本臂主张的离线比较，不拿来下结论。
- 已测季度上的读数只是一个季度一次的抽样：不要按已揭示的季度挑持仓只数或其他参数，也不要把一个季度写成实力。
- 放弃方法之前至少要有：阶段一的结果、两种以上配置在预测层面的配对比较，以及一次方法与两个对照同批的 `validate`。只比过一次就关掉，不算结论。

## 本臂的数据与账户

- 本臂用日线价量与带公告日期的季度财务。公告标题也在种子里，但本臂不需要；要用时，D 日的标题最早用于 D+2 起第一个交易日的决策。
- 以某日打分为起点、期限 h 个交易日的标签，要等期限末那天的价格进入决策的视图之后才能用来训练；相邻 h 天的标签互相重叠，所以早停用的验证段与训练段之间至少空出 h 个交易日。
- 20 万元账户的算术，不是持仓配额：同时持有 10、20、40 只时每只约 2 万、1 万、5,000 元，最低佣金使单边成本约 7.6、10.1、15.1 bp，往返另加卖出印花税。包不设持仓只数、单票权重、调仓频率或价格上限。
