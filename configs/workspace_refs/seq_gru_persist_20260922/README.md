# 持久化序列排序器参考包（seq_gru_persist，20260922）

本目录是只读 refs。本包登记的是**一个在沪深 300 成分内训练、带残差标签、跨决策持久化并增量热启动的日频序列排序器**，以及它必须同批携带的 LightGBM 对照。它不是可提交策略，也不是预期收益。

**先把最重要的一件事写在前面：这个家族上一次跑过，并且死得很难看。** `gru_ranker` 臂在共享前推窗上读 −13.2 %/年、信息比率 −1.31，按现在生效的零技能面板重算，主动信息比率 **−2.44**，是记录在案五本冻结书里最差的一本。本包不是重开那条臂，而是**在它失败的四个地方各改一处，并把「它是不是只是树模型的一个弱化版本」这件事做成进回放之前的硬门**。哪四处、为什么每一处都重要，写在 `families.md` 的差异表里；这张表是本臂存在的全部理由，第一轮预登记必须逐行引用它。

按以下顺序读：

1. `families.md`：主候选 `g1`、必跑对照 `c_lgbm`、登记变体 `g1r`、与上一条 GRU 臂的逐条差异、增量信息门、允许的变体轴、提名条件与臂级终止规则（**唯一权威表述**）。
2. `pit-field-map.md`：逐表可见时点、单位、成分截面读法与陷阱（唯一权威表述）。本轮新增的四类日频列与被排除的集合竞价面也只写在这里。
3. `exploration-plan.md`：不占预算的普查、**全离线的增量信息门 G-INC**、首轮批次、判定分支与预算。
4. `references/`：四份技术笔记——零技能面板、账户算术、成分面、学习型候选的 `fit` 成本纪律与持久化口径。沙箱无网络，四份都是自写的，外部出处列在 `sources.md`。
5. `sources.md`：读数出处、本包在沙箱镜像里实测到的 `fit` 与推断成本、诚实的限制。
6. `starter/`：合同内的最小可运行包，**就是**三个候选本身，`main.py` 的候选常量在 `g1` / `c_lgbm` / `g1r` 之间切换，三者除这一行外逐字相同。它通过 `validate_strategy_package`，并在沙箱镜像里按正式容器边界跑通了「读取 → 训练 → 打分 → 出单 → 热启动重训」（读数见 `sources.md`）；正式回放的第一步仍然是 `smoke_backtest`。**会话开始时 `output/` 就是这份代码**，`refs/starter/` 只是同一份的只读参考副本。

## 机制，以及它这一次凭什么不同

信息源是**日频序列本身**：复权开高低收与成交均价、拆分一致的成交量、换手率与自由流通换手率、量比、涨跌停触板标记、融资余额与融资净买入对流通市值的比，共 14 条通道的 60 日窗口。A 股短周期的可预测性主要来自散户主导下的过度反应与流动性溢价——反转、换手、波动、成交量形态与**交易约束**（触板、两融准入）叠加在一起，而不是任何单一因子。手写算子（Alpha158）把其中一部分压成固定算子再交给树模型；序列模型直接从原始序列里学形态，用截面 IC 损失只学「同一天谁比谁好」，不学市场方向。

上一条臂把这套东西放在**全市场 30 元以下的池子**里、配**原始收益秩标签**、每季度**冷启动**重训，并且在方向研究已经量出「它输给同门的 LightGBM、两者日度秩相关 0.74」之后仍然开跑。本包把这四件事全部换掉（`families.md` 差异表），其中两件是本仓库从未做过的：

- **标签是残差的。** 未来 10 日开盘到开盘收益，减去该名字自己的滚动 β 乘以同两个开盘之间的沪深 300 收益。原始标签在一个基准相对的股票池里教模型去买 β，而 β 正是前推窗里把这条线打死的那次规模/风格反转。
- **模型是持久的。** `fit` 把每个种子的权重写进 `context.state_dir`，下一次季度重训**读回来接着训**（低学习率、少轮次），而不是从随机初始化重来；每四次重训冷启动一次，防止一条链跑穿整段回放。本仓库 28 个抽样冻结产物里 `models/` 全是空的，**每一次 fit 都是冷启动**——这条线从来没有人走过。

为什么它可能在漂移下留住边际（推断，不是证据）：学到的是逐日截面上的相对形态，热启动让模型把第一个研究年学到的东西带进最后一个研究年，而不是每季度用三年数据重新发现一遍；三个固定种子取平均压住种子噪声。反面同样要写清：价量信息与树模型高度重叠，卖方同类 GRU 因子自 2023 年起超额明显衰减，2024 年 2 月的小盘踩踏正是这类信号的拥挤风险，而**本包自己的起步包在实测里早停得很早**（`sources.md`）。

## 你被评的是主动序列

每次正式验证结束后，**宿主**按候选自己的成交骨架随机换名重放若干份，取日收益等权均值作为**零技能面板**，再在「候选减面板」的主动序列上算全部统计量。**包不设零技能对照腿，也不设信息比率或去膨胀 Sharpe 的门**——这些是流水线的，写在运行事实里。由此推出的读法与几个零技能就能拿到的构造，写在 `references/zero-skill-panel.md`；本臂最该记住的两条是：

- **持有股票池本身不算成绩。** 等权持有沪深 300 全部成分，零技能读中性化超额 +3.2…+3.5 %/年、信息比率 0.87。
- **面板对齐股票池、日历、每笔的钱与成本，但不对齐权重方案。** 起步包因此是等额现金：等额不需要额外的机制归因对照，任何非等额的权重方案都要按 `families.md` 的 P5 同批跑一条同分数等额腿。

## 本臂的执行边界

执行合同——入口与订单、允许的 import、文件 I/O、`available_at` 与 PIT 读法、不写死宿主路径、沙箱无网络——以只读 `output/README.md` 与系统提示为准，本包不复述。本包只在以下几点上更具体：

- 本包声明 `fit(context)` 与季度重训；权重只经 `torch.save` / `torch.load` 读写 `context.state_dir`，LightGBM 用 `save_model` / `Booster(model_file=...)`。**`models/` 只放随产物交付的静态资产，拟合出来的东西一律不进去**——这是策略合同，不是本包的选择；本包的「持久化」指的是**一次回放之内跨决策、跨季度重训的热启动**，每次回放开始时 `state_dir` 为空，第一次 `fit` 必然是冷启动，回放因此仍然只由 PIT 数据决定。
- **本臂 `gpu_count = 1`，策略必须在 CUDA 上训练和打分，不写 CPU 路径。** 没有 CUDA 时 `fit` 与复核直接报错，而不是悄悄换成另一种计算。这与模板 README「保留 CPU 路径」的通用建议不同，本臂以本条为准。`c_lgbm` 对照在同一个容器的 CPU 上训练，不用 CUDA。
- **显存预算**：一次 `fit` 的显存峰值必须低于 12 GiB。执行器只把空闲显存不低于 12 GiB 的卡分给容器；低于这条线时的 CUDA 显存不足记为环境失败，高于这条线仍不足就是策略自己的错误。卡在批次内共享：三路并发回放可能落在同一张卡上，每路都不能假定独占整卡。起步包实测卡上峰值 **0.65 GiB**（`sources.md`），加长序列或加通道时先在冒烟里重量一次。
- **策略容器按 8 核 / 16 GiB 设计**，`--memory-swap` 与 `--memory` 同值：**超了不是变慢，是直接 OOM 失败**。线程数写死在 8 以内。起步包实测容器峰值 1.7–2.5 GiB。
- 固定种子：三个 GRU 种子与 LightGBM 种子写死在代码里。cuDNN 的 GRU 内核在重复回放之间仍可能有细小差异，逐位复现不保证，读数以同批比较为准。
- 本臂不挂分钟域（运行事实 `execution_policy`），执行时点只有 09:30 与 15:00。
- 不要把 `refs/` 里的文件拷进 `output/`：整棵包是只读的，`cp` 会把权限一起带过去；会话开始时 `output/` 已经是 `starter/` 的内容。

## 账户与成本

研究期几何、预算、冻结门与毕业条件以运行事实为准，本包不复述。**开工第一件事是读自己的运行事实**：`broker_replay.initial_cash`、`acceptance_rules` 里有没有跟踪授权、两个回撤上限、`budgets` 与 `max_replay_years`。本包按**100 万元、不带跟踪授权**写成，起步包的 30 席就是从这个账户推出来的；运行事实与此不符时按 `families.md` 的终止规则改登记或诚实终止，不要静默沿用。

100 万元 30 席：座位约 32,300 元，一手买得起 98–99 % 的成分（实测本轮某决策日买不起 0.35 %），5 元最低佣金约 **1.5 bp/边**，一次往返约 12 bp。**在这个账户上换手是舍入误差而不是一等参数**：实测年换手 17–18 倍的书在 100 万元上只付 0.03–0.07 %/年。10 日标签的学习信号需要**每周复核**：方向研究里同一分数改成月度复核后，所有学习型篮子的中性化超额都落到 0 附近。起步节奏是每周复核、2 倍保留带、每次最多换 4 只（含被迫卖出）。

## 「没有边际」的读法

每个候选按 `families.md` 的提名条件与「什么会杀死它」逐条读，不看整窗总收益。另外三点：

- **读主动读数，不读原始超额**：`benchmark.active_neutralized_excess` / `active_tracking_error` / `active_information_ratio`、`benchmark.panel_neutralized_excess`、`sub_windows[].active_neutralized_excess_return`。
- **`c_lgbm` 的同跨度读数必须同批出现**，并写出 `g1` 与它的整窗与逐年差。落后本身不触发关闭，但它是 G-INC 的输入，不得省略。
- 池内 IC 高不等于 30 只篮子挣钱：上一条臂的控制后 IC t 读 +5.0，而它最好的 15 只相对池均值在 10 日上是 **−0.03 %**。候选只按篮子回放的主动读数裁决，离线 IC 只作诊断。

没有候选证明边际时，不冻结是正当结果：按 `families.md` 的终止规则以 `no_edge` 携读数结束本臂。

## 禁止退回别的家族

本包的候选形态只有 `families.md` 登记的序列排序器及其变体。手写的价值 / 反转 / 动量 / 低波 / Alpha158 打分不得作为候选；`c_lgbm` 只能作对照，**永远不得提名冻结**；`g1r` 不得调成事实上只剩树模型；14 条通道里的任何一条（尤其是两条两融通道）**不得被抽出来做成独立分数**——融资拥挤是已关闭家族，把它从输入变成方向就是重开它。

## 本包的硬要求

跨实验的运行教训不写在参考包里（见 `inputs/skills_index.json` 的运行记忆）。本包在流水线之外只加五条，全部写在 `families.md`：预登记（P1）、行业敞口与规模并排汇报（P2）、成本（P3）、按主动读数导航（P4）、非等额权重方案的同批等额对照（P5），外加一条本轮特有的、必须在整期批次**之前**通过的**增量信息门 G-INC**——它全离线，**不花回放年、也不计一个 trial**，因为每一次完成的验证不分跨度都会抬高本臂自己的去膨胀 Sharpe 门。另有一条实现层面的硬要求：**训练面板与决策截面必须由同一个函数构建**（`starter/lib/panel.py` 的 `build` 与 `window`），GRU 与树对照共用这份面板、同一组训练日期与同一个标签。
