# 先并行只读，再单点实现

有效的开局是同一轮启动几个互斥的只读子代理（数据与单位、父策略与已有知识、参考材料），拿到结论后再交给一个可写子代理做计算或实现。

## 做法

- 只读块并行，写入块串行；同一文件同一时间只交给一个子代理。
- 一个子代理只做一件有界的事。把统计计算和实现改写拆成两个，不要塞进同一个长任务。
- task 里写清路径、约束和期望的返回格式。子代理不继承你踩过的坑：凡是会用到 shell、路径或文件写入的 task，把工具约定逐条抄进正文（`shell-argv-usage` 和 `workspace-path-rules` 各有一条现成的可复制约定）。
- 把验收点写成 task 的完成条件，而不是留成提醒，例如「自查结果随汇报一并给出之前，不得发起冒烟」。子代理汇报的是意图，先验收它实际写入的文件，再依赖它的结论。
- 等待期间继续设计并启动下一块，不要轮询；结果会以消息送回。

## 教训

把计算和验证塞进同一个长子代理，连续两折都拖慢了进度；也出现过汇报「已完成」但没有写入任何文件的交付，父会话只有验收文件才发现。工具约定即使逐字写进 task 也只能减少而不能消除同类错误：一个折里 6 个子代理仍把同一处调用格式写错 11 次。所以约定要写，验收也要做，两者缺一都会把错误留到下一轮才暴露。
