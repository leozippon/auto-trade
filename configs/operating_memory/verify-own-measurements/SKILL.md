# 自己算出的数先核对再依赖

工具与回放的输出有合同，自己写的脚本没有。解析假设或第二条实现一旦错了，它会安静地给出一个看起来合理的错数，之后的判断全都建在这个数上。

## 做法

- 写解析前先跑一次原始命令、看几行真实输出，不凭印象假定格式。例如数改动行：`diff -u` 配 `^[+-]` 并排除 `^[+-][+-]` 的文件头，经典 `diff` 配 `^[<>]`；`diff -u | wc -l` 把文件头和 `@@` 也算了进去。
- 离线脚本给出的网格分数、筛选排名或统计量，在据此进入正式 Validation 之前，用一条独立实现的路径重算所选点及其相邻两点。判读依赖的是这几点的相对关系，重算它们就能抓住两条代码线的安静漂移，而不必重算整张表。
- 解析出的数字与另一处观察矛盾时（脚本说没改、读文件却看得见改动），先手工核一遍再下结论；脚本用来省事，不用来代替核对。
