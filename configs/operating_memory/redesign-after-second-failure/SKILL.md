# 同一组件第二次失败就换设计

同一个组件第二次以同样的原因失败时，停止打补丁，换设计。串行的「改一点、再跑一次、又失败」循环会把整折预算耗光，最后什么产物都留不下。

## 做法

- 第一次失败先定位到具体组件并写下原因，第二次同类失败就换读法、换机制，或退到更小的垂直切片。
- 不要用正式验证当调试器：先在工作区脚本或冒烟回放里复现问题，确认修好再进入正式流程。
- 连续失败时先把已经跑通的最小版本固定下来，再在它之上做增量。
- 换设计时同时缩小范围，不要用一个更大的新框架去修一个还没定位清楚的问题。

## 教训

一个折用掉近百轮和全部正式回放次数，全部失败于同一个错误，会话自己的复盘承认是「一直在补同一处」而不是换读法。
