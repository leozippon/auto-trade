# 冻结的产物只含在用的代码

`output/` 冻结后会被后续 Fold 继承、在不可见区间评估并最终部署。多出来的文件让静态检查与冒烟当场拒绝，而错误指向目录内容，不指向策略逻辑；多出来的逻辑不会让任何检查失败，只会一代代被继承、占改动量并误导下一次阅读。两者都只能靠提交前主动检查发现。

## 目录里只放包本身

- 入口 `main.py` 与它真正 import 的模块才是产物。探数脚本、笔记、日志与导出数据写在工作区根（如 `notes/`），跨 Fold 的静态资产写 `models/`，回放期拟合结果只写 `context.state_dir`。
- 在 `output/` 或候选目录里执行过 Python 会留下 `__pycache__`：从工作区根运行脚本，或提交前删掉缓存。
- 发起回放前逐个列一遍 `output/` 与每个候选目录，确认只剩入口和被引用的模块。

## 文件里只留在用的逻辑

- 恒为假的分支、只被它调用的函数、不再被引用的参数与常量都是死代码：删掉，不留开关式残留，需要时再写。
- 一轮候选被证伪后立刻拆掉落选变体的接线，不把半截实现留在胜者里。
- 改了窗口、阈值或口径就同步改注释与 docstring：写着一个数、算着另一个数的注释比没有更糟。
- 删已验证产物里的代码前先证明零引用（全包只剩定义处）；拿不准时把清理作为下一轮候选去做并验证，不在待验证的候选上顺手改。
