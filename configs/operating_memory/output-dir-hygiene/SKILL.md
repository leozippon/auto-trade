# output/ 只交付正式产物

`output/` 是正式策略产物：以 `main.py` 为入口的 Python 包。包内被入口引用的兄弟模块是合法产物，计入文件数与字节上限，不算残留；残留是目录里多出来的**文件**。它们会让 `modification_check` 与冒烟当场硬失败，而失败信息指向目录内容，不指向策略逻辑，所以每次都要多花一轮才想到问题不在代码里。（文件内部留下的死逻辑是另一回事，见 `dead-code-sweep`。）

## 做法

- 调试脚本、探数结果、笔记、日志、数据导出写在工作区根（例如 `notes/`），不写进 `output/` 与 `models/`。
- 在 `output/` 里执行过 Python 就会留下 `__pycache__`；脚本从工作区根执行，或在检查前删掉缓存目录。
- 调用 `modification_check` 与 `smoke_backtest` 之前先列一遍 `output/`，确认只剩入口和它真正 import 的模块。
- 动手写策略代码之前先读只读的 `output/README.md`：允许的库、数据读写调用的写法（路径必须是首个位置参数，且是以某个 `context` 目录为根的字面拼接）、文件与字节上限，全部以它为准。这些是导入前的静态检查，不进回放就被拒，照着合同自查一遍再发起冒烟，比让回放替你逐条发现便宜得多。
- 跨 Fold 继承的静态资产放 `models/`，回放期拟合出来的东西只写 `context.state_dir`，两者都不进 `output/`。

## 教训

多个折在冒烟阶段被残留缓存目录挡下，每次都要多花一轮才定位到目录内容。另一个折的实现子代理靠回放的静态拒绝逐条发现允许库与数据路径写法——这些规则在产物合同里一字不差地写着——同一个候选被连拦四次，烧掉了约四分之一的折墙钟。
