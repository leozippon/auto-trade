# 窗口化 PIT 读取

策略每个决策日只有很短的推理预算，无窗口的 PIT 读取是最常见的耗尽方式：每次 `pd.read_parquet(context.asof_dir + "/<domain>", ...)` 都要同时给出 `columns=` 和日期窗口，只取真正需要的尾窗。

## 做法

- 先算出本次需要的最早日期，按日期过滤后再读，不要整段读进来再切片。
- 只列出会用到的列。宽表的全列读取是超时的主要来源。
- 逐日重复的滚动窗口在决策内自己维护，不要每天重算整段历史。
- 冷启动那一天的读取量最大，按它估算耗时，而不是按平均日。
- `output/` 一旦可运行就先用 `smoke_backtest` 量一次单日耗时，确认留有余量再进入正式验证。

## 教训

一个折的全部正式回放都因为同一处无窗口读取而超时失败，没有留下任何可选节点；同样的读法在后来的实验里再次出现，说明它不是偶发错误。
