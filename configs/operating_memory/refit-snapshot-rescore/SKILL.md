# 重打分要用当时那次重训的快照

同一次回放里各次 `fit` 共用一个 `context.state_dir`：上一次写下的文件下一次还在，热启动链就建在它上面，每次重训也就覆盖同一份状态文件。事后离线重算某一天的分数时，必须用不晚于这一天的最近一次重训留下的快照，不能读已经被后来的重训盖掉的共享文件。

分数、相关和篮子收益会因此悄悄改变，而与模型无关的列保持原样，所以这个错误很难从行数上看出来。

- 每次重训结束立刻把当次产物按决策日另存。存的是这次真正写进共享路径的权重，不是训练循环结束时留在内存里的那份。
- 沿上一次模型续训的，重放也要按同样的顺序重跑，不能单独重跑中间一次。重放后的验证值和当时记下的值一致，这次重放才可信。
- 重算出来的分数要和当时打印下来的值一致。共享文件已经被盖掉时，先从对应日期的快照恢复，再继续后面的热启动。
